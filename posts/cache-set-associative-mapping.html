四路组相联 Cache：顺序访问后的映射与替换

一块 4 路组相联 Cache，每个 way 有 256 条 line，总共能保存 1024 条 line。地址先决定 set，再由该 set 的填充或替换策略选择 way。下面用连续的主存 cache line 编号说明这一过程。

1. Cache 组织

4 路、每路 256 条 line，等价于：

\[ 256\ \text{sets}\times 4\ \text{ways}=1024\ \text{cache lines}. \]

设主存 cache line 编号为 $L$。不考虑 line 内 byte offset 时：

\[ \text{set}(L)=L\bmod256, \qquad \text{tag}(L)=\left\lfloor\frac{L}{256}\right\rfloor. \]

地址映射只规定 set，不规定具体 way。同一个 set 内的四个位置地位相同，硬件按空 way 选择或替换策略决定写入哪一路。

2. 顺序遍历 1024 条 line

假设 Cache 初始为空，依次访问主存 line 0 到 1023，期间没有其他访问。前 256 条 line 分别进入 set 0 到 set 255；接下来的三轮重复相同的 set index，并占用各 set 的其余 way。

若为了展示，假设空 way 按 Way 0 到 Way 3 的顺序填充，遍历结束后的硬件编号如下：

Set Way 0 Way 1 Way 2 Way 3
00256512768
11257513769
22258514770
...............
2552555117671023

因此，任意 set $s$ 保存的四条主存 line 是：

\[ \boxed{s,\quad s+256,\quad s+512,\quad s+768}. \]

表中的 way 顺序只是一种可能的硬件状态。无论 way 如何编号，set $s$ 中保存的四个 line 编号不变。此时 1024 个 Cache 位置全部有效；若立即再次遍历 line 0 到 1023，所有访问都会命中。

3. 继续访问第 1025 条 line

本文使用 0-based 编号，所以第 1025 条 line 是 line 1024。它的映射为：

\[ \text{set}(1024)=0, \qquad \text{tag}(1024)=4. \]

set 0 已经保存 line 0、256、512 和 768，必须先选择一个 victim。若采用严格 LRU，四条 line 在顺序遍历中的访问次序是：

\[ 0\rightarrow256\rightarrow512\rightarrow768. \]

line 0 最久没有被访问，因此硬件淘汰 line 0，并把 line 1024 放进它原来的 way。set 0 从：

\[ \{0,256,512,768\} \quad\longrightarrow\quad \{1024,256,512,768\}. \]

set 1 到 set 255 保持不变，Cache 仍然保存 1024 条 line。若被淘汰的 line 0 是 dirty line，硬件需要先把它写回下一级存储；clean line 可以直接覆盖。

LRU 决定上述例子淘汰 line 0。若硬件采用 Random 或 PLRU，victim 可能不同，但 line 1024 仍然只能进入 set 0。
