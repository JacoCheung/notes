四路组相联 Cache 的地址映射与 LRU 替换

组相联 Cache 把地址映射和替换分成两步：地址中的 index 选择 set，填充或替换策略再从该 set 的多个 way 中选择位置。这里用一块包含 256 个 set、每个 set 4 个 way 的 Cache，推导顺序访问 1024 条主存 line 后的状态，以及下一次冲突访问触发的 LRU 替换。

这是一个人为设定的 Cache 模型，不对应某款 CPU 或 GPU。例子假设 256 个 set、空 way 按编号填充，并在需要替换时采用严格 LRU；真实硬件可能采用 PLRU、Random 或未公开策略。

1. Cache 组织

组相联 Cache 是由多个 set 组成的存储结构，每个 set 包含固定数量的 way。同一主存 line 只能映射到一个 set，却可以占用该 set 内任一 way。4 路、每路 256 条 line，等价于：

\[ 256\ \text{sets}\times 4\ \text{ways}=1024\ \text{cache lines}. \]

设主存 cache line 编号为 $L$。不考虑 line 内 byte offset 时：

\[ \text{set}(L)=L\bmod256, \qquad \text{tag}(L)=\left\lfloor\frac{L}{256}\right\rfloor. \]

地址映射只规定 set，不规定具体 way。同一个 set 内的四个位置地位相同，硬件按空 way 选择或替换策略决定写入哪一路。

2. 顺序遍历 1024 条 line

假设 Cache 初始为空，依次访问主存 line 0 到 1023，期间没有其他访问。前 256 条 line 分别进入 set 0 到 set 255；接下来的三轮重复相同的 set index，并占用各 set 的其余 way。

若为了展示，假设空 way 按 Way 0 到 Way 3 的顺序填充，遍历结束后的硬件编号如下：

Set Way 0 Way 1 Way 2 Way 3
00256512768
11257513769
22258514770
...............
2552555117671023

四轮访问分别贡献一个 tag，因此任意 set $s$ 保存的四条主存 line 是：

\[ \boxed{s,\quad s+256,\quad s+512,\quad s+768}. \]

表中的 way 顺序只是一种可能的硬件状态。无论 way 如何编号，set $s$ 中保存的四个 line 编号不变。此时 1024 个 Cache 位置全部有效；若立即再次遍历 line 0 到 1023，所有访问都会命中。

3. 继续访问第 1025 条 line

本文使用 0-based 编号，所以第 1025 条 line 是 line 1024。它的映射为：

\[ \text{set}(1024)=0, \qquad \text{tag}(1024)=4. \]

set 0 已经保存 line 0、256、512 和 768，必须先选择一个 victim。若采用严格 LRU，四条 line 在顺序遍历中的访问次序是：

\[ 0\rightarrow256\rightarrow512\rightarrow768. \]

line 0 最久没有被访问，因此硬件淘汰 line 0，并把 line 1024 放进它原来的 way。set 0 从：

\[ \{0,256,512,768\} \quad\longrightarrow\quad \{1024,256,512,768\}. \]

set 1 到 set 255 保持不变，Cache 仍然保存 1024 条 line。若被淘汰的 line 0 是 dirty line，硬件必须保留其写回下一级存储的过程；writeback buffer 可以让该过程与当前 miss 的完成部分解耦。clean line 不需要写回。

LRU 决定上述例子淘汰 line 0。若硬件采用 Random 或 PLRU，victim 可能不同，但 line 1024 仍然只能进入 set 0。

Address Mapping and LRU Replacement in a Four-Way Set-Associative Cache

A set-associative cache separates address mapping from replacement: the index bits select a set, then the fill or replacement policy chooses one of that set's ways. This example uses 256 sets with four ways each to derive the state after a sequential scan of 1,024 memory lines and the LRU replacement caused by the next conflicting access.

This is a hypothetical cache model rather than the specification of a particular CPU or GPU. It assumes 256 sets, fills empty ways in numeric order, and uses strict LRU when replacement is required. Real hardware may use PLRU, random replacement, or an undisclosed policy.

1. Cache Organization

A set-associative cache consists of sets with a fixed number of ways. A memory line maps to exactly one set but may occupy any way in that set. Four ways with 256 lines per way is equivalent to:

\[ 256\ \text{sets}\times 4\ \text{ways}=1024\ \text{cache lines}. \]

Let $L$ be the memory cache-line number. Ignoring the byte offset within a line:

\[ \text{set}(L)=L\bmod256, \qquad \text{tag}(L)=\left\lfloor\frac{L}{256}\right\rfloor. \]

Address mapping determines the set, not the exact way. The four positions within a set are peers; hardware chooses a way according to the empty-way selection or replacement policy.

2. Sequentially Scanning 1,024 Lines

Assume the cache starts empty and memory lines 0 through 1023 are accessed in order, with no intervening accesses. The first 256 lines occupy sets 0 through 255. The next three rounds repeat the same set indices and fill the remaining ways in each set.

For illustration, suppose empty ways are filled from Way 0 through Way 3. After the scan, the hardware numbering is:

Set Way 0 Way 1 Way 2 Way 3
00256512768
11257513769
22258514770
...............
2552555117671023

The four passes contribute one tag apiece, so each set $s$ contains these four memory lines:

\[ \boxed{s,\quad s+256,\quad s+512,\quad s+768}. \]

The way order shown in the table is only one possible hardware state. Regardless of way numbering, set $s$ contains the same four line numbers. All 1,024 cache positions are now valid. An immediate second scan of lines 0 through 1023 would hit on every access.

3. Accessing the 1,025th Line

This article uses zero-based numbering, so the 1,025th line is line 1024. Its mapping is:

\[ \text{set}(1024)=0, \qquad \text{tag}(1024)=4. \]

Set 0 already contains lines 0, 256, 512, and 768, so one line must be selected as the victim. Under strict LRU, those lines were touched in this order during the sequential scan:

\[ 0\rightarrow256\rightarrow512\rightarrow768. \]

Line 0 has gone unused for the longest time. The cache evicts it and places line 1024 in its former way. Set 0 changes from:

\[ \{0,256,512,768\} \quad\longrightarrow\quad \{1024,256,512,768\}. \]

Sets 1 through 255 remain unchanged, and the cache still holds 1,024 lines. If line 0 is dirty, hardware must preserve its writeback to the next level; a writeback buffer may partially decouple that work from completion of the current miss. A clean line needs no writeback.

LRU selects line 0 in this example. With random replacement or PLRU, the victim could differ, but line 1024 can still enter only set 0.
