组相联 Cache 与 LRU 替换

Cache 远小于主存。组相联 Cache 把每条主存 line 限定在一个 set 内，查找时只需检查该 set 的几个 way；代价是同一 set 的 line 争用这几个 way，占满后新 line 只能替换旧 line。访问顺序因此决定命中与冲突。

下文使用一个人为设定的 Cache 模型，不对应某款 CPU 或 GPU。例子假设 256 个 set、每个 set 4 路、空 way 按编号填充，并在需要替换时采用严格 LRU；真实硬件可能采用 PLRU、Random 或未公开策略。

1. 地址映射：line 进入哪个 set

判断命中之前，硬件先要知道一条主存 line 能放在哪里。组相联 Cache 由多个 set 组成，每个 set 包含固定数量的 way；同一主存 line 只能映射到一个 set，却可以占用该 set 内任一 way。4 路、每路 256 条 line，等价于：

\[ 256\ \text{sets}\times 4\ \text{ways}=1024\ \text{cache lines}. \]

设主存 cache line 编号为 $L$。不考虑 line 内 byte offset 时，set 号和区分同一 set 内各 line 的 tag 为：

\[ \text{set}(L)=L\bmod256, \qquad \text{tag}(L)=\left\lfloor\frac{L}{256}\right\rfloor. \]

地址映射只规定 set，不规定 way。同一 set 内的四个 way 地位相同，硬件按空 way 选择或替换策略决定写入哪一路，因此 way 的占用取决于访问顺序。

2. 顺序遍历：填满 1024 个位置

先看最简单的顺序：Cache 初始为空，依次访问主存 line 0 到 1023，期间没有其他访问。前 256 条 line 分别进入 set 0 到 set 255；接下来的三轮重复相同的 set index，占用各 set 的其余 way。

若空 way 按 Way 0 到 Way 3 的顺序填充，遍历结束后的状态如下：

Set Way 0 Way 1 Way 2 Way 3
00256512768
11257513769
22258514770
...............
2552555117671023

四轮访问分别贡献一个 tag，因此任意 set $s$ 保存的四条主存 line 是：

\[ \boxed{s,\quad s+256,\quad s+512,\quad s+768}. \]

表中的 way 顺序只是一种可能的硬件状态；无论 way 如何编号，set $s$ 中的四个 line 编号不变。此时 1024 个位置全部有效，立即再次遍历 line 0 到 1023 会全部命中，但任何新 line 都必须先替换一条旧 line。

3. 第 1025 条 line：LRU 替换

第 1025 条 line 就是这样的新 line。本文使用 0-based 编号，它是 line 1024，映射为：

\[ \text{set}(1024)=0, \qquad \text{tag}(1024)=4. \]

set 0 已经保存 line 0、256、512 和 768，必须先选出一个 victim。严格 LRU 淘汰最久未被访问的 line，而这四条 line 在顺序遍历中的访问次序是：

\[ 0\rightarrow256\rightarrow512\rightarrow768. \]

line 0 最久没有被访问，因此被淘汰，line 1024 放进它原来的 way。set 0 从：

\[ \{0,256,512,768\} \quad\longrightarrow\quad \{1024,256,512,768\}. \]

set 1 到 set 255 不变，Cache 仍保存 1024 条 line。若 line 0 是 dirty line，硬件必须保留其写回下一级存储的过程，writeback buffer 可以让写回与当前 miss 的完成部分解耦；clean line 无需写回。

这次替换的代价在再次遍历 line 0 到 1024 时显现：set 1 到 set 255 的 1020 次访问全部命中，set 0 却要用 4 个 way 轮流容纳 5 条 line。line 0 已被替换，访问它时 miss，并淘汰最久未访问的 256，而 256 正是下一条要访问的 line；此后每次 miss 都淘汰下一条要访问的 line，set 0 的 5 次访问因此全部 miss。

LRU 决定上述例子淘汰 line 0。若硬件采用 Random 或 PLRU，victim 可能不同，但 line 1024 仍然只能进入 set 0。

Set-associative caches and LRU

A cache is far smaller than main memory. A set-associative cache confines each memory line to one set, so a lookup checks only that set's ways. The price is that lines in the same set compete for those ways; once they are full, a new line can only replace an old one. Access order therefore decides hits and conflicts.

The example uses a hypothetical cache model rather than the specification of a particular CPU or GPU. It assumes 256 sets of four ways, fills empty ways in numeric order, and uses strict LRU when replacement is required. Real hardware may use PLRU, random replacement, or an undisclosed policy.

1. Mapping: which set a line enters

To detect a hit, hardware must first know where a line can be stored. A set-associative cache consists of sets with a fixed number of ways. A memory line maps to exactly one set but may occupy any way in that set. Four ways with 256 lines per way is equivalent to:

\[ 256\ \text{sets}\times 4\ \text{ways}=1024\ \text{cache lines}. \]

Let $L$ be the memory cache-line number. Ignoring the byte offset within a line, the set and the tag that tells lines in a set apart are:

\[ \text{set}(L)=L\bmod256, \qquad \text{tag}(L)=\left\lfloor\frac{L}{256}\right\rfloor. \]

Address mapping determines the set, not the way. The four ways in a set are peers; the empty-way selection or replacement policy picks one, so way occupancy depends on access order.

2. Sequential scan: filling all 1,024 slots

Take the simplest order first. The cache starts empty, and memory lines 0 through 1023 are accessed in order with no intervening accesses. The first 256 lines occupy sets 0 through 255. The next three rounds repeat the same set indices and fill the remaining ways in each set.

If empty ways are filled from Way 0 through Way 3, the state after the scan is:

Set Way 0 Way 1 Way 2 Way 3
00256512768
11257513769
22258514770
...............
2552555117671023

Each of the four rounds contributes one tag, so set $s$ contains:

\[ \boxed{s,\quad s+256,\quad s+512,\quad s+768}. \]

The way order in the table is only one possible hardware state; regardless of way numbering, set $s$ contains the same four line numbers. All 1,024 positions are now valid: an immediate rescan of lines 0 through 1023 would hit every time, but any new line must first replace an old one.

3. The 1,025th line: LRU replacement

The 1,025th line is such a line. This article uses zero-based numbering, so it is line 1024, which maps to:

\[ \text{set}(1024)=0, \qquad \text{tag}(1024)=4. \]

Set 0 already holds lines 0, 256, 512, and 768, so one must become the victim. Strict LRU evicts the line unused longest, and the sequential scan touched these lines in this order:

\[ 0\rightarrow256\rightarrow512\rightarrow768. \]

Line 0 is therefore evicted, and line 1024 takes its former way. Set 0 changes from:

\[ \{0,256,512,768\} \quad\longrightarrow\quad \{1024,256,512,768\}. \]

Sets 1 through 255 are unchanged, and the cache still holds 1,024 lines. If line 0 is dirty, hardware must preserve its writeback to the next level, which a writeback buffer may partially decouple from completion of the current miss; a clean line needs no writeback.

Rescanning lines 0 through 1024 exposes the cost of this eviction: the 1,020 accesses to sets 1 through 255 hit, but set 0 must cycle five lines through four ways. Line 0 is gone, so its access misses and evicts the LRU line, 256, the very next line requested. Each later miss likewise evicts the next line requested, so all five accesses to set 0 miss.

LRU selects line 0 in this example. With random replacement or PLRU, the victim could differ, but line 1024 can still enter only set 0.
