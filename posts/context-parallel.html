Context Parallel 的通信方法与实现约束

长序列训练把一个 Transformer layer 的 token 激活扩展到单卡难以容纳的规模。Context Parallel（CP）沿序列维把同一个样本分布到多个 rank：LayerNorm、MLP 与 projection 可以处理本地 token，而全局 attention 仍要求每个 query 访问完整的 K/V 上下文。恢复这条跨 rank 依赖有多种办法，它们分别改变通信原语、峰值显存、因果 mask 下的负载分布，以及通信与局部 attention 的重叠窗口。本文用统一成本模型分析 AllGather KV、Ring Attention、Ulysses、二维组合与动态 mask 分配，并将算法条件、固定版本实现约束和拓扑相关配置分别陈述。

所有引用均来自公开源:arXiv 论文、开源 GitHub 仓库、官方文档。本文是「LLM 训练系统」系列第 1 篇。

0. 长序列 attention 的切分边界

序列长度从几千 token 增长到几十万甚至更长时，逐 token 激活与稠密 attention 以不同速度扩张。下面给出算法量级，实际显存和 step time 还取决于模型结构、attention kernel、重计算策略与 batch 形状。

  • 激活显存:许多逐 token 激活随 $S$ 近似线性增长。
  • attention 计算:稠密 attention 的两个矩阵乘法按 $O(S^2)$ 增长;耗时是否主导整个 step,还取决于 FFN、并行配置和 kernel 效率。

训练系统中的并行维度按不同对象分配工作。它们与 CP 的关系可以按切分对象和单个样本的序列边界整理：

并行维度切分对象与序列边界
Data Parallel (DP)沿样本分配工作，每个 rank 处理分配给自己的完整样本。
Tensor Parallel (TP)切分层内权重与计算，并引入逐层 collective。TP 增大后，每个 rank 的 GEMM 变短，通信重叠能力取决于 hidden size、序列长度、拓扑和 tp_comm_overlap。Megatron-Core 0.16.0 的说明也采用这一条件化边界。
Pipeline Parallel (PP)沿 layer 维分配 stage，每个 stage 处理其 micro-batch 中的完整序列。
Expert Parallel (EP)分布 MoE expert，dense attention 仍保留原有序列范围。

Context Parallel 是沿 $S$ 维把单个样本的序列切成 cp 份的并行方式。LayerNorm、FFN 和 QKV projection 等逐 token 模块直接消费本地分片；其它跨 token 运算需要恢复各自的全局依赖。对稠密 attention 而言，$\text{Attention}(Q, K, V) = \text{softmax}(QK^T/\sqrt{d})\,V$ 要求本地 query 覆盖同一序列的全部 K/V，因此 CP 的主要通信发生在 attention 边界。Megatron-Core 0.16.0 的CP 文档采用相同的范围定义。

比较维度：CP 方法在 attention 的数据分布处形成不同路径。本文统一比较通信原语与字节量、计算通信重叠、mask 负载分布，以及实现支持的 tensor layout。

通信字节量只有与本地计算时间和实际链路能力结合后才具有可比性。下面先建立共同的符号与扩展场景，后续各方法沿用同一组假设。

1. 通信与计算的统一成本模型

统一模型把每个 rank 的 attention 时间分成本地计算与数据交换两项。它暂时忽略 collective 延迟、软件调度和 kernel launch 开销，用于识别随 $S$、cp 与 tp 变化的一阶趋势。

1.1 attention 的 FLOPs 与通信量

记号(全文统一):

符号含义
$S$序列长度(per sample)
$H$注意力头数(MHA 时 $H_{kv} = H$)
$H_{kv}$KV 头数(GQA 时 $< H$)
$d$单头隐藏维度
$\text{cp}$context parallel size
$\text{tp}$tensor parallel size(沿 head 维切)
$\text{flops}$单卡实际 GPU 算力 (TFLOPS)
$BW$实际通信带宽 (GB/s)

一次 forward attention 的计算量(忽略 softmax / LayerNorm,只算 $QK^T$ 和 $\text{attn} \cdot V$ 两次 matmul):

$$ V_{\text{compute}} = 4 \times \frac{H}{\text{tp}} \times S^2 \times d $$

其中 4 = 2 个 matmul × 2 FMA ops/element。若 kernel 能跳过严格上三角,理想的因果计算量约为全 attention 的一半:

$$ V_{\text{compute, causal}} = 2 \times \frac{H}{\text{tp}} \times S^2 \times d $$

引入 cp 后,每张卡只算 $1/\text{cp}$ 份(理想均衡):

$$ V_{\text{compute, per GPU}} = \frac{V_{\text{compute}}}{\text{cp}} $$

各方法通过不同的数据对象、轮次与粒度形成通信量 $V_{\text{comm}}$：有的交换完整 KV，有的分步轮转 KV，还有的重分布 Q、K、V 与 output。后续各节分别给出 $V_{\text{comm}}^{\text{method}}$。

一次 attention 的总时间(假设通信和计算不重叠):

$$ T_{\text{attn}} = \frac{V_{\text{compute, per GPU}}}{\text{flops}} + \frac{V_{\text{comm}}}{BW} $$

若通信与计算可以完整并发,带宽模型中的主项可近似取 $\max$;部分重叠、collective 延迟和同步开销会使实际时间高于这个下界。

1.2 强扩展与布局扫描

扩展方式决定公式中哪些项保持不变。本文采用两种场景：

场景固定什么变化什么评估什么
场景 1：强扩展$S$ 与 $\text{tp}$ 固定增大 $\text{cp}$，用更多 GPU 处理同一序列计算项下降后，通信下限何时暴露
场景 2：并行布局扫描$S$ 与 $\text{tp} \times \text{cp}$ 固定调整 $\text{cp}$ 与 $\text{tp}$ 的比例固定设备数下的 TP/CP 分配
小例 1.2 LLaMA2-7B 的 attention 参数:$H = 32, d = 128$。一个 $S = 128\text{K}$、$\text{tp} = 8$ 的训练:
compute(causal) = $2 \times 32/8 \times (128\text{K})^2 \times 128 = 2 \times 4 \times 1.7 \times 10^{10} \times 128 \approx 1.7 \times 10^{13}$ FLOPs/sample。
若假设单卡 BF16 峰值 989 TFLOPS、该 shape 达到 55% 峰值,则有效算力约 550 TFLOPS。每张卡 ($\text{cp} = 4$): $\frac{1.7 \times 10^{13}}{4 \times 5.5 \times 10^{14}} \approx 7.7$ ms。

这只是 roofline 式代入,不是 H100 实测;kernel 利用率和端到端时间需要单独测量。

1.3 拓扑映射:通信频率与带宽

在 $DP \times PP \times CP \times TP$ 布局中，通信组的拓扑映射取决于消息频率、粒度与可重叠时间。常见的 8-GPU NVLink 节点通常把高频、细粒度的 TP collective 放在高速互连域内，再按 attention 通信量安排 CP；PP 与可分桶重叠的 DP 更容易延伸到节点间。更大的 NVLink 域、不同 NIC 数量与重叠策略会改变这一经验顺序，它属于性能配置而非正确性条件。

Megatron-Core 0.16.0 说明，增大 TP 可能缩短覆盖通信的计算区间；LoongTrain 的公开论文则在特定 8 节点、每节点 4 NIC 的实验拓扑上分析 Ring 的 multi-rail 利用率。这些证据支持条件化的配置方法：代入消息大小、collective 实现、链路带宽与延迟，再用 profile 验证 TP 与 CP 的放置。

2. AllGather KV 的完整副本路径

AllGather KV 先在每个 rank 上构造完整 K/V，再执行 local attention。TransformerEngine v2.16 通过 cp_comm_type="all_gather" 暴露这条可选路径，同一 dispatcher 还提供 p2p、a2a 与 a2a+p2p。具体分发逻辑见固定版本源码。

2.1 思路与张量形状

每张卡持有的 KV:[H, S/cp, d]。AllGather 后:[H, S, d]。Q 不变,仍是 [H, S/cp, d]。然后跑标准 FlashAttention,得 [H, S/cp, d] 的 output。

# transformer_engine/pytorch/attention/dot_product_attention/context_parallel.py
# 简化自 TE v2.16 AttnFuncWithCPAndKVAllGather (line 3018 起)
def forward(ctx, q, k, v, cp_group, ...):
    cp_size = get_world_size(cp_group)

    # Step 1: AllGather K, V 跨 cp_group
    k_ag, _ = gather_along_first_dim(k, cp_group)   # [cp*S/cp, ..] -> [S, ..]
    v_ag, _ = gather_along_first_dim(v, cp_group)

    # Step 2: 因果 mask 下做 chunk 重排(§4 zigzag)
    chunk_ids = get_seq_chunk_ids_for_reordering_before_attn(cp_size, k.device)
    k_ag = torch.index_select(k_ag, dim=0, index=chunk_ids)
    v_ag = torch.index_select(v_ag, dim=0, index=chunk_ids)

    # Step 3: 本地 FA(每卡处理自己的 Q chunk,但 KV 全有)
    out = flash_attn_func(q, k_ag, v_ag, causal=is_causal)
    return out

2.2 通信量与建模

每张卡需要的 KV 通信量(bf16,2 bytes):

$$ V_{\text{comm}}^{\text{AG}} = 2 \times 2 \times \frac{H_{kv}}{\text{tp}} \times S \times d $$

这里两个 2:一个是 K + V,一个是 bf16 字节数。公式把 gathered K/V 按完整张量计数;若只统计从远端接收的数据,还要乘 $(\text{cp}-1)/\text{cp}$。GQA 的 $H_{kv}$ 较小时,这部分流量相应减少。

时间(忽略 reordering 开销):

$$ T_{\text{AG}} = \frac{V_{\text{compute}}}{\text{flops} \cdot \text{cp}} + \frac{V_{\text{comm}}^{\text{AG}}}{BW_{\text{AG}}} $$

为了看清标度,先把 $BW_{\text{AG}}$ 当作常数。真实 collective 带宽会随 rank 数、消息大小、拓扑和 NCCL 算法变化,因此下面两点是模型趋势,不是性能保证:

  • 场景 1(tp 固定,cp 增大):$T_{\text{compute}}$ 理想地随 cp 下降,而每卡最终需要完整 K/V,通信项趋向下限。足够大的 cp 可能进入通信受限区间。
  • 场景 2(tp × cp 固定):cp 增大时 tp 缩小,$H_{kv}/\text{tp}$ 增大,模型中的通信项随之增大;端到端时间是否变慢仍要看 GEMM 效率和 collective 实测。

执行特征成本与约束
实现直接(AllGather + 本地 attention)TE v2.16 将 KV AllGather 定义为 exposed

3. Ring Attention 的分块 P2P 路径

AllGather 会在本地 attention 之前形成一段集中的 KV 通信;这部分暴露多少,取决于实现能否分块、预取或与其他工作重叠。Ring Attention(Li et al. 2021,Liu et al. 2023)把 AllGather 拆成 cp 步 P2P send/recv:每收到一块 KV,就立即与本地 Q 计算 attention,从而为通信与计算重叠创造条件。

3.1 KV 轮转与 online softmax

每张卡持有自己的 Q chunk,$K_i$ 在 ring 上转一圈。每一步:

  1. 计算:当前手上的 $(Q_{\text{local}}, K_j, V_j)$ 算 partial attention,用 online softmax 累加。
  2. 通信:把当前的 $(K_j, V_j)$ 通过 P2P send 给 ring 上下一个 rank;同时 recv 上一个 rank 的 $(K_{j-1}, V_{j-1})$。
  3. 循环:重复 cp 次直到每块 KV 都和本地 Q 配过一次。

实现把当前 chunk 的 attention 与下一块 KV 的传输并发执行。当单步通信时间不超过单步计算时间时，带宽项可以被局部 attention 覆盖。下图给出 cp=4 的时间顺序：

3.2 通信-计算 overlap 边界

每步(per chunk)的通信量与计算量:

$$ V_{\text{comm}}^{\text{step}} = 4 \times \frac{H_{kv}}{\text{tp}} \times \frac{S}{\text{cp}} \times d $$

$$ V_{\text{compute}}^{\text{step}} = 4 \times \frac{H}{\text{tp}} \times \frac{S^2}{\text{cp}^2} \times d $$

4 = K + V × 2 bytes(bf16);计算分 $\frac{1}{\text{cp}^2}$ 是因为 Q chunk 是 $S/\text{cp}$、KV chunk 也是 $S/\text{cp}$。

通信能被计算完全 hide 的条件:

$$ \frac{V_{\text{comm}}^{\text{step}}}{BW} \leq \frac{V_{\text{compute}}^{\text{step}}}{\text{flops}} \quad\Longrightarrow\quad \text{cp} \leq \frac{BW \times S}{\text{flops}} \times \frac{H}{H_{kv}} $$

把这个简化条件记作重叠边界 $\text{cp}_{\text{bor}}$。边界以内，计算有机会覆盖带宽项；边界以外，固定 $S$ 的强扩展逐渐接近通信下限。每步消息量按 $1/\text{cp}$ 缩小，步骤数则随 cp 增加，因此纯带宽字节量趋于稳定，而 P2P latency、同步与负载不均衡会逐步累积。该公式用于一阶估算。

小例 3.2 用一组假设值说明公式:$BW=540$ GB/s 或 $43$ GB/s、有效 BF16 算力 550 TFLOPS,$S=128\text{K}$,MHA(无 GQA):
较快链路: $\text{cp}_{\text{bor}} \approx \frac{540 \times 10^9 \times 128 \times 1024}{550 \times 10^{12}} \approx 128$。
较慢链路: $\text{cp}_{\text{bor}} \approx \frac{43 \times 10^9 \times 128 \times 1024}{550 \times 10^{12}} \approx 10$。

这些数值来自带宽模型代入，用于展示变量关系。DGX-H100 或具体 CP 配置的实测边界还会随 collective rail 数、消息 latency、GQA 比例和 backend 移动。

3.3 反向传播

反向 Ring 还要传播并规约 dK/dV,通信和计算都比正向多;具体倍数取决于 kernel、是否重计算和通信调度。TE v2.16 在同一固定版本的 P2P 实现中分别组织 forward 和 backward 路径。

4. 因果 mask 的负载均衡

连续序列分片与标准 causal mask 组合时，不同 rank 覆盖的有效三角区域面积不同，因而形成负载不均。稀疏或分块 mask 也需要负载分析，但其有效区域应按各自的 mask 几何形状计算。

4.1 连续分片的三角形负载

用 $S = 8, \text{cp} = 2$ 举例,Causal mask 下哪些 $(i, j)$ 要算?$j \leq i$ 的下三角:

              KV chunk
              0,1,2,3  4,5,6,7
       Q  0  [  ■        ░     ]    GPU 0 (持 Q0..Q3)
       c  1  [  ■        ░     ]
       h  2  [  ■        ░     ]
       u  3  [  ■        ░     ]
       n  ─────────────────────
       k  4  [  ■        ■     ]    GPU 1 (持 Q4..Q7)
          5  [  ■        ■     ]
          6  [  ■        ■     ]
          7  [  ■        ■     ]

       ■ = 要算的位置;░ = 不算(j > i)

连续切分后，GPU 0 持有 Q[0..3]、KV[0..3]，GPU 1 持有 Q[4..7]、KV[4..7]。在因果 mask 下，GPU 0 计算左上角 4×4 的一半，共 8 个 cell；GPU 1 计算左侧完整 4×4 与右侧 4×4 的一半，共 24 个 cell。两者相差 3 倍，而 Ring 的每一轮都受最慢 rank 的完成时间约束。

4.2 Striped Attention

Striped Attention（Brandon et al., arXiv:2311.09431）按 stride=cp 交错分配 token，使每个 rank 的位置均匀分布在完整序列中。这样，各 rank 覆盖的因果区域面积更接近：

       cp = 2 的 Striped 切分:
       GPU 0 持有 token 0, 2, 4, 6  (偶数位置)
       GPU 1 持有 token 1, 3, 5, 7  (奇数位置)

       这样每张卡的 (Q_i, K_j) 配对中,causal mask
       的"几何形状"接近,负载差异随粒度减小。

公开性能(论文 §5):A100 上 256K seq 提速 1.45×,16× TPUv4 上 786K seq 提速 1.65×。

4.3 Zigzag / dual-chunk 布局

另一种常见布局通常称为 Zigzag 或 dual-chunk:把 sequence 切成 2×cp 个 chunk,每张卡分到一前一后两个 chunk。Megatron-Core r0.16.0 的 get_batch_on_this_cp_rank 使用了这一分配方式;TE v2.16 的源码注释称其为 discontiguous sequence chunks / DualChunking。

       cp = 2,seq 切成 4 个 chunk:
       chunk_0  chunk_1  chunk_2  chunk_3

       GPU 0 持有:chunk_0 + chunk_3  (头 + 尾)
       GPU 1 持有:chunk_1 + chunk_2  (中间两块)

       Causal mask 下:
       - GPU 0 在 chunk_0 处工作量小 + chunk_3 处工作量大
       - GPU 1 在 chunk_1 处工作量中 + chunk_2 处工作量中

       两个之和几乎一致 → 负载均衡。

TransformerEngine v2.16 的重排函数:

def get_seq_chunk_ids_for_reordering_before_attn(cp_size, device):
    """把 2*cp 个 chunk 重新排列,使第 rank 张卡拿到
       chunk_{2*rank} 和 chunk_{2*cp - 2*rank - 1}。"""
    chunk_ids = torch.empty(2 * cp_size, dtype=torch.int32, device=device)
    for rank in range(cp_size):
        chunk_ids[rank]           = 2 * rank
        chunk_ids[rank + cp_size] = 2 * cp_size - 2 * rank - 1
    return chunk_ids

Megatron-Core r0.16.0 在 get_batch_on_this_cp_rank 中切分 batch。TE v2.16 说明，当所有层共享同一 CP 配置时，reorder 可以放进 dataloader 并复用结果。算法条件是在 attention 前建立正确布局，并对 token、position 与相关 mask metadata 使用一致索引；dataloader 是满足该条件的一种实现位置。

术语边界：本文用 Zigzag / dual-chunk 指代“每个 rank 取前后两个不连续 chunk”的布局；Striped Attention 按 token stride 交错。仓库命名存在差异，索引映射是区分两者的判据。

4.4 实践提示

  • Megatron-Core r0.16.0 的该 utility 要求被切分的序列维可 reshape 为 2 * cp_size 份,不满足时需要 padding 或另一种分片实现。
  • reorder 可以在数据路径或 attention 前完成;相关张量和 mask 元数据必须采用一致的索引语义。
  • 对于连续 causal attention，dual-chunk 通常能减少三角负载差异。非因果、sliding-window、packed/varlen 与自定义 mask 需要按具体 backend 和 layout 验证收益与转换成本。

5. Ulysses 的 head 轴重分布

Ring、Striped 与 Zigzag 都保留序列分片，并通过 P2P 让本地 Q 依次接触各块 KV。DeepSpeed Ulysses（Jacobs et al., arXiv:2309.14509）在 attention 前用 AllToAll 交换序列轴与 head 轴，使每个 rank 在 attention 内持有完整序列和一部分 heads。

5.1 AllToAll 换轴

每个 transformer block 进 attention 之前的张量:[H, S/cp, d](沿 S 分布)。Ulysses 在 attention 前后各插一次 AllToAll:

进 attention 前:                       attention 中:                       attention 后:
─────────────────                       ─────────────                       ─────────────────
GPU 0: [H, S/cp, d]    AlltoAll    GPU 0: [H/cp, S, d]    本地 FA      GPU 0: [H/cp, S, d]    AlltoAll    GPU 0: [H, S/cp, d]
GPU 1: [H, S/cp, d]   ─────────→   GPU 1: [H/cp, S, d]    ──────→      GPU 1: [H/cp, S, d]   ─────────→   GPU 1: [H, S/cp, d]
GPU 2: [H, S/cp, d]                GPU 2: [H/cp, S, d]                 GPU 2: [H/cp, S, d]                GPU 2: [H, S/cp, d]
GPU 3: [H, S/cp, d]                GPU 3: [H/cp, S, d]                 GPU 3: [H/cp, S, d]                GPU 3: [H, S/cp, d]

     ↑                                  ↑                                    ↑                                ↑
   沿 S 切                          沿 H 切                              沿 H 切                          沿 S 切
                                  每卡持完整 S                        每卡持完整 S
                                  跑 H/cp 头 attention

  • 算法:DeepSpeed Ulysses 论文 v1
  • TE v2.16:AttnFuncWithCPAndQKVOA2A,通过 cp_comm_type="a2a" 启用

5.2 通信复杂度

从算法阶段看，forward 在 attention 前后各做一次轴变换，backward 执行对应的逆向变换。实际 collective launch 数取决于实现；例如 TE v2.16 分别处理 Q、K、V，因此“四个轴变换阶段”与 profiler 中的 kernel 数不是一一对应关系。下面的公式表示 forward 与 backward 的简化元素流量：

$$ V_{\text{comm}}^{\text{Ulysses, fwd+bwd}} = 4 \times 2 \times \frac{H + 2 H_{kv}}{\text{tp}} \times \frac{S}{\text{cp}} \times d \times \frac{\text{cp} - 1}{\text{cp}} $$

这个公式的标度取决于扩展方式。固定 $S$ 增大 cp 时,$S/\text{cp}$ 项使每卡流量下降;当 $S$ 与设备数同比增长时,$S/\text{cp}$ 保持不变,每卡流量才趋于常数。相同弱扩展条件下,Ring 需要轮转随全局序列增长的 KV,两者才出现论文所强调的差别。

论文原文表述(Jacobs et al. §3):"maintains constant communication volume when sequence length and compute devices are increased proportionally"。

5.3 A2A 实现约束:本地 head 必须可整除

无 KV replication 的 head-parallel A2A 需要把本 rank 的 Q、K、V head 均匀发给 A2A group。以 TE v2.16 为例,源码明确检查本地 Q/K/V head 数都能被 cp_size 整除。若 TP 已均匀切分 head,可写成:

$$ \text{cp}_{a2a} \mid \frac{H}{\text{tp}}, \qquad \text{cp}_{a2a} \mid \frac{H_{kv}}{\text{tp}} $$

因此 $\text{tp}\times\text{cp}_{a2a}\le H_{kv}$ 只是必要条件,还缺少整除要求。这里约束的是 Ulysses/A2A 子组,不是 Ring P2P 使用的总 CP size。

以 LLaMA3-8B 的 $H_{kv}=8$ 为例,若 tp=2,TE v2.16 的直接 GQA A2A 路径要求 cp_a2a 整除本地 4 个 KV heads,所以可选值至多为 4。纯 Ulysses 的扩展度因而受 head 数限制;LoongTrain 论文也把这一点列为 head parallelism 的扩展边界。KV replication 或其它 headwise chunking 可以改变边界,代价是额外流量或更复杂的实现。USP/LoongTrain/TE hybrid CP 则保留较小的 cp_a2a,再用不受 head 整除约束的 cp_p2p 扩展总 CP size。

6. USP 与 LoongTrain 的二维组合

Ring 通过序列轴提供较大的 CP degree，代价是多轮 P2P；Ulysses 通过 head 轴控制弱扩展中的每卡通信量，其 degree 受本地 head 整除条件约束。USP（Fang & Zhao，arXiv:2405.07719v1）与 LoongTrain（Gu et al.，arXiv:2406.18485v1）把两条轴组合成二维 CP。LoongTrain 进一步给出 Double-Ring 与设备映射方案。

6.1 Ulysses × Ring 二维网格

把 cp 拆成两个维度:

$$ \text{cp} = \text{cp}_{a2a} \times \text{cp}_{p2p} $$

GPU 拓扑组织成二维网格:

  • A2A 维(cp_a2a 个 rank):用 Ulysses A2A 切 head。对 TE v2.16 的直接 GQA 路径,cp_a2a 必须同时整除 TP-local Q/K/V head 数。通常优先映射到高带宽域,但这不是算法要求。
  • P2P 维(cp_p2p 个 rank):用 Ring P2P 继续切 sequence。它可以跨节点,性能取决于网络拓扑和 overlap。

所以一次 attention 的流程是:

  1. 第 1 个 A2A:在 a2a 组内换轴,每个 rank 拿到一部分 head,以及当前 p2p 坐标所覆盖的完整序列分片;只有再经过 P2P 维的轮转才覆盖全局 sequence。
  2. Ring Attention:在 p2p 组内对这部分 head 跑 ring attention(cp_p2p 步轮转)。
  3. 第 2 个 A2A:换轴回来,output 还是 [H/tp, S/cp, d] 形状。
例 6.1：LLaMA3-8B 在 16 卡上 $H_{kv} = 8$,假设 tp=2,要 cp=16:
- 纯 Ulysses 的上限是 cp ≤ $H_{kv} / \text{tp} = 4$，低于目标 cp=16。
- 纯 Ring 可以达到 cp=16，代价项是 16 步 P2P 的消息 latency 与跨节点链路。
- USP/LoongTrain 取 cp_a2a=4（整除本地 4 个 KV heads）、cp_p2p=4，总 cp 为 16。常见映射把 A2A 放在节点内高速域，把 4-way Ring 放到节点间；最终选择由具体拓扑和 profile 决定。

yunchang 提供 USP 参考实现。TE v2.16 也支持 cp_comm_type="a2a+p2p",并明确要求 cp_group = [a2a_cp_group, p2p_cp_group],见固定版本源码。

USP 公开 benchmark(arXiv:2405.07719):LLAMA3-8B 208K seq,2 × 8 × A800 RDMA,269.8 TFLOPS,MFU 0.86。

6.2 LoongTrain 的 Double-Ring

LoongTrain 在其 8 节点 Ampere 测试平台上观察到，普通 Ring 每一步使用一条发送和一条接收路径，论文所用映射未能充分利用每节点 4 张 NIC 的 multi-rail 资源。这个结论绑定于论文的拓扑与 rank mapping；其它系统需要根据通信库和设备放置重新测量。

LoongTrain 的 Double-Ring Attention 把单一 ring 拆成双层 ring:

  • 内环(inner ring):intra-node 几张 GPU 组成,走 NVLink。多个内环并行。
  • 外环(outer ring):跨节点移动各内环的初始 KV chunk。论文的映射让多个外环传输并发,以提高多 NIC 利用率;实际效果仍受 rank placement 和通信库选择影响。

LoongTrain v1 的公开实验覆盖最长 1M sequence，并在论文测试配置中报告相对 DeepSpeed-Ulysses 和 Megatron-CP 的 MFU 最大提升为 2.88×。该数值是特定序列长度、拓扑与软件配置下的上界结果。

7. MagiAttention 的动态 mask 分配

二维 CP 解决 head degree 与序列通信的组合问题；复杂 mask 还要求系统表达有效 attention 区域，并把区域均衡分配给 rank。sparse、varlen、block-causal、视频 AR 与 MoD 等 mask 的支持范围由 kernel 的 mask 表示和分片接口共同决定。

MagiAttention 把这项工作拆成 mask 表示、负载求解、按需通信与分阶段重叠。本文的实现描述以 v1.1.1（2026-05，核对日期 2026-08-28）为边界；该项目首次公开发布于 2025 年，后续版本可能调整 backend 与依赖。

7.1 Flexible Flash Attention 内核(FFA)

MagiAttention v1.1.1 的 Flexible Flash Attention（FFA） 用 AttnSlice 表示一个 Q range、一个 KV range 与对应的 mask type。多个 slice 的并集组成完整 mask，从而扩展常见 FlashAttention API 中 causal、window_size 等固定参数所能表达的区域：

AttnSlice = (QRange, KRange, MaskType)
         ↑       ↑         ↑
       Q 段     KV 段    mask 类型: FULL / CAUSAL / INV-CAUSAL / BI-CAUSAL

一个 mask = AttnSlice 的集合 = 多个矩形块的并集

例如，document-causal mask 可以分解为多个 (Qrange, Krange, CAUSAL) slice，每个 slice 覆盖一个文档内的因果区域；视频 AR 的 block-causal mask 也可采用类似分解。FFA kernel 直接消费这一表示，使不同 mask 共享同一套 slice 接口。

v1.1.1 README 报告 FFA 在其 Hopper benchmark 中达到与 FlashAttention-3 可比较的性能。这个范围限定在项目公布的 shape、mask 与版本组合。

7.2 Dispatch Solver:复杂 mask 的负载均衡

Zigzag 假定 mask 是规整的因果三角形,可以直接构造前后 chunk 配对。MagiAttention 面对项目所支持的复杂 mask 组合,将分片写成一个优化问题:

$$ f^* = \arg\min_f \max_j \text{SumArea}(B_j) $$

其中 $f$ 是把 chunks 分到 cp 个 bucket 的分配方案,$B_j$ 是 bucket $j$ 的负载(mask 内的 entry 数)。这是 NP-hard,实际用贪心 min-heap 近似,$O(n \log n)$ 一次迭代。

在项目给定的 mask 表达和 chunk 粒度下,Dispatch Solver 可以处理比规则因果三角形更复杂的负载分配。结果是否接近最优,仍取决于 mask 形状、chunk 粒度和贪心近似质量。

7.3 GroupCast/GroupReduce:减少冗余通信

GroupCast/GroupReduce 针对固定 Ring/A2A 模式可能发送无效 KV 区间的问题。项目文档给出两类例子:

  • Ring 在 causal mask 下轮转的 KV 包含被 mask 排除的 entry。论文将这部分统计为 "causal mask causes 25% redundant communication"。
  • varlen block-causal 下冗余更高,"can exceed 33% redundancy"。

MagiAttention 用两个新通信原语取代 P2P/A2A 的固定模式:

原语语义底层
GroupCast(正向)给定 ranks → (起始 offset, 长度) 的 mapping,把需要的 KV 段发给需要它的 rank,不冗余AllToAll-v + Range-Gather kernel
GroupReduce(反向)类似,但 reduce 梯度,不分发Range-Scatter-Reduce kernel

按 v1.1.1 README 的版本记录,v1.0.5 先提供基于 DeepEP 的节点内实验性 group collective;v1.1.0 才加入节点内和节点间的原生 group collective 支持。这里描述的是该项目版本的实现选择,不是 GroupCast/GroupReduce 的算法必备依赖。

7.4 Multi-Stage Overlap

v1.1.1 将 GroupCast/GroupReduce 切成多个 stage,尝试让一个 stage 的通信与另一个 stage 的 FFA 计算并发。可隐藏比例取决于 stage 划分、消息大小和 kernel 时间,并非固定只暴露某一个 stage。

7.5 公开 benchmark

README 和官方博客里和 Ulysses、Ring P2P、Ring AllGather、USP、LoongTrain、Megatron HybridCP 逐一对比,测试规模:H100 集群 8K seq/device,B200 集群 16K seq/device,cp 从 8 到 64。Mask 类型:full / causal / varlen full / varlen causal。

Communication Methods and Implementation Constraints in Context Parallelism

Long-sequence training expands the token activations of a Transformer layer beyond the capacity of one GPU. Context Parallelism (CP) distributes one sample along the sequence dimension: LayerNorm, MLP, and projections can process local tokens, while global attention still requires every query to reach the full K/V context. Restoring that dependency across ranks changes the communication primitive, peak memory, causal-mask load distribution, and the overlap window between communication and local attention. This article analyzes AllGather KV, Ring Attention, Ulysses, two-dimensional compositions, and dynamic mask assignment under one cost model, while separating algorithmic conditions, fixed-version implementation constraints, and topology-dependent configuration.

All references are drawn from public sources: arXiv papers, open-source GitHub repositories, and official documentation. This is Part 1 of the "LLM Training Systems" series.

0. Partition boundary for long-sequence attention

As training sequences grow from a few thousand tokens to hundreds of thousands or more, token-wise activations and dense attention expand at different rates. The bounds below describe algorithmic scaling; actual memory and step time also depend on model structure, attention kernels, recomputation, and batch shape.

  • Activation memory: many token-wise activations grow approximately linearly with $S$.
  • Attention compute: the two dense-attention matrix multiplications grow as $O(S^2)$. Whether they dominate the full step also depends on the FFN, parallel layout, and kernel efficiency.

Training systems distribute work along several axes. Their relationship to CP becomes clear when organized by the object being sharded and the sequence boundary retained by one sample:

Parallel dimensionSharded object and sequence boundary
Data Parallel (DP)Distributes samples; each rank processes the complete samples assigned to it.
Tensor Parallel (TP)Shards weights and layer compute and introduces per-layer collectives. As TP grows, each rank's GEMMs get shorter, and overlap depends on hidden size, sequence length, topology, and tp_comm_overlap. The Megatron-Core 0.16.0 documentation describes the same conditional boundary.
Pipeline Parallel (PP)Distributes layers across stages; each stage processes the full sequence in its micro-batch.

Context Parallelism shards one sample into cp parts along $S$. Token-wise modules such as LayerNorm, FFN, and QKV projection consume a local shard directly; other cross-token operations must restore their own global dependencies. For dense attention, $\text{Attention}(Q, K, V) = \text{softmax}(QK^T/\sqrt{d})\,V$ requires each local query to cover all K/V tokens in the same sequence, so the main CP exchange sits at the attention boundary. The Megatron-Core 0.16.0 CP documentation uses the same scope.

Comparison dimensions: CP methods diverge at the distribution of attention data. This article compares their communication primitive and byte volume, communication-compute overlap, mask-induced load distribution, and supported tensor layouts.

Communication bytes become comparable only when paired with local compute time and achievable link performance. The following model establishes common notation and scaling scenarios that every method section will reuse.

1. Unified communication and compute model

The model separates per-rank attention time into local computation and data exchange. It temporarily omits collective latency, software scheduling, and kernel-launch overhead to expose first-order trends in $S$, cp, and tp.

1.1 FLOPs and communication volume of attention

Notation (used throughout the article):

SymbolMeaning
$S$Sequence length (per sample)
$H$Number of attention heads (with MHA, $H_{kv} = H$)
$H_{kv}$Number of KV heads (with GQA, $< H$)
$d$Per-head hidden dimension
$\text{cp}$Context parallel size
$\text{tp}$Tensor parallel size (split along the head dimension)
$\text{flops}$Achievable per-GPU FLOPS (TFLOPS)
$BW$Achievable communication bandwidth (GB/s)

The compute for one forward attention (ignoring softmax / LayerNorm; only the two matmuls $QK^T$ and $\text{attn} \cdot V$):

$$ V_{\text{compute}} = 4 \times \frac{H}{\text{tp}} \times S^2 \times d $$

where 4 = 2 matmuls × 2 FMA ops/element. If the kernel skips the strict upper triangle, the ideal causal work is about half of full attention:

$$ V_{\text{compute, causal}} = 2 \times \frac{H}{\text{tp}} \times S^2 \times d $$

Introducing cp, each GPU only computes $1/\text{cp}$ of the work (ideal balance):

$$ V_{\text{compute, per GPU}} = \frac{V_{\text{compute}}}{\text{cp}} $$

Each method produces a different $V_{\text{comm}}$ through its data objects, number of rounds, and transfer granularity. Some exchange complete KV tensors, some rotate KV chunks, and others redistribute Q, K, V, and output. Each method section derives its own $V_{\text{comm}}^{\text{method}}$.

The total time for one attention (assuming communication and compute do not overlap):

$$ T_{\text{attn}} = \frac{V_{\text{compute, per GPU}}}{\text{flops}} + \frac{V_{\text{comm}}}{BW} $$

With complete concurrency, the leading bandwidth-model term can be approximated by $\max$. Partial overlap, collective latency, and synchronization keep real time above that lower bound.

1.3 Topology mapping: frequency and bandwidth

Mapping $DP \times PP \times CP \times TP$ groups onto a GPU mesh depends on message frequency, granularity, and overlap time. On common eight-GPU NVLink nodes, configurations often keep frequent, fine-grained TP collectives inside the fast fabric, then place CP according to attention traffic; PP and bucketed, overlapped DP communication are easier to extend across nodes. Larger NVLink domains, different NIC counts, and overlap schedules can change this empirical ordering, which is a performance choice rather than a correctness condition.

The Megatron-Core 0.16.0 documentation explains that increasing TP may shorten the compute interval available to cover communication. The LoongTrain paper analyzes Ring multi-rail utilization on a specific eight-node system with four NICs per node. Together, these sources support a conditional configuration method: substitute message size, collective implementation, link latency, and bandwidth, then validate TP and CP placement with profiling.

2. Full-replica path with AllGather KV

AllGather KV constructs complete K/V tensors on every rank before running local attention. TransformerEngine v2.16 exposes this optional path through cp_comm_type="all_gather"; the same dispatcher also provides p2p, a2a, and a2a+p2p. See the fixed-version source for the dispatch logic.

2.1 Idea and tensor shapes

Each GPU holds KV of shape [H, S/cp, d]. After AllGather: [H, S, d]. Q is unchanged, still [H, S/cp, d]. Then run a standard FlashAttention to get the output of shape [H, S/cp, d].

# Simplified from TE v2.16 AttnFuncWithCPAndKVAllGather (line 3018 onward)
def forward(ctx, q, k, v, cp_group, ...):
    cp_size = get_world_size(cp_group)

    # Step 1: AllGather K, V across cp_group
    k_ag, _ = gather_along_first_dim(k, cp_group)   # [cp*S/cp, ..] -> [S, ..]
    v_ag, _ = gather_along_first_dim(v, cp_group)

    # Step 2: chunk reorder for causal mask (§4 zigzag)
    chunk_ids = get_seq_chunk_ids_for_reordering_before_attn(cp_size, k.device)
    k_ag = torch.index_select(k_ag, dim=0, index=chunk_ids)
    v_ag = torch.index_select(v_ag, dim=0, index=chunk_ids)

    # Step 3: local FA (each GPU processes its own Q chunk, but has full KV)
    out = flash_attn_func(q, k_ag, v_ag, causal=is_causal)
    return out

2.2 Communication volume and model

The KV communication volume per GPU (bf16, 2 bytes):

$$ V_{\text{comm}}^{\text{AG}} = 2 \times 2 \times \frac{H_{kv}}{\text{tp}} \times S \times d $$

The two 2s represent K + V and the bf16 byte size. The formula counts the gathered K/V as a full tensor; remote bytes received add a factor of $(\text{cp}-1)/\text{cp}$. A smaller $H_{kv}$ under GQA reduces this traffic.

Time (ignoring reorder overhead):

$$ T_{\text{AG}} = \frac{V_{\text{compute}}}{\text{flops} \cdot \text{cp}} + \frac{V_{\text{comm}}^{\text{AG}}}{BW_{\text{AG}}} $$

To expose the scaling trend, first treat $BW_{\text{AG}}$ as constant. Actual collective bandwidth varies with rank count, message size, topology, and NCCL algorithm, so the following are model trends rather than guarantees:

  • Scenario 1 (tp fixed, cp grows): ideal compute time falls with cp, while every rank still materializes full K/V and the communication term approaches a floor. A sufficiently large cp may become communication-bound.
  • Scenario 2 (tp × cp fixed): as cp grows and tp shrinks, $H_{kv}/\text{tp}$ grows, increasing the modeled communication term. End-to-end time still depends on GEMM efficiency and measured collective behavior.

3. Chunked P2P path with Ring Attention

AllGather creates a concentrated KV communication phase before local attention. How much of that phase is exposed depends on whether the implementation can chunk, prefetch, or overlap the transfer with other work. Ring Attention (Li et al. 2021, Liu et al. 2023) splits the AllGather into cp P2P send/recv steps: each received KV chunk is immediately processed against the local Q, creating an opportunity to overlap communication with computation.

3.1 KV rotation and online softmax

Each GPU holds its own Q chunk, and $K_i$ rotates around the ring. At each step:

  1. Compute: compute partial attention on the currently held $(Q_{\text{local}}, K_j, V_j)$, accumulating via online softmax.
  2. Communicate: P2P-send $(K_j, V_j)$ to the next rank in the ring; simultaneously recv $(K_{j-1}, V_{j-1})$ from the previous rank.
  3. Loop: repeat cp times, until each KV chunk has met every local Q chunk once.

The implementation overlaps attention on the current chunk with transfer of the next KV chunk. When per-step communication time does not exceed per-step computation time, local attention can cover the bandwidth term. The following diagram shows the schedule for cp=4:

3.2 Communication-computation overlap boundary

Per-step (per chunk) communication and compute:

$$ V_{\text{comm}}^{\text{step}} = 4 \times \frac{H_{kv}}{\text{tp}} \times \frac{S}{\text{cp}} \times d $$

$$ V_{\text{compute}}^{\text{step}} = 4 \times \frac{H}{\text{tp}} \times \frac{S^2}{\text{cp}^2} \times d $$

4 = K + V × 2 bytes (bf16); compute scales as $\frac{1}{\text{cp}^2}$ because both the Q chunk and the KV chunk are of size $S/\text{cp}$.

The condition for communication to be fully hidden by compute:

$$ \frac{V_{\text{comm}}^{\text{step}}}{BW} \leq \frac{V_{\text{compute}}^{\text{step}}}{\text{flops}} \quad\Longrightarrow\quad \text{cp} \leq \frac{BW \times S}{\text{flops}} \times \frac{H}{H_{kv}} $$

Call this simplified condition the overlap boundary $\text{cp}_{\text{bor}}$. Below it, computation may cover the bandwidth term; above it, fixed-$S$ strong scaling approaches a communication floor. Per-step bytes shrink as $1/\text{cp}$ while the number of steps grows with cp, keeping pure bandwidth volume near a constant as P2P latency, synchronization, and load imbalance accumulate. The equation is a first-order estimate.

Example 3.2 Use hypothetical values to illustrate the equation: $BW=540$ GB/s or $43$ GB/s, effective BF16 compute 550 TFLOPS, $S=128\text{K}$, and MHA (no GQA):
Faster link: $\text{cp}_{\text{bor}} \approx \frac{540 \times 10^9 \times 128 \times 1024}{550 \times 10^{12}} \approx 128$.
Slower link: $\text{cp}_{\text{bor}} \approx \frac{43 \times 10^9 \times 128 \times 1024}{550 \times 10^{12}} \approx 10$.

These values are substitutions into a bandwidth model and expose the relationship among variables. A measured boundary for DGX-H100 or a particular CP configuration also moves with collective rail usage, message latency, GQA ratio, and backend.

3.3 Backward pass

Backward Ring must propagate and reduce dK/dV in addition to the forward data movement, so both communication and compute increase. The exact ratio depends on the kernel, recomputation, and schedule. TE v2.16 organizes forward and backward within the same fixed-version P2P implementation.

4. Load balancing under a causal mask

Contiguous sequence shards combined with a standard causal mask cover triangular areas of different sizes on different ranks, creating load imbalance. Sparse and block masks need the same analysis with work estimated from their own valid-region geometry.

4.1 Triangular load under contiguous sharding

Take $S = 8, \text{cp} = 2$ as an example. Under a causal mask, which $(i, j)$ have to be computed? The lower triangle with $j \leq i$:

              KV chunk
              0,1,2,3  4,5,6,7
       Q  0  [  ■        ░     ]    GPU 0 (holds Q0..Q3)
       c  1  [  ■        ░     ]
       h  2  [  ■        ░     ]
       u  3  [  ■        ░     ]
       n  ─────────────────────
       k  4  [  ■        ■     ]    GPU 1 (holds Q4..Q7)
          5  [  ■        ■     ]
          6  [  ■        ■     ]
          7  [  ■        ■     ]

       ■ = compute;  ░ = skip (j > i)

With contiguous sharding, GPU 0 holds Q[0..3], KV[0..3], while GPU 1 holds Q[4..7], KV[4..7]. Under the causal mask, GPU 0 computes half of the upper-left 4×4, or 8 cells; GPU 1 computes the complete left 4×4 plus half of the right 4×4, or 24 cells. Their work differs by a factor of three, and every Ring round is bounded by the slowest rank.

4.2 Striped Attention

Striped Attention (Brandon et al., arXiv:2311.09431) interleaves tokens with stride=cp, distributing each rank's positions across the full sequence. The resulting causal areas are more similar across ranks:

       Striped partition with cp = 2:
       GPU 0 holds tokens 0, 2, 4, 6  (even positions)
       GPU 1 holds tokens 1, 3, 5, 7  (odd  positions)

       This way every (Q_i, K_j) pair on every GPU sees
       a similar "geometry" of the causal mask,
       reducing imbalance as the granularity gets finer.

Published results (paper §5): 1.45× speedup at 256K sequence on A100, 1.65× speedup at 786K sequence on 16× TPUv4.

4.3 Zigzag / dual-chunk layout

Another common layout is usually called Zigzag or dual-chunk: split the sequence into 2×cp chunks and assign one front and one back chunk to each GPU. Megatron-Core r0.16.0 uses this mapping in get_batch_on_this_cp_rank; TE v2.16 source comments call it discontiguous sequence chunks / DualChunking.

       cp = 2, seq split into 4 chunks:
       chunk_0  chunk_1  chunk_2  chunk_3

       GPU 0 holds: chunk_0 + chunk_3  (front + back)
       GPU 1 holds: chunk_1 + chunk_2  (middle two)

       Under the causal mask:
       - GPU 0: small work on chunk_0 + large work on chunk_3
       - GPU 1: medium work on chunk_1 + medium work on chunk_2

       The two sums are nearly equal → load-balanced.

The TransformerEngine v2.16 reorder function:

def get_seq_chunk_ids_for_reordering_before_attn(cp_size, device):
    """Reorder 2*cp chunks so that the rank-th GPU gets
       chunk_{2*rank} and chunk_{2*cp - 2*rank - 1}."""
    chunk_ids = torch.empty(2 * cp_size, dtype=torch.int32, device=device)
    for rank in range(cp_size):
        chunk_ids[rank]           = 2 * rank
        chunk_ids[rank + cp_size] = 2 * cp_size - 2 * rank - 1
    return chunk_ids

Megatron-Core r0.16.0 slices the batch in get_batch_on_this_cp_rank. TE v2.16 explains that the reorder can take place in the dataloader when all layers share one CP configuration, allowing the result to be reused. The algorithmic condition is a correct pre-attention layout with consistent indexing for tokens, positions, and mask metadata; the dataloader is one implementation location that satisfies it.

Terminology: this article uses Zigzag / dual-chunk for the layout in which each rank receives two discontiguous front/back chunks. Striped Attention interleaves at token stride. Repository names vary, and the index mapping provides the criterion for distinguishing the two.

4.4 Practical notes

  • The Megatron-Core r0.16.0 utility reshapes the sequence dimension into 2 * cp_size chunks, so that dimension must divide evenly or use padding/a different partitioner.
  • The reorder may run in the data path or immediately before attention; related tensors and mask metadata must use consistent indices.
  • Dual-chunk layout often reduces triangular imbalance for contiguous causal attention. Non-causal, sliding-window, packed/varlen, and custom masks require validation of both benefit and conversion cost on the selected backend and layout.

5. Head-axis redistribution in Ulysses

Ring, Striped, and Zigzag retain sequence shards and use P2P rotation so that each local Q reaches every KV chunk. DeepSpeed Ulysses (Jacobs et al., arXiv:2309.14509) uses AllToAll before attention to exchange the sequence and head axes, leaving each rank with the complete sequence for a subset of heads.

5.2 Communication complexity

At the algorithmic stage level, forward transforms the distribution before and after attention, and backward applies the corresponding reverse transformations. Actual collective launch count depends on the implementation; TE v2.16 handles Q, K, and V separately, so the four axis-transform stages do not map one-to-one onto profiler kernel counts. The following equation expresses a simplified forward-plus-backward element volume:

$$ V_{\text{comm}}^{\text{Ulysses, fwd+bwd}} = 4 \times 2 \times \frac{H + 2 H_{kv}}{\text{tp}} \times \frac{S}{\text{cp}} \times d \times \frac{\text{cp} - 1}{\text{cp}} $$

The scaling depends on the experiment. With fixed $S$ and increasing cp, the $S/\text{cp}$ term lowers per-GPU volume. Per-GPU volume approaches a constant only when $S$ grows proportionally with the device count, keeping $S/\text{cp}$ fixed. Under that weak-scaling condition, Ring rotates KV for a growing global sequence, which is the distinction emphasized by the Ulysses paper.

The original wording in the paper (Jacobs et al. §3): "maintains constant communication volume when sequence length and compute devices are increased proportionally".

5.3 A2A implementation constraint: local heads must divide evenly

A head-parallel A2A implementation without KV replication must distribute each rank's local Q, K, and V heads evenly across the A2A group. TE v2.16 asserts that all local Q/K/V head counts are divisible by cp_size. With ordinary even TP partitioning:

$$ \text{cp}_{a2a} \mid \frac{H}{\text{tp}}, \qquad \text{cp}_{a2a} \mid \frac{H_{kv}}{\text{tp}} $$

Thus $\text{tp}\times\text{cp}_{a2a}\le H_{kv}$ is necessary but not sufficient; divisibility is also required. This constraint applies to the Ulysses/A2A subgroup, not to the total CP size used by Ring P2P.

For LLaMA3-8B with $H_{kv}=8$ and tp=2, the direct TE v2.16 GQA A2A path requires cp_a2a to divide four local KV heads, so it can be at most 4. Pure Ulysses is therefore bounded by the head count; the LoongTrain paper describes the same limit for head parallelism. KV replication or other headwise chunking can move the boundary at the cost of traffic or implementation complexity. USP, LoongTrain, and TE hybrid CP keep cp_a2a small and extend total CP with cp_p2p, which has no head-divisibility requirement.

6. Two-dimensional composition in USP and LoongTrain

Ring provides a large CP degree through the sequence axis at the cost of multiple P2P rounds. Ulysses controls per-GPU communication under long-sequence weak scaling through the head axis, with a degree limited by local-head divisibility. USP (Fang & Zhao, arXiv:2405.07719v1) and LoongTrain (Gu et al., arXiv:2406.18485v1) combine these axes into two-dimensional CP. LoongTrain also specifies Double-Ring and device-placement schemes.

6.1 Ulysses × Ring 2D grid

Split cp into two dimensions:

$$ \text{cp} = \text{cp}_{a2a} \times \text{cp}_{p2p} $$

The GPU topology is organized as a 2D grid:

  • A2A dimension (cp_a2a ranks): Ulysses A2A splits heads. For TE v2.16's direct GQA path, cp_a2a must divide every TP-local Q/K/V head count. It is commonly placed in a high-bandwidth domain, but that is not an algorithmic requirement.
  • P2P dimension (cp_p2p ranks): Ring P2P further shards the sequence. It can cross nodes; performance depends on topology and overlap.

So one attention does the following:

  1. First A2A: swap axes within the A2A group; each rank receives a subset of heads and the complete sequence shard owned by its current P2P coordinate. The later P2P rotation is what covers the global sequence.
  2. Ring Attention: within the p2p group, run ring attention on these heads (cp_p2p rotations).
  3. Second A2A: swap axes back; output is still shaped [H/tp, S/cp, d].
Example 6.1: LLaMA3-8B on 16 GPUs $H_{kv} = 8$; assume tp=2 and want cp=16:
- Pure Ulysses is bounded by cp ≤ $H_{kv} / \text{tp} = 4$, below the target cp=16.
- Pure Ring reaches cp=16, with 16-step P2P latency and cross-node links as its main cost terms.
- USP/LoongTrain uses cp_a2a=4, which divides the four local KV heads, and cp_p2p=4 for total cp=16. A common mapping keeps A2A in the fast intra-node domain and runs the 4-way Ring across nodes; profiling the actual topology determines the final choice.

yunchang provides a USP reference implementation. TE v2.16 also supports cp_comm_type="a2a+p2p" and explicitly requires cp_group = [a2a_cp_group, p2p_cp_group]; see the fixed-version source.

USP's public benchmark (arXiv:2405.07719): LLAMA3-8B at 208K seq on 2 × 8 × A800 RDMA, 269.8 TFLOPS, MFU 0.86.

6.2 LoongTrain's Double-Ring

On its eight-node Ampere testbed, LoongTrain observed that a conventional Ring step used one send and one receive path, and the paper's mapping left part of the four-NIC multi-rail capacity unused. This result is tied to that topology and rank mapping; other systems need fresh measurements under their communication library and device placement.

LoongTrain's Double-Ring Attention splits the single ring into a two-level ring:

  • Inner ring: a few intra-node GPUs forming a ring over NVLink. Multiple inner rings run in parallel.
  • Outer ring: moves each inner ring's initial KV chunks across nodes. The paper's placement allows several outer transfers to run concurrently and improve multi-NIC utilization; results still depend on rank placement and the communication library.

LoongTrain v1 evaluates sequences up to 1M and reports a maximum 2.88× MFU improvement over DeepSpeed-Ulysses and Megatron-CP in its test configurations. This value is the upper reported result for particular sequence lengths, topology, and software settings.

7. Dynamic mask assignment in MagiAttention

Two-dimensional CP combines the head-degree and sequence-communication problems. Complex masks add a separate requirement: the system must represent valid attention regions and assign those regions evenly across ranks. Support for sparse, varlen, block-causal, video AR, and MoD masks therefore depends on the kernel's mask representation and partitioning interface.

MagiAttention separates that work into mask representation, load solving, demand-driven communication, and staged overlap. The implementation statements here are pinned to v1.1.1 (2026-05, checked 2026-08-28). The project was first released publicly in 2025, and later versions may change backend and dependency boundaries.

7.1 Flexible Flash Attention kernel (FFA)

MagiAttention v1.1.1 Flexible Flash Attention (FFA) represents one Q range, one KV range, and one mask type in each AttnSlice. The union of several slices forms a complete mask, extending the fixed regions expressed by common FlashAttention parameters such as causal and window_size:

AttnSlice = (QRange, KRange, MaskType)
         ↑       ↑         ↑
       Q range  KV range  mask type: FULL / CAUSAL / INV-CAUSAL / BI-CAUSAL

A mask = a set of AttnSlices = the union of rectangular blocks

For example, a document-causal mask can be decomposed into (Qrange, Krange, CAUSAL) slices, one for each document's causal region. Video AR block-causal masks admit a similar decomposition. The FFA kernel consumes this representation directly, allowing different masks to share the same slice interface.

The v1.1.1 README reports performance comparable to FlashAttention-3 in its Hopper benchmarks. That evidence is scoped to the published combinations of shapes, masks, and software versions.

7.2 Dispatch Solver: load balance for complex masks

Zigzag assumes a regular causal triangle and can construct front/back chunk pairs directly. MagiAttention handles the complex mask combinations supported by the project by formulating partitioning as an optimization problem:

$$ f^* = \arg\min_f \max_j \text{SumArea}(B_j) $$

where $f$ is the assignment of chunks to cp buckets and $B_j$ is the load (entries inside the mask) of bucket $j$. This is NP-hard; in practice they use a greedy min-heap approximation, $O(n \log n)$ per iteration.

Under the project's mask representation and chunking granularity, the dispatch solver can handle load assignments beyond a regular causal triangle. How close it gets to optimal still depends on mask shape, chunk granularity, and greedy approximation quality.

7.3 GroupCast/GroupReduce: reducing redundant communication

GroupCast/GroupReduce address KV ranges that fixed Ring/A2A patterns may send even though the mask makes them unnecessary. The project documentation gives two examples:

  • The KV that Ring rotates under a causal mask contains many entries that are never used (they get masked out); the paper notes "causal mask causes 25% redundant communication".
  • Under varlen block-causal the redundancy is higher, "can exceed 33% redundancy".

7.4 Multi-Stage Overlap

Version 1.1.1 splits GroupCast/GroupReduce into stages and attempts to run one stage's communication concurrently with another stage's FFA compute. The hidden fraction depends on stage partitioning, message size, and kernel time; it is not fixed to one exposed stage.

7.5 Public benchmarks

The README and the official blog compare head-to-head against Ulysses, Ring P2P, Ring AllGather, USP, LoongTrain, and Megatron HybridCP. Test scales: H100 cluster at 8K seq/device, B200 cluster at 16K seq/device, cp from 8 to 64. Mask types: full / causal / varlen full / varlen causal.

Blog figures 44-59 report "near-linear scalability on varlen causal masks" on H100 and B200. Specific TFLOPS values appear only in the figures, so this article retains the qualitative claim.

7.6 Limitations

  • Backend support is versioned: v1.1.0 added early Blackwell support through a forked FA4 backend, and v1.1.1 extended FFA_FA4 to Ampere.
  • The native group-collective implementation in v1.1.1 is based on DeepEP; replacement backends must be checked in the corresponding release source.

9.2 Selection decision tree

Configuration choice begins with mask semantics, head divisibility, and topology. The following flow maps those conditions to implementation paths that should be benchmarked first.

START
  │
  ├─ cp == 1
  │      └→ no CP needed, skip this series
  │
  ├─ mask is non-standard (varlen / sparse / block-causal / video AR)
  │      └→ evaluate MagiAttention or another implementation with explicit mask partitioning
  │
  ├─ sliding-window mask required
  │      └→ AllGather KV (TE: cp_comm_type="all_gather") or Ulysses
  │
  ├─ cp divides both H/tp and H_kv/tp, and the A2A topology is suitable
  │      └→ benchmark Ulysses against RingAttention
  │
  ├─ cp factors into cp_a2a × cp_p2p with a valid head divisor
  │      └→ USP / LoongTrain 2D
  │             ├─ choose cp_a2a from divisors of both H/tp and H_kv/tp
  │             └─ cp_p2p = cp / cp_a2a
  │      On multi-rail networks, compare Ring, Double-Ring, and other hierarchical communication
  │
  └─ otherwise
         └→ start with RingAttention; evaluate dual-chunk for contiguous causal shards
Configuration checks:
① Contiguous causal shards are candidates for dual-chunk layout; verify backend semantics first for other masks and packed/varlen inputs.
② Head divisibility constrains only the A2A subgroup: cp_a2a must divide TP-local Q/K/V head counts. Pure P2P CP has no such constraint.
③ Whether cross-node CP is limiting depends on communication type, GQA ratio, sequence length, rail count, and available compute overlap. A common starting point is to place frequent communicators in the fast domain, then adjust from profiles.
④ GPU and network generations change the best 2D decomposition; a model name alone does not determine a fixed cp layout.
