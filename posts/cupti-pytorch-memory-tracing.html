用 CUPTI 追踪 PyTorch 显存分配

PyTorch 的一次 Tensor 分配，可能复用缓存中的旧地址，也可能触发 CUDA runtime 的 cudaMalloc，或由 driver 的虚拟内存管理接口创建并映射新的物理内存。CUPTI 能记录这些 CUDA 调用的参数、返回值和发生时间，让 Tensor 生命周期、allocator 缓存与底层显存资源之间的关系可以逐项核对。本文以同一段 PyTorch 分配程序，对比普通 native allocator 与 expandable segments 两条路径，并给出可编译的追踪器和运行命令。

示例面向 Linux、CUDA Toolkit / CUPTI 12.8 与 PyTorch 2.8.0，PyTorch 源码固定到 ba56102387ef。这里的 memory 事务指分配、释放和地址映射；kernel 内的 load/store、cache sector 与 DRAM transaction 属于另一种分析尺度。

1. CUPTI 与 Nsight Systems

CUDA 的观测接口

CUPTI（CUDA Profiling Tools Interface）是 NVIDIA 提供的 CUDA profiling / tracing 接口。工具通过它订阅 CUDA API 调用，收集 kernel、memcpy 等活动记录，并将 CPU 提交与 GPU 执行关联起来。它随 CUDA Toolkit 提供头文件、动态库和示例，应用可以在进程内加载自己的采集器。CUPTI 12.8

Nsight Systems 使用 CUPTI 收集 CUDA 相关信息，在此基础上组织时间线、统计与导出文件；它还采集 CPU 调度、OS runtime、NVTX 等其他信息。这些信息各有采集来源，不能把整个 nsys 都视为 CUPTI 的封装。直接使用 CUPTI 的价值在于定义自己的筛选范围和记录字段，例如只关心某几个显存 API 的参数。Nsight Systems / CUPTI

显存事件的层次

观察对象典型问题对应入口
PyTorch Tensor / allocator哪次 Tensor 分配使用了缓存块？Tensor 指针、memory_allocated / memory_reserved、allocator snapshot
CUDA 内存管理何时调用 cudaMalloc、cuMemCreate、cuMemMap？参数是什么？CUPTI Runtime / Driver API callbacks
GPU 数据搬运一次 H2D 实际何时开始、何时结束？MEMCPY activity；CPU API 区间不能替代 GPU 执行区间
Kernel 内存访问Load/store 产生多少 cache / DRAM 流量？硬件计数器与 Nsight Compute 等 profiling 工具

MEMCPY activity 描述实际搬运的字节数和 GPU 起止时间；cudaMalloc callback 描述内存管理 API 的一次调用。两者可以同时出现在 CUDA 工作负载里，但记录的含义不同。CUpti_ActivityMemcpy6。本项目的 GPU 访存路径与 Nsight Compute 讨论 kernel 内的访存层次。

2. Callback 与 Activity

同步 callback

一个 subscriber 将回调函数注册给 CUPTI。Domain 区分 runtime、driver、resource 等事件来源，CBID 标识 domain 内的具体 API。本文只启用两个 runtime CBID 和七个 driver VMM CBID；未订阅的 API 不会出现在这份日志中。Callback API

接口 / 字段用途
cuptiSubscribe注册 callback 与用户状态，取得 subscriber handle
cuptiEnableCallback为一个 domain + CBID 启用或禁用通知
CUPTI_API_ENTER / EXIT在 CUDA API 执行前、返回调用者前运行 callback
functionParams按该 CBID 对应的参数结构读取输入和输出参数
functionReturnValueEXIT 时读取 cudaError_t 或 CUresult
correlationData / correlationId前者保存同一次调用 ENTER / EXIT 之间的工具状态；后者关联对应 activity
cuptiUnsubscribe停止订阅；应在回调代码所在动态库卸载前完成

Runtime 和 Driver API callback 在调用线程上同步执行，日志写入会延长应用的执行路径。callback 内不应调用 CUDA runtime / driver API，也不应创建 CUDA Tensor；这可能引发递归或死锁。示例只读取参数、调用 CUPTI 时间戳接口并写入 CSV。CUPTI Callback usage

参数结构由 Toolkit 的 generated_cuda_runtime_api_meta.h 和 generated_cuda_meta.h 定义。cudaMalloc_v3020_params 中的 v3020 是该 API 参数版本标识，不要求使用 CUDA 3.2。分配地址位于输出参数 *devPtr 中，必须在 EXIT 且返回成功后读取；失败时仍可以记录请求大小和错误码。CUpti_CallbackData

// At CUPTI_API_EXIT for cudaMalloc:
const auto* p = static_cast<const cudaMalloc_v3020_params*>(info->functionParams);
const auto result = *static_cast<const cudaError_t*>(info->functionReturnValue);
const size_t requested_bytes = p->size;
if (result == cudaSuccess) {
    void* allocated_address = *p->devPtr;
    // Copy scalar fields into the trace while the callback data is valid.
}

functionParams 指向的结构只在 callback 有效期内可用。需要异步写日志时，应在回调内复制所需标量，不能把这些临时指针直接塞进后台队列。示例用 correlationData 保存 ENTER 时间戳，并在 EXIT 输出一条完整记录；start_ns / end_ns 是 host 侧 API 边界，不是 GPU 工作持续时间。

异步 activity

Activity API 让 CUPTI 把记录写入工具提供的 buffer，再异步交付给工具。RUNTIME / DRIVER activity 给出 API 名称对应的 CBID、时间、进程 / 线程与返回值；它们不提供 callback 那样的完整 functionParams。需要提取 VMM 的 handle、地址和映射长度时，callback 更直接。CUpti_ActivityAPI

Register buffers: cuptiActivityRegisterCallbacks(requestBuffer, completeBuffer)
Enable records:   cuptiActivityEnable(CUPTI_ACTIVITY_KIND_RUNTIME / DRIVER / ...)
Run workload:     CUPTI fills buffers, then delivers them asynchronously
Consume buffer:   cuptiActivityGetNextRecord(...) until MAX_LIMIT_REACHED
Check losses:     cuptiActivityGetNumDroppedRecords(context, streamId, &dropped)
Finish workload:  synchronize needed CUDA work outside callbacks
Drain records:    cuptiActivityFlushAll(0); release buffers after parsing

Buffer 解析需要处理结束状态、记录版本和丢失计数。cuptiActivityFlushAll 本身不隐式同步 CUDA 工作；希望得到完整 GPU 起止时间时，应用必须先完成所需同步。本文的可运行追踪器只使用 Callback API，因此不注册 activity buffer，也不需要 activity flush。Activity API

CUPTI_ACTIVITY_KIND_MEMORY2 的 CUpti_ActivityMemory4 将分配与释放表示为独立记录，包含地址、字节数、memory kind 等信息。它适合补充内存生命周期视图；逐项重建 VMM 的 reserve、create、map、set-access 过程，仍应检查对应 Driver callback，不能用一条 MEMORY2 记录代替全部步骤。CUpti_ActivityMemory4

Callback 的 correlationId 对应同一 domain 的 API activity。关联记录时需要保留进程与 domain，不能假设相邻 runtime 和 driver 记录共享同一个 ID；例如 CUpti_ActivityMemcpy6 分别提供 driver 的 correlationId 与 runtimeCorrelationId。callback、API activity 和内存 activity 也可能是同一操作的不同视角，不能重复计数。CUpti_CallbackData；CUpti_ActivityMemcpy6

3. PyTorch 显存路径

缓存与 cudaMalloc

Native caching allocator 优先从池中寻找可复用块。缓存不足时，普通路径通过 cudaMalloc 获得更大的分配，再将块交给 Tensor。Tensor 销毁后，allocator 通常保留空闲块供后续使用；只有向 CUDA 归还资源时，才会出现 cudaFree。因此一次 torch.empty 不必对应一次 cudaMalloc，del tensor 也不必对应 cudaFree。cudaMalloc path；Release cached allocation

memory_allocated() 统计 allocator 当前归于 Tensor 等活跃分配的大小，memory_reserved() 统计 allocator 管理的显存。两者都不是进程全部 CUDA 资源的总计；CUDA context、库内部或其他 allocator 的内存可能不包含在内。empty_cache() 释放可归还的空闲缓存，不能释放仍被活跃 Tensor 占用的内存。PyTorch memory management

Expandable segments 与 VMM

backend:native,expandable_segments:True 仍使用 PyTorch 的 native allocator，但改变其向 CUDA 获得内存的方式：先预留连续虚拟地址，再按需创建物理分配并映射。可扩展的是已映射的覆盖范围，缓存复用仍然存在。ExpandableSegment: reserve；ExpandableSegment: create

Driver API管理的资源追踪字段
cuMemAddressReserve预留虚拟地址范围；此时不等于获得同样多的物理显存成功后的 ptr、size
cuMemCreate创建物理内存分配并返回 handle；尚未映射到可访问地址成功后的 handle、size
cuMemMap将物理分配关联到虚拟地址区间ptr、size、handle、offset
cuMemSetAccess设置指定设备对该范围的访问权限ptr、size；需要分析多 GPU 权限时再扩展 desc 数组
cuMemUnmap解除指定地址区间的映射ptr、size
cuMemRelease释放一个 allocation handle 引用；物理资源回收还取决于剩余引用 / 映射handle；从对应成功 create 记录查找大小
cuMemAddressFree归还已解除映射的虚拟地址预留ptr、size

这组 API 把地址空间、物理分配、映射和权限拆开管理。cuMemMap 后仍需设置访问权限，才可供相应设备使用。PyTorch 的释放路径先等待相关工作完成，再 unmap、release；整个 expandable segment 销毁时才 address-free。CUDA VMM API；Map and access；Unmap and release；Release VA range

三个容易混淆的量：cuMemAddressReserve 的 size 是虚拟地址范围；cuMemCreate 的 size 是物理分配大小；PyTorch memory_reserved 是 allocator 的显存统计，不等于预留的整个虚拟地址范围。CU_MEM_ALLOCATION_TYPE_PINNED 配合 DEVICE location 创建的是这里的设备物理内存，也不是 DataLoader pin_memory 使用的页锁定 CPU batch。

本文固定版本的大池使用 20 MiB 分配块，小池使用 2 MiB。这是 allocator 的粒度，不代表 GPU 硬件页大小。一个全新的大池承接 64 MiB 请求，可能需要四个 20 MiB handle，映射总量为 80 MiB。地址预留范围则可能远大于这些实际物理分配。Allocator segment size；ExpandableSegment: reserve

4. 端到端示例

环境与编译

示例需要 NVIDIA GPU、兼容 CUDA 12.8 的驱动、CUDA Toolkit 12.8 开发文件，以及带 CUDA 的 PyTorch 2.8。C++ 追踪器使用普通 g++ 编译，不含 device kernel。安装了 PyTorch wheel 不等于系统已经有完整 CUDA 开发头文件；编译时的 CUPTI headers 和动态库应来自同一版本。

将 memory_trace.cpp、build.sh、allocator_demo.py 和 summarize.py 保存到同一目录。已有匹配环境时可跳过创建 venv 和安装 PyTorch：

# Linux, NVIDIA GPU + compatible driver, CUDA Toolkit 12.8 development files
python3 -m venv .venv
source .venv/bin/activate
python -m pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cu128
nvidia-smi

# Save memory_trace.cpp, build.sh, allocator_demo.py, summarize.py here.
export CUDA_ROOT=/usr/local/cuda-12.8
export TRACE_BUILD="$PWD/build"
bash build.sh

build.sh 默认使用 $CUDA_ROOT/include、$CUDA_ROOT/extras/CUPTI/include 和 $CUDA_ROOT/extras/CUPTI/lib64。发行版安装到其他位置时，可覆盖 CUDA_INCLUDE、CUPTI_INCLUDE 和 CUPTI_LIB。构建产物只链接 libcupti，使用 rpath 指向所选 CUPTI 库目录，无需为截获 cudaMalloc 另写 LD_PRELOAD wrapper。

查看完整编译脚本
#!/usr/bin/env bash
set -euo pipefail

# Override CUDA_INCLUDE, CUPTI_INCLUDE, and CUPTI_LIB for nonstandard installs.
CUDA_ROOT=${CUDA_ROOT:-/usr/local/cuda-12.8}
CUDA_INCLUDE=${CUDA_INCLUDE:-$CUDA_ROOT/include}
CUPTI_INCLUDE=${CUPTI_INCLUDE:-$CUDA_ROOT/extras/CUPTI/include}
CUPTI_LIB=${CUPTI_LIB:-$CUDA_ROOT/extras/CUPTI/lib64}
TRACE_BUILD=${TRACE_BUILD:-./build}
SOURCE_DIR=$(cd -- "$(dirname -- "${BASH_SOURCE[0]}")" && pwd)
test -f "$CUDA_INCLUDE/cuda.h"
test -f "$CUPTI_INCLUDE/cupti.h"
if [[ -f "$CUPTI_LIB/libcupti.so" ]]; then
    CUPTI_LINK=-lcupti
else
    test -f "$CUPTI_LIB/libcupti.so.12"
    CUPTI_LINK=-l:libcupti.so.12
fi
mkdir -p "$TRACE_BUILD"
"${CXX:-g++}" -std=c++17 -O2 -Wall -Wextra -Werror -fPIC -shared -pthread \
    -I"$CUDA_INCLUDE" -I"$CUPTI_INCLUDE" "$SOURCE_DIR/memory_trace.cpp" \
    -L"$CUPTI_LIB" "$CUPTI_LINK" -Wl,-rpath,"$CUPTI_LIB" \
    -o "$TRACE_BUILD/libmemory_trace.so"
printf 'Built %s/libmemory_trace.so\n' "$TRACE_BUILD"

追踪器

Python 用 ctypes 显式加载追踪器，在首次 CUDA 初始化前执行 trace_start，阶段切换时执行 trace_mark，结束时执行 trace_stop。CUPTI 的 domain / CBID 订阅拦截对应调用，所以即使 PyTorch 通过 driver 函数指针调用 VMM，也不依赖同名函数的 ELF 符号替换。

追踪器为每次完成的 API 调用记录 phase、PID / TID、domain、CBID、correlation ID、context UID、函数名、起止时间、返回值与内存字段。失败记录保留请求字节数，但不读取未定义的输出地址或 handle。cudaFree 和 cuMemRelease 本身没有 size 参数，因此其 bytes 留空。

查看完整 C++ 追踪器
// Linux teaching tracer: CUDA Toolkit / CUPTI 12.8, one controlled process.
// Callback logging is synchronous; do not use these timings as a benchmark.
#include <cupti.h>
#include <cupti_driver_cbid.h>
#include <cupti_runtime_cbid.h>
// cupti.h already includes generated_cuda{,_runtime_api}_meta.h in 12.8.
// These generated parameter headers do not have independent include guards.

#include <cinttypes>
#include <cstdio>
#include <cstring>
#include <mutex>
#include <sys/syscall.h>
#include <unistd.h>

namespace {
CUpti_SubscriberHandle subscriber{};
FILE* output = nullptr;
std::mutex output_mutex;
char phase[64] = "INIT";
bool active = false;
bool io_failed = false;

struct Fields {
    uint64_t bytes = 0, address = 0, handle = 0, offset = 0;
    bool has_bytes = false, has_address = false, has_handle = false;
    bool has_offset = false;
};

// Decode inputs at EXIT. Read output pointers ONLY after successful return.
Fields decode(CUpti_CallbackDomain domain, CUpti_CallbackId id,
              const void* params, bool success) {
    Fields f;
    if (domain == CUPTI_CB_DOMAIN_RUNTIME_API) {
        if (id == CUPTI_RUNTIME_TRACE_CBID_cudaMalloc_v3020) {
            const auto* p = static_cast<const cudaMalloc_v3020_params*>(params);
            f.bytes = p->size; f.has_bytes = true;
            if (success && p->devPtr) {
                f.address = reinterpret_cast<uintptr_t>(*p->devPtr);
                f.has_address = true;
            }
        } else if (id == CUPTI_RUNTIME_TRACE_CBID_cudaFree_v3020) {
            const auto* p = static_cast<const cudaFree_v3020_params*>(params);
            f.address = reinterpret_cast<uintptr_t>(p->devPtr);
            f.has_address = true;
        }
        return f;
    }
    switch (id) {
    case CUPTI_DRIVER_TRACE_CBID_cuMemAddressReserve: {
        const auto* p = static_cast<const cuMemAddressReserve_params*>(params);
        f.bytes = p->size; f.has_bytes = true;
        if (success && p->ptr) { f.address = *p->ptr; f.has_address = true; }
        break;
    }
    case CUPTI_DRIVER_TRACE_CBID_cuMemAddressFree: {
        const auto* p = static_cast<const cuMemAddressFree_params*>(params);
        f.bytes = p->size; f.address = p->ptr;
        f.has_bytes = f.has_address = true;
        break;
    }
    case CUPTI_DRIVER_TRACE_CBID_cuMemCreate: {
        const auto* p = static_cast<const cuMemCreate_params*>(params);
        f.bytes = p->size; f.has_bytes = true;
        if (success && p->handle) { f.handle = *p->handle; f.has_handle = true; }
        break;
    }
    case CUPTI_DRIVER_TRACE_CBID_cuMemRelease: {
        const auto* p = static_cast<const cuMemRelease_params*>(params);
        f.handle = p->handle; f.has_handle = true;
        break;
    }
    case CUPTI_DRIVER_TRACE_CBID_cuMemMap: {
        const auto* p = static_cast<const cuMemMap_params*>(params);
        f.address = p->ptr; f.bytes = p->size; f.handle = p->handle;
        f.offset = p->offset;
        f.has_address = f.has_bytes = f.has_handle = f.has_offset = true;
        break;
    }
    case CUPTI_DRIVER_TRACE_CBID_cuMemUnmap: {
        const auto* p = static_cast<const cuMemUnmap_params*>(params);
        f.address = p->ptr; f.bytes = p->size;
        f.has_address = f.has_bytes = true;
        break;
    }
    case CUPTI_DRIVER_TRACE_CBID_cuMemSetAccess: {
        const auto* p = static_cast<const cuMemSetAccess_params*>(params);
        f.address = p->ptr; f.bytes = p->size;
        f.has_address = f.has_bytes = true;
        break;
    }
    default: break;
    }
    return f;
}

uint64_t timestamp() {
    uint64_t value = 0;
    // A zero timestamp is retained as missing data, never a valid duration.
    if (cuptiGetTimestamp(&value) != CUPTI_SUCCESS) return 0;
    return value;
}

void CUPTIAPI callback(void*, CUpti_CallbackDomain domain,
                       CUpti_CallbackId id, const void* data) {
    if (domain != CUPTI_CB_DOMAIN_RUNTIME_API &&
        domain != CUPTI_CB_DOMAIN_DRIVER_API) return;
    const auto* info = static_cast<const CUpti_CallbackData*>(data);
    if (info->callbackSite == CUPTI_API_ENTER) {
        *info->correlationData = timestamp();
        return;
    }
    if (info->callbackSite != CUPTI_API_EXIT) return;
    const uint64_t end = timestamp();
    const uint64_t start = *info->correlationData;
    const int result = domain == CUPTI_CB_DOMAIN_RUNTIME_API
        ? static_cast<int>(*static_cast<const cudaError_t*>(info->functionReturnValue))
        : static_cast<int>(*static_cast<const CUresult*>(info->functionReturnValue));
    const Fields f = decode(domain, id, info->functionParams, result == 0);
    char bytes[32] = "", address[32] = "", handle[32] = "", offset[32] = "";
    if (f.has_bytes) std::snprintf(bytes, sizeof(bytes), "%" PRIu64, f.bytes);
    if (f.has_address) std::snprintf(address, sizeof(address), "0x%" PRIx64, f.address);
    if (f.has_handle) std::snprintf(handle, sizeof(handle), "0x%" PRIx64, f.handle);
    if (f.has_offset) std::snprintf(offset, sizeof(offset), "%" PRIu64, f.offset);
    std::lock_guard<std::mutex> lock(output_mutex);
    if (!output) return;
    const int written = std::fprintf(output,
        "api,%s,%ld,%ld,%s,%u,%u,%u,%s,%" PRIu64 ",%" PRIu64 ",%d,%s,%s,%s,%s\n",
        phase, static_cast<long>(getpid()), static_cast<long>(syscall(SYS_gettid)),
        domain == CUPTI_CB_DOMAIN_RUNTIME_API ? "runtime" : "driver",
        static_cast<unsigned>(id), info->correlationId, info->contextUid,
        info->functionName, start, end, result, bytes, address, handle, offset);
    if (written < 0) io_failed = true;
}

bool check(CUptiResult result, const char* operation) {
    if (result == CUPTI_SUCCESS) return true;
    const char* message = "unknown CUPTI error";
    cuptiGetResultString(result, &message);
    std::fprintf(stderr, "%s: %s (%d)\n", operation, message, static_cast<int>(result));
    return false;
}
}  // namespace

// Call start/mark/stop serially from the controlling Python thread.
// Before stop, all application threads must have left traced CUDA API calls.
extern "C" int trace_start(const char* path) {
    if (active || output || !path) return -1;
    output = std::fopen(path, "w");
    if (!output) { std::perror("open trace"); return -1; }
    io_failed = false;
    std::snprintf(phase, sizeof(phase), "INIT");
    std::fprintf(output, "kind,phase,pid,tid,domain,cbid,correlation_id,context_uid,api,start_ns,end_ns,result,bytes,address,handle,offset\n");
    if (!check(cuptiSubscribe(&subscriber, callback, nullptr), "cuptiSubscribe")) {
        std::fclose(output); output = nullptr; return -1;
    }
    active = true;
    struct Selection { CUpti_CallbackDomain domain; CUpti_CallbackId id; };
    const Selection selection[] = {
        {CUPTI_CB_DOMAIN_RUNTIME_API, CUPTI_RUNTIME_TRACE_CBID_cudaMalloc_v3020},
        {CUPTI_CB_DOMAIN_RUNTIME_API, CUPTI_RUNTIME_TRACE_CBID_cudaFree_v3020},
        {CUPTI_CB_DOMAIN_DRIVER_API, CUPTI_DRIVER_TRACE_CBID_cuMemAddressReserve},
        {CUPTI_CB_DOMAIN_DRIVER_API, CUPTI_DRIVER_TRACE_CBID_cuMemAddressFree},
        {CUPTI_CB_DOMAIN_DRIVER_API, CUPTI_DRIVER_TRACE_CBID_cuMemCreate},
        {CUPTI_CB_DOMAIN_DRIVER_API, CUPTI_DRIVER_TRACE_CBID_cuMemRelease},
        {CUPTI_CB_DOMAIN_DRIVER_API, CUPTI_DRIVER_TRACE_CBID_cuMemMap},
        {CUPTI_CB_DOMAIN_DRIVER_API, CUPTI_DRIVER_TRACE_CBID_cuMemUnmap},
        {CUPTI_CB_DOMAIN_DRIVER_API, CUPTI_DRIVER_TRACE_CBID_cuMemSetAccess},
    };
    for (const auto& item : selection) {
        if (!check(cuptiEnableCallback(1, subscriber, item.domain, item.id), "cuptiEnableCallback")) {
            if (check(cuptiUnsubscribe(subscriber), "cuptiUnsubscribe")) {
                active = false; std::fclose(output); output = nullptr;
            }
            return -1;
        }
    }
    return 0;
}

extern "C" int trace_mark(const char* name) {
    if (!active || !name || std::strlen(name) >= sizeof(phase)) return -1;
    // Keep CSV fields unquoted by restricting phase labels to safe characters.
    for (const char* p = name; *p; ++p) {
        if (!((*p >= 'A' && *p <= 'Z') || (*p >= '0' && *p <= '9') || *p == '_')) return -1;
    }
    const uint64_t now = timestamp();
    std::lock_guard<std::mutex> lock(output_mutex);
    std::snprintf(phase, sizeof(phase), "%s", name);
    if (std::fprintf(output, "phase,%s,%ld,%ld,host,,,,mark,%" PRIu64 ",%" PRIu64 ",0,,,,\n",
        phase, static_cast<long>(getpid()), static_cast<long>(syscall(SYS_gettid)), now, now) < 0) io_failed = true;
    return io_failed ? -1 : 0;
}

extern "C" int trace_stop() {
    if (!active) return -1;
    if (!check(cuptiUnsubscribe(subscriber), "cuptiUnsubscribe")) return -1;
    active = false;
    std::lock_guard<std::mutex> lock(output_mutex);
    const bool failed = io_failed || std::ferror(output);
    const int closed = std::fclose(output); output = nullptr;
    return failed || closed != 0 ? -1 : 0;
}

这是便于阅读的同步 CSV 采集器：一个 mutex 保证每行完整，写入和 callback 都有开销。生产级工具通常在 callback 中复制标量到预分配队列，再由后台线程处理。示例的全局 phase 只适用于这段受控程序；多线程服务需要按线程或显式操作 ID 关联，不能据此把所有 CUDA 调用归因到某个 Python 算子。

分配、复用与释放

程序先分配 64 MiB 的 A，删除后用同样大小的 B 检查缓存复用；B 保持存活时，再分配 96 MiB 的 C，使池需要增长。最后删除 B、C 并 empty_cache。所有 Tensor 都使用 torch.empty，不填值、不做 H2D，这样观察的是 allocator 行为。每个阶段同时输出 PyTorch 内存统计与需要核对的地址。

"""Controlled PyTorch allocation phases. Run each allocator mode in a fresh process."""
import argparse
import ctypes
import gc
import json
import os
from pathlib import Path


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--library", required=True, type=Path)
    parser.add_argument("--trace", required=True, type=Path)
    args = parser.parse_args()
    # Importing torch does not intentionally create CUDA tensors in this script.
    # Set PYTORCH_CUDA_ALLOC_CONF in the launch command, before this import.
    import torch

    if torch.version.cuda is None:
        raise SystemExit("Install a CUDA-enabled PyTorch build; this is a CPU-only build.")
    tracer = ctypes.CDLL(str(args.library.resolve()))
    tracer.trace_start.argtypes = [ctypes.c_char_p]
    tracer.trace_mark.argtypes = [ctypes.c_char_p]
    tracer.trace_stop.argtypes = []
    for name in ("trace_start", "trace_mark", "trace_stop"):
        getattr(tracer, name).restype = ctypes.c_int

    def mark(name):
        if tracer.trace_mark(name.encode()) != 0:
            raise RuntimeError("Could not write trace phase " + name)

    def snapshot(name, **pointers):
        print(json.dumps({"phase": name,
            "allocated": torch.cuda.memory_allocated(),
            "reserved": torch.cuda.memory_reserved(), **pointers}), flush=True)

    args.trace.parent.mkdir(parents=True, exist_ok=True)
    if tracer.trace_start(os.fsencode(args.trace)) != 0:
        raise SystemExit("CUPTI subscription failed; inspect the error above.")
    try:
        mark("INIT")
        torch.cuda.init()
        torch.cuda.synchronize()
        torch.cuda.empty_cache()
        print(json.dumps({"torch": torch.__version__, "cuda_build": torch.version.cuda,
            "allocator_config": os.environ.get("PYTORCH_CUDA_ALLOC_CONF", ""),
            "backend": torch.cuda.memory.get_allocator_backend()}), flush=True)
        snapshot("INIT")

        mark("ALLOC_A")
        a = torch.empty(16 * 1024 * 1024, dtype=torch.float32, device="cuda")  # 64 MiB
        original = a.data_ptr()
        snapshot("ALLOC_A", a=hex(original))

        mark("DROP_A")
        del a
        gc.collect()
        snapshot("DROP_A")

        mark("REUSE_B")
        b = torch.empty(16 * 1024 * 1024, dtype=torch.float32, device="cuda")
        snapshot("REUSE_B", b=hex(b.data_ptr()), reused=(b.data_ptr() == original))

        mark("GROW_C")
        c = torch.empty(24 * 1024 * 1024, dtype=torch.float32, device="cuda")  # 96 MiB
        snapshot("GROW_C", c=hex(c.data_ptr()))

        mark("DROP_ALL")
        del b, c
        gc.collect()
        torch.cuda.synchronize()
        snapshot("DROP_ALL")

        mark("EMPTY_CACHE")
        torch.cuda.empty_cache()
        snapshot("EMPTY_CACHE")
        torch.cuda.synchronize()
    finally:
        # No application worker threads issue CUDA calls in this example.
        # Unsubscribe before ctypes can unload the library at process exit.
        if tracer.trace_stop() != 0:
            raise RuntimeError("Trace shutdown or file write failed")


if __name__ == "__main__":
    main()

地址、handle 与计数

Native 路径可用成功 cudaMalloc 的 address → size 配对 cudaFree；VMM 路径则要分别维护 VA 范围、handle → size，以及 (VA interval, handle, offset) 映射。地址与 handle 都可能被再次使用，需要按发生顺序维护生命周期；不要把某个十六进制值当作全程唯一对象 ID。

例如同一份 80 MiB backing 既产生 80 MiB 的 create 记录，也产生 80 MiB 的 map 记录。二者相加得到的 160 MiB 没有“物理占用”的含义。Reserve 的巨大 size 更不能加入显存总量。通用 VMM 程序还允许多映射、共享 handle 与跨进程引用，cuMemRelease 的一次调用也不足以独立证明物理内存已回收。

配套汇总脚本只按 phase / domain / API 统计成功次数、失败次数及该 API 自身的 bytes 总和，刻意不输出跨 API 的“总显存”。Free / Release 缺少的 size 也不会被当作 0 字节释放。需要绘制占用曲线时，应补上生命周期配对与映射状态分析，并说明统计的是活跃 Tensor、allocator backing 还是保留的 VA。

"""Summarize API events without adding VA reservation bytes to allocation bytes."""
import argparse
import csv
from collections import Counter


def summarize(path):
    with open(path, newline="") as stream:
        rows = list(csv.DictReader(stream))
    if not rows:
        raise ValueError("Empty trace: check subscription, workload, and output path")
    phases = list(dict.fromkeys(row["phase"] for row in rows))
    counts = Counter()
    failed = Counter()
    byte_totals = Counter()
    for row in rows:
        if row["kind"] != "api":
            continue
        key = (row["phase"], row["domain"], row["api"])
        if int(row["result"]) != 0:
            failed[key] += 1
            continue
        counts[key] += 1
        if row["bytes"]:
            byte_totals[key] += int(row["bytes"])
    print(f"{'phase':<14} {'domain':<8} {'API':<24} {'ok':>4} {'failed':>6} {'sum(bytes), MiB':>16}")
    for phase in phases:
        keys = sorted(key for key in counts.keys() | failed.keys() if key[0] == phase)
        if not keys:
            print(f"{phase:<14} (no selected API calls)")
        for key in keys:
            total = f"{byte_totals[key] / 2**20:.2f}" if key in byte_totals else "-"
            print(f"{key[0]:<14} {key[1]:<8} {key[2]:<24} {counts[key]:>4} {failed[key]:>6} {total:>16}")
    print("\nBytes are summed separately per API, not live memory or a cross-API total.")
    print("Reserve = VA range; Create = physical allocation; Map = mapping extent.")
    print("Release/Free can omit a size; recover it from the successful creation record.")
    if not counts:
        raise ValueError("No successful selected API calls: this is not evidence of zero allocation")


if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("trace")
    summarize(parser.parse_args().trace)

Tracing PyTorch memory allocation with CUPTI

A PyTorch Tensor allocation may reuse a cached address, call the CUDA runtime’s cudaMalloc, or create and map physical memory through driver virtual memory management APIs. CUPTI exposes the arguments, results, and timing of these CUDA calls, connecting Tensor lifetimes to allocator caches and underlying resources. A single allocation workload compares the ordinary native allocator with expandable segments, using a compilable tracer and explicit launch commands.

The example targets Linux, CUDA Toolkit / CUPTI 12.8, and PyTorch 2.8.0, with PyTorch source pinned to ba56102387ef. Memory operations here mean allocation, release, and address mapping. Kernel load/store instructions, cache sectors, and DRAM transactions are a different observation level.

1. CUPTI and Nsight Systems

Observing CUDA

CUPTI, the CUDA Profiling Tools Interface, provides NVIDIA’s interfaces for CUDA profiling and tracing. Tools subscribe to API calls, collect kernel and memcpy activities, and correlate CPU submissions with GPU execution. The Toolkit supplies headers, libraries, and samples for building a collector loaded into the application process. CUPTI 12.8

Synchronous callbacks

A subscriber registers a callback with CUPTI. A domain identifies runtime, driver, resource, or another event category; a CBID identifies a particular API within that domain. Runtime and Driver API callbacks execute synchronously on the calling thread. Logging therefore adds work to the application’s execution path. Do not call CUDA runtime / driver APIs or create CUDA tensors inside these callbacks: recursion or deadlock may result. This example reads parameters, obtains CUPTI timestamps, and writes CSV. The Toolkit’s generated_cuda_runtime_api_meta.h and generated_cuda_meta.h define parameter structures. The v3020 suffix in cudaMalloc_v3020_params identifies an API parameter version, not a requirement to install CUDA 3.2. The allocated address is an output, *devPtr, and must only be read at a successful EXIT. A failed call still has a request size and an error worth recording. CUpti_CallbackData

functionParams is valid only during the callback. An asynchronous logger must copy needed scalar values before returning, rather than retain these temporary pointers. The example stores the ENTER timestamp in correlationData and writes one record at EXIT. Its start_ns / end_ns delimit host API execution, not GPU work.

Asynchronous activities

The Activity API fills tool-provided buffers and delivers records asynchronously. RUNTIME / DRIVER activities contain CBID, timing, process / thread IDs, and return values. They do not expose the full functionParams available to callbacks. Callbacks are the direct route to VMM handles, addresses, and mapping lengths. CUpti_ActivityAPI

Register buffers: cuptiActivityRegisterCallbacks(requestBuffer, completeBuffer)

Buffer handling must account for end-of-buffer status, record versions, and dropped records. cuptiActivityFlushAll does not implicitly synchronize CUDA work; the application must complete the necessary work first when complete GPU timestamps are required. 3. PyTorch allocation paths

Caching and cudaMalloc

The native caching allocator first searches for reusable blocks. When the ordinary path needs more memory, it obtains an allocation through cudaMalloc and assigns a block to the Tensor. Deleting a Tensor typically leaves an idle block in the pool; cudaFree appears when resources are returned to CUDA. Consequently, neither torch.empty nor del tensor implies a one-to-one CUDA allocation or free. cudaMalloc path; Release cached allocation

memory_allocated() measures allocator-accounted live allocations such as Tensor storage, while memory_reserved() measures memory managed by the allocator. Neither is a complete inventory of all CUDA resources in the process: context memory, library allocations, and other allocators may be outside that accounting. empty_cache() returns eligible idle cached memory; it cannot free storage still owned by live Tensors. PyTorch memory management

Expandable segments and VMM

backend:native,expandable_segments:True retains the native allocator and changes how it obtains memory from CUDA. It reserves a contiguous virtual range, then creates physical allocations and maps them as needed. The mapped coverage can grow, while cache reuse remains part of the path. Keep three quantities separate: cuMemAddressReserve size is virtual address space; cuMemCreate size is physical allocation; PyTorch memory_reserved is allocator memory accounting, not the entire reserved VA range. CU_MEM_ALLOCATION_TYPE_PINNED with a DEVICE location describes device physical memory here, not the page-locked CPU batches in DataLoader pin_memory.

The pinned PyTorch version uses 20 MiB chunks for its large pool and 2 MiB chunks for its small pool. These are allocator granularities, not GPU hardware page sizes. A fresh large pool serving a 64 MiB request can create four 20 MiB handles, giving 80 MiB of mapped backing. Its VA reservation can be much larger. Allocator segment size; ExpandableSegment: reserve

The tracer

Python explicitly loads the library through ctypes, starts tracing before its first CUDA initialization, marks each phase, and stops tracing at the end. CUPTI subscribes to domains and CBIDs, so PyTorch’s calls through driver function pointers do not depend on ELF symbol interposition.

Each completed API record contains a phase, PID / TID, domain, CBID, correlation ID, context UID, name, timestamps, result, and memory fields. Failed calls retain request bytes but never dereference undefined output addresses or handles. cudaFree and cuMemRelease have no size argument, so their bytes field is empty.

bool active = false;
bool io_failed = false;

struct Fields {
    uint64_t bytes = 0, address = 0, handle = 0, offset = 0;
    bool has_bytes = false, has_address = false, has_handle = false;
    bool has_offset = false;
};

// Decode inputs at EXIT. Read output pointers ONLY after successful return.
Fields decode(CUpti_CallbackDomain domain, CUpti_CallbackId id,
              const void* params, bool success) {
    Fields f;
    if (domain == CUPTI_CB_DOMAIN_RUNTIME_API) {
        if (id == CUPTI_RUNTIME_TRACE_CBID_cudaMalloc_v3020) {
            const auto* p = static_cast<const cudaMalloc_v3020_params*>(params);
            f.bytes = p->size; f.has_bytes = true;
            if (success && p->devPtr) {
                f.address = reinterpret_cast<uintptr_t>(*p->devPtr);
                f.has_address = true;
            }
        } else if (id == CUPTI_RUNTIME_TRACE_CBID_cudaFree_v3020) {
            const auto* p = static_cast<const cudaFree_v3020_params*>(params);
            f.address = reinterpret_cast<uintptr_t>(p->devPtr);
            f.has_address = true;
        }
        return f;
    }
    switch (id) {
    case CUPTI_DRIVER_TRACE_CBID_cuMemAddressReserve: {
        const auto* p = static_cast<const cuMemAddressReserve_params*>(params);
        f.bytes = p->size; f.has_bytes = true;
        if (success && p->ptr) { f.address = *p->ptr; f.has_address = true; }
        break;
    }
    case CUPTI_DRIVER_TRACE_CBID_cuMemAddressFree: {
        const auto* p = static_cast<const cuMemAddressFree_params*>(params);
        f.bytes = p->size; f.address = p->ptr;
        f.has_bytes = f.has_address = true;
        break;
    }
    case CUPTI_DRIVER_TRACE_CBID_cuMemCreate: {
        const auto* p = static_cast<const cuMemCreate_params*>(params);
        f.bytes = p->size; f.has_bytes = true;
        if (success && p->handle) { f.handle = *p->handle; f.has_handle = true; }
        break;
    }
    case CUPTI_DRIVER_TRACE_CBID_cuMemRelease: {
        const auto* p = static_cast<const cuMemRelease_params*>(params);
        f.handle = p->handle; f.has_handle = true;
        break;
    }
    case CUPTI_DRIVER_TRACE_CBID_cuMemMap: {
        const auto* p = static_cast<const cuMemMap_params*>(params);
        f.address = p->ptr; f.bytes = p->size; f.handle = p->handle;
        f.offset = p->offset;
        f.has_address = f.has_bytes = f.has_handle = f.has_offset = true;
        break;
    }
    case CUPTI_DRIVER_TRACE_CBID_cuMemUnmap: {
        const auto* p = static_cast<const cuMemUnmap_params*>(params);
        f.address = p->ptr; f.bytes = p->size;
        f.has_address = f.has_bytes = true;
        break;
    }
    case CUPTI_DRIVER_TRACE_CBID_cuMemSetAccess: {
        const auto* p = static_cast<const cuMemSetAccess_params*>(params);
        f.address = p->ptr; f.bytes = p->size;
        f.has_address = f.has_bytes = true;
        break;
    }
    default: break;
    }
    return f;
}

uint64_t timestamp() {
    uint64_t value = 0;
    // A zero timestamp is retained as missing data, never a valid duration.
    if (cuptiGetTimestamp(&value) != CUPTI_SUCCESS) return 0;
    return value;
}

void CUPTIAPI callback(void*, CUpti_CallbackDomain domain,
                       CUpti_CallbackId id, const void* data) {
    if (domain != CUPTI_CB_DOMAIN_RUNTIME_API &&
        domain != CUPTI_CB_DOMAIN_DRIVER_API) return;
    const auto* info = static_cast<const CUpti_CallbackData*>(data);
    if (info->callbackSite == CUPTI_API_ENTER) {
        *info->correlationData = timestamp();
        return;
    }
    if (info->callbackSite != CUPTI_API_EXIT) return;
    const uint64_t end = timestamp();
    const uint64_t start = *info->correlationData;
    const int result = domain == CUPTI_CB_DOMAIN_RUNTIME_API
        ? static_cast<int>(*static_cast<const cudaError_t*>(info->functionReturnValue))
        : static_cast<int>(*static_cast<const CUresult*>(info->functionReturnValue));
    const Fields f = decode(domain, id, info->functionParams, result == 0);
    char bytes[32] = "", address[32] = "", handle[32] = "", offset[32] = "";
    if (f.has_bytes) std::snprintf(bytes, sizeof(bytes), "%" PRIu64, f.bytes);
    if (f.has_address) std::snprintf(address, sizeof(address), "0x%" PRIx64, f.address);
    if (f.has_handle) std::snprintf(handle, sizeof(handle), "0x%" PRIx64, f.handle);
    if (f.has_offset) std::snprintf(offset, sizeof(offset), "%" PRIu64, f.offset);
    std::lock_guard<std::mutex> lock(output_mutex);
    if (!output) return;
    const int written = std::fprintf(output,
        "api,%s,%ld,%ld,%s,%u,%u,%u,%s,%" PRIu64 ",%" PRIu64 ",%d,%s,%s,%s,%s\n",
        phase, static_cast<long>(getpid()), static_cast<long>(syscall(SYS_gettid)),
        domain == CUPTI_CB_DOMAIN_RUNTIME_API ? "runtime" : "driver",
        static_cast<unsigned>(id), info->correlationId, info->contextUid,
        info->functionName, start, end, result, bytes, address, handle, offset);
    if (written < 0) io_failed = true;
}

bool check(CUptiResult result, const char* operation) {
    if (result == CUPTI_SUCCESS) return true;
    const char* message = "unknown CUPTI error";
    cuptiGetResultString(result, &message);
    std::fprintf(stderr, "%s: %s (%d)\n", operation, message, static_cast<int>(result));
    return false;
}
}  // namespace

// Call start/mark/stop serially from the controlling Python thread.
// Before stop, all application threads must have left traced CUDA API calls.
extern "C" int trace_start(const char* path) {
    if (active || output || !path) return -1;
    output = std::fopen(path, "w");
    if (!output) { std::perror("open trace"); return -1; }
    io_failed = false;
    std::snprintf(phase, sizeof(phase), "INIT");
    std::fprintf(output, "kind,phase,pid,tid,domain,cbid,correlation_id,context_uid,api,start_ns,end_ns,result,bytes,address,handle,offset\n");
    if (!check(cuptiSubscribe(&subscriber, callback, nullptr), "cuptiSubscribe")) {
        std::fclose(output); output = nullptr; return -1;
    }
    active = true;
    struct Selection { CUpti_CallbackDomain domain; CUpti_CallbackId id; };
    const Selection selection[] = {
        {CUPTI_CB_DOMAIN_RUNTIME_API, CUPTI_RUNTIME_TRACE_CBID_cudaMalloc_v3020},
        {CUPTI_CB_DOMAIN_RUNTIME_API, CUPTI_RUNTIME_TRACE_CBID_cudaFree_v3020},
        {CUPTI_CB_DOMAIN_DRIVER_API, CUPTI_DRIVER_TRACE_CBID_cuMemAddressReserve},
        {CUPTI_CB_DOMAIN_DRIVER_API, CUPTI_DRIVER_TRACE_CBID_cuMemAddressFree},
        {CUPTI_CB_DOMAIN_DRIVER_API, CUPTI_DRIVER_TRACE_CBID_cuMemCreate},
        {CUPTI_CB_DOMAIN_DRIVER_API, CUPTI_DRIVER_TRACE_CBID_cuMemRelease},
        {CUPTI_CB_DOMAIN_DRIVER_API, CUPTI_DRIVER_TRACE_CBID_cuMemMap},
        {CUPTI_CB_DOMAIN_DRIVER_API, CUPTI_DRIVER_TRACE_CBID_cuMemUnmap},
        {CUPTI_CB_DOMAIN_DRIVER_API, CUPTI_DRIVER_TRACE_CBID_cuMemSetAccess},
    };
    for (const auto& item : selection) {
        if (!check(cuptiEnableCallback(1, subscriber, item.domain, item.id), "cuptiEnableCallback")) {
            if (check(cuptiUnsubscribe(subscriber), "cuptiUnsubscribe")) {
                active = false; std::fclose(output); output = nullptr;
            }
            return -1;
        }
    }
    return 0;
}

extern "C" int trace_mark(const char* name) {
    if (!active || !name || std::strlen(name) >= sizeof(phase)) return -1;
    // Keep CSV fields unquoted by restricting phase labels to safe characters.
    for (const char* p = name; *p; ++p) {
        if (!((*p >= 'A' && *p <= 'Z') || (*p >= '0' && *p <= '9') || *p == '_')) return -1;
    }
    const uint64_t now = timestamp();
    std::lock_guard<std::mutex> lock(output_mutex);
    std::snprintf(phase, sizeof(phase), "%s", name);
    if (std::fprintf(output, "phase,%s,%ld,%ld,host,,,,mark,%" PRIu64 ",%" PRIu64 ",0,,,,\n",
        phase, static_cast<long>(getpid()), static_cast<long>(syscall(SYS_gettid)), now, now) < 0) io_failed = true;
    return io_failed ? -1 : 0;
}

extern "C" int trace_stop() {
    if (!active) return -1;
    if (!check(cuptiUnsubscribe(subscriber), "cuptiUnsubscribe")) return -1;
    active = false;
    std::lock_guard<std::mutex> lock(output_mutex);
    const bool failed = io_failed || std::ferror(output);
    const int closed = std::fclose(output); output = nullptr;
    return failed || closed != 0 ? -1 : 0;
}

This is a synchronous teaching logger. A mutex keeps CSV rows intact; both callbacks and writes add overhead. A production collector would typically copy scalar fields into preallocated queues for a background writer. The global phase is appropriate only for this controlled program. Multithreaded services need per-thread or explicit operation IDs, rather than treating the phase as attribution to a Python operator.

Allocation, reuse, and release

The workload allocates a 64 MiB A, deletes it, then requests an equally sized B to inspect reuse. While B remains live, it allocates a 96 MiB C to grow the pool. It deletes B and C before empty_cache. All tensors use torch.empty, with no initialization or H2D, isolating allocator behavior. Each phase reports PyTorch memory statistics and the relevant addresses.

"""Controlled PyTorch allocation phases. Run each allocator mode in a fresh process."""
import argparse
import ctypes
import gc
import json
import os
from pathlib import Path


def main():
    parser = argparse.ArgumentParser()
    parser.add_argument("--library", required=True, type=Path)
    parser.add_argument("--trace", required=True, type=Path)
    args = parser.parse_args()
    # Importing torch does not intentionally create CUDA tensors in this script.
    # Set PYTORCH_CUDA_ALLOC_CONF in the launch command, before this import.
    import torch

    if torch.version.cuda is None:
        raise SystemExit("Install a CUDA-enabled PyTorch build; this is a CPU-only build.")
    tracer = ctypes.CDLL(str(args.library.resolve()))
    tracer.trace_start.argtypes = [ctypes.c_char_p]
    tracer.trace_mark.argtypes = [ctypes.c_char_p]
    tracer.trace_stop.argtypes = []
    for name in ("trace_start", "trace_mark", "trace_stop"):
        getattr(tracer, name).restype = ctypes.c_int

    def mark(name):
        if tracer.trace_mark(name.encode()) != 0:
            raise RuntimeError("Could not write trace phase " + name)

    def snapshot(name, **pointers):
        print(json.dumps({"phase": name,
            "allocated": torch.cuda.memory_allocated(),
            "reserved": torch.cuda.memory_reserved(), **pointers}), flush=True)

    args.trace.parent.mkdir(parents=True, exist_ok=True)
    if tracer.trace_start(os.fsencode(args.trace)) != 0:
        raise SystemExit("CUPTI subscription failed; inspect the error above.")
    try:
        mark("INIT")
        torch.cuda.init()
        torch.cuda.synchronize()
        torch.cuda.empty_cache()
        print(json.dumps({"torch": torch.__version__, "cuda_build": torch.version.cuda,
            "allocator_config": os.environ.get("PYTORCH_CUDA_ALLOC_CONF", ""),
            "backend": torch.cuda.memory.get_allocator_backend()}), flush=True)
        snapshot("INIT")

        mark("ALLOC_A")
        a = torch.empty(16 * 1024 * 1024, dtype=torch.float32, device="cuda")  # 64 MiB
        original = a.data_ptr()
        snapshot("ALLOC_A", a=hex(original))

        mark("DROP_A")
        del a
        gc.collect()
        snapshot("DROP_A")

        mark("REUSE_B")
        b = torch.empty(16 * 1024 * 1024, dtype=torch.float32, device="cuda")
        snapshot("REUSE_B", b=hex(b.data_ptr()), reused=(b.data_ptr() == original))

        mark("GROW_C")
        c = torch.empty(24 * 1024 * 1024, dtype=torch.float32, device="cuda")  # 96 MiB
        snapshot("GROW_C", c=hex(c.data_ptr()))

        mark("DROP_ALL")
        del b, c
        gc.collect()
        torch.cuda.synchronize()
        snapshot("DROP_ALL")

        mark("EMPTY_CACHE")
        torch.cuda.empty_cache()
        snapshot("EMPTY_CACHE")
        torch.cuda.synchronize()
    finally:
        # No application worker threads issue CUDA calls in this example.
        # Unsubscribe before ctypes can unload the library at process exit.
        if tracer.trace_stop() != 0:
            raise RuntimeError("Trace shutdown or file write failed")


if __name__ == "__main__":
    main()

The PyTorch 2.8 expandable path may try one handle type, then fall back if unsupported. A failed cuMemCreate followed by a successful retry is not two allocations. Return status determines whether a resource was established. ExpandableSegment: create

Addresses, handles, and counts

For the ordinary path, match successful cudaMalloc address → size records to cudaFree. For VMM, separately track VA ranges, handle → size, and (VA interval, handle, offset) mappings. Both addresses and handles can be reused, so maintain lifetimes in event order rather than treating a hexadecimal value as a permanent object ID.

The same 80 MiB backing can generate 80 MiB of create records and 80 MiB of map records. Adding them into a 160 MiB physical total is incorrect. Large reservation sizes must also stay out of physical accounting. General VMM applications may share handles, create multiple mappings, or retain cross-process references; one cuMemRelease does not independently prove physical reclamation.

The summarizer groups by phase / domain / API, reporting successful calls, failures, and that API’s own byte sum. It does not output a cross-API memory total or treat the missing Free / Release size as zero-byte release. A memory-usage curve needs additional lifetime matching and mapping state, plus a definition of whether it measures live Tensors, allocator backing, or VA reservations.

Complete summarizer
"""Summarize API events without adding VA reservation bytes to allocation bytes."""
import argparse
import csv
from collections import Counter


def summarize(path):
    with open(path, newline="") as stream:
        rows = list(csv.DictReader(stream))
    if not rows:
        raise ValueError("Empty trace: check subscription, workload, and output path")
    phases = list(dict.fromkeys(row["phase"] for row in rows))
    counts = Counter()
    failed = Counter()
    byte_totals = Counter()
    for row in rows:
        if row["kind"] != "api":
            continue
        key = (row["phase"], row["domain"], row["api"])
        if int(row["result"]) != 0:
            failed[key] += 1
            continue
        counts[key] += 1
        if row["bytes"]:
            byte_totals[key] += int(row["bytes"])
    print(f"{'phase':<14} {'domain':<8} {'API':<24} {'ok':>4} {'failed':>6} {'sum(bytes), MiB':>16}")
    for phase in phases:
        keys = sorted(key for key in counts.keys() | failed.keys() if key[0] == phase)
        if not keys:
            print(f"{phase:<14} (no selected API calls)")
        for key in keys:
            total = f"{byte_totals[key] / 2**20:.2f}" if key in byte_totals else "-"
            print(f"{key[0]:<14} {key[1]:<8} {key[2]:<24} {counts[key]:>4} {failed[key]:>6} {total:>16}")
    print("\nBytes are summed separately per API, not live memory or a cross-API total.")
    print("Reserve = VA range; Create = physical allocation; Map = mapping extent.")
    print("Release/Free can omit a size; recover it from the successful creation record.")
    if not counts:
        raise ValueError("No successful selected API calls: this is not evidence of zero allocation")


if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("trace")
    summarize(parser.parse_args().trace)
