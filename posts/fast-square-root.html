快速平方根与逆平方根近似

把向量 (3, 4) 归一化，需要将两个分量都乘以 1/√25 = 0.2。这个公共因子可以由浮点位模式估计，再用乘法修正。Quake III 公开源码中的 Q_rsqrt 就采用这条路径：一次整数右移、一次减法生成初值，随后执行一次牛顿迭代。Q_rsqrt · 向量归一化中的调用

用输入 x = 25 可以逐步核算初值和迭代结果，再将逆平方根乘以输入，得到平方根近似。实现、位模式演示和误差测量程序均采用 IEEE 754 的 32 位二进制浮点格式。

1. 平方根与归一化

平方根和逆平方根对应两个计算目标：

\[s=\sqrt{x},\qquad y=\frac{1}{\sqrt{x}},\qquad s=xy\quad(x>0).\]

对于向量归一化，先求平方长度，再求它的逆平方根，各分量就能复用同一个缩放因子。以 (3, 4) 为例，平方长度为 25；因子为 0.2，输出为 (0.6, 0.8)。如果任务需要长度本身，则还要计算 25 × 0.2 = 5。

直接求平方根也可以使用牛顿法。对方程 \(s^2-x=0\) 求根，更新式为：

\[s_{n+1}=\frac12\left(s_n+\frac{x}{s_n}\right).\]

取 x = 25、s₀ = 6，前两次更新分别得到约 5.083333 和 5.000683。每轮包含一次除法。经典快速逆平方根选择另一个求根方程，用乘法和加减法完成修正。位级初值先将估计带到真值附近，再由一两轮迭代缩小误差。

2. 浮点编码与位级初值

2.1 浮点数的整数位模式

一个 32 位浮点数包含 1 位符号、8 位指数字段和 23 位小数字段。对正的正规数，符号位为零，数值与字段之间满足：

\[x=(1+m)2^{E-127},\qquad m=\frac{M}{2^{23}},\quad 1\le E\le254.\]

这里 \(E\) 是存储的带偏置指数字段，\(M\) 是 23 位小数字段对应的整数；实际指数为 \(E-127\)。最高有效位的 1 隐含在正规数的编码规则中。32 位浮点格式

25 的十六进制位模式为 0x41c80000，其中 E = 131、M = 0x480000，所以 m = 0.5625，数值为 1.5625 × 2⁴。把相同的 32 位按无符号整数解释，得到整数 \(I\)：

\[I=2^{23}E+M=2^{23}(E+m).\]

整数 \(I\) 同时包含指数和小数部分。程序在这个整数上做右移和减法，再把结果的位模式解释为浮点数，便得到逆平方根的初值。现代 C++ 可用 std::bit_cast 完成这两次对象表示转换。C++20 bit_cast

2.2 逆平方根的对数线性近似

开平方在对数域中对应乘以二分之一，取倒数对应变号。浮点位模式可用来近似对数，因此这两种操作可以合成一次整数变换。

\[\log_2x=E-127+\log_2(1+m).\]

在 \(0\le m<1\) 内，用直线 \(m+\sigma\) 近似 \(\log_2(1+m)\)。\(\sigma\) 用来调整这条直线的位置。令 \(L=2^{23}\)，则：

\[\log_2x\approx\frac{I}{L}-127+\sigma.\]

设逆平方根初值的整数位模式为 \(J\)。对输入和输出使用同一近似，并代入 \(\log_2y=-\tfrac12\log_2x\)，得到：

\[\frac{J}{L}-127+\sigma\approx-\frac12\left(\frac{I}{L}-127+\sigma\right),\qquad J\approx\frac32L(127-\sigma)-\frac12I.\]

由此得到整数表达式 J = R - (I >> 1)。右移一位实现无符号整数除以二并向下取整，常量 \(R\) 则合并指数偏置和直线修正。取 \(\sigma=0\) 时，常量为 0x5f400000；Quake III 采用的 0x5f3759df 对应 \(\sigma\approx0.0450466\)。直线近似给出了常量的形式，具体数值还取决于所选的误差目标。所采用的常量

代入 x = 25，整数运算为：

I       = 0x41c80000
I >> 1  = 0x20e40000
R       = 0x5f3759df
J       = 0x3e5359df

将 J 按浮点位模式解释，得到初值约 0.2063975，已经接近目标 0.2。下一步利用方程本身修正这个估计。

3. 牛顿迭代与误差收敛

选择 \(f(y)=y^{-2}-x\)，它在正数范围内的根就是 \(1/\sqrt{x}\)。将导数 \(f'(y)=-2y^{-3}\) 代入牛顿更新式，并消去分式：

\[y_{n+1}=y_n-\frac{y_n^{-2}-x}{-2y_n^{-3}}=y_n\left(\frac32-\frac12xy_n^2\right).\]

当估计略大于真值时，\(xy_n^2\) 大于 1，括号中的修正系数使估计减小。每次更新会消去误差的一阶项。令 \(y_n=(1+\varepsilon_n)/\sqrt{x}\)，在实数运算下可得：

\[\varepsilon_{n+1}=-\frac32\varepsilon_n^2-\frac12\varepsilon_n^3.\]

当误差较小时，下一轮误差主要由平方项决定。约 3% 的初值误差经过一轮可降至千分量级，再一轮降至百万分量级；32 位浮点运算还会叠加各步的舍入误差。x = 25 的实际结果如下。

6. 现代硬件上的平方根路径

位级初值利用数值表示取得估计，再用方程修正。现代处理器也提供平方根或逆平方根指令，工程实现可以依据指令规定的精度和舍入规则选择计算路径。

以 CUDA 13.1.1 对应的 PTX ISA 9.1 为例，rsqrt.approx.f32 在默认次正规数处理模式下，对正有限输入给出的最大相对误差为 \(2^{-22.9}\)。sqrt.rn.f32 则给出最近值、平局取偶数的平方根舍入语义。指令名称中的 approx 和 rn 明确区分了这两类契约。逆平方根指令 · 平方根指令

计算路径取决于输出要求。归一化直接使用逆平方根；需要正确舍入的平方根时，选择具有相应语义的库函数或指令；允许近似误差的融合计算，则同时检查允许的误差和生成的机器码。x * rsqrt.approx(x) 还包含最后一次乘法舍入，评估结果误差时应将它计入。

Fast square roots and reciprocal square roots

Normalizing the vector (3, 4) means multiplying both components by 1/√25 = 0.2. Floating-point bits can provide an estimate of this shared factor, and multiplication can refine it. The classic Q_rsqrt implementation in the public Quake III source follows that sequence: one integer shift and subtraction produce the seed, followed by one Newton iteration. Q_rsqrt · Vector normalization call site

This article follows x = 25 through the seed and refinement, then multiplies the reciprocal square root by the input to approximate the square root. The implementation uses IEEE 754 binary32, with a bit-pattern explorer and a runnable accuracy measurement program.

1. Square roots and normalization

A square root and a reciprocal square root serve different computational purposes:

\[s=\sqrt{x},\qquad y=\frac{1}{\sqrt{x}},\qquad s=xy\quad(x>0).\]

For vector normalization, compute the squared length and its reciprocal square root, then reuse that factor for each component. The squared length of (3, 4) is 25. Multiplying by 0.2 gives (0.6, 0.8). To recover the length itself, compute 25 × 0.2 = 5.

Newton iteration can compute the square root directly. Applying it to \(s^2-x=0\) gives:

\[s_{n+1}=\frac12\left(s_n+\frac{x}{s_n}\right).\]

With x = 25 and s₀ = 6, the first two updates produce approximately 5.083333 and 5.000683. Each iteration includes a division. Fast reciprocal square root uses a different equation whose update simplifies to multiplication and addition or subtraction. The bit-level seed is close enough for one or two updates to reduce the error.

2. Floating-point encoding and the seed

2.1 Reading the same bits as an integer

A binary32 value has one sign bit, eight exponent bits, and 23 fraction bits. For a positive normal number, the sign is zero and:

\[x=(1+m)2^{E-127},\qquad m=\frac{M}{2^{23}},\quad 1\le E\le254.\]

Here \(E\) is the stored, biased exponent field and \(M\) is the integer represented by the fraction field. The actual exponent is \(E-127\), and the leading significand bit is implicit in the normal-number encoding. Binary32 format

The bits of 25 are 0x41c80000: E = 131 and M = 0x480000. Thus m = 0.5625, giving 1.5625 × 2⁴. Interpreting those same bits as an unsigned integer produces \(I\):

\[I=2^{23}E+M=2^{23}(E+m).\]

The integer contains both the exponent and the fraction. Shifting and subtracting it, then interpreting the resulting bits as a float, produces a reciprocal-square-root seed. C++20 provides std::bit_cast to convert between these object representations. C++20 bit_cast

2.2 A linear transformation in logarithmic space

Taking a square root halves a logarithm; taking a reciprocal changes its sign. Floating-point encoding lets us approximate that logarithm and combine the two operations in one integer transformation.

\[\log_2x=E-127+\log_2(1+m).\]

For \(0\le m<1\), approximate \(\log_2(1+m)\) with the line \(m+\sigma\). The offset \(\sigma\) adjusts its position. Writing \(L=2^{23}\) gives:

\[\log_2x\approx\frac{I}{L}-127+\sigma.\]

Let \(J\) be the integer bits of the reciprocal-square-root seed. Applying the same approximation to the input and output, with \(\log_2y=-\tfrac12\log_2x\), yields:

\[\frac{J}{L}-127+\sigma\approx-\frac12\left(\frac{I}{L}-127+\sigma\right),\qquad J\approx\frac32L(127-\sigma)-\frac12I.\]

This explains the form J = R - (I >> 1). The shift divides the unsigned integer by two, rounding down; \(R\) absorbs the exponent bias and line offset. Setting \(\sigma=0\) gives 0x5f400000. The Quake III constant 0x5f3759df corresponds to \(\sigma\approx0.0450466\). The linear approximation explains the family of constants; the specific choice also depends on the error objective. The chosen constant

I       = 0x41c80000

R       = 0x5f3759df
J       = 0x3e5359df

Interpreting J as a float produces approximately 0.2063975, already close to the target 0.2. A Newton iteration refines that estimate.

3. Newton iteration and error reduction

Choose \(f(y)=y^{-2}-x\), whose positive root is \(1/\sqrt{x}\). Using its derivative \(f'(y)=-2y^{-3}\), the Newton update simplifies to:

\[y_{n+1}=y_n-\frac{y_n^{-2}-x}{-2y_n^{-3}}=y_n\left(\frac32-\frac12xy_n^2\right).\]

When the estimate is too large, \(xy_n^2\) exceeds 1, and the correction factor reduces it. Near the root, the update cancels the first-order error. Substituting \(y_n=(1+\varepsilon_n)/\sqrt{x}\) gives, in real arithmetic:

\[\varepsilon_{n+1}=-\frac32\varepsilon_n^2-\frac12\varepsilon_n^3.\]

The squared term dominates once the error is small. An initial error of roughly 3% can fall to a few parts per thousand after one update and a few parts per million after another. Binary32 arithmetic adds rounding at each operation. The measured results for x = 25 are:

4. Implementation and intermediate ranges

The following C++20 implementation comes from the accompanying verification program. Its entry points require finite, positive normal inputs, retain the 0x5f3759df seed, and allow zero to two refinement steps.

std::bit_cast<std::uint32_t> preserves the input bits; integer arithmetic constructs the seed, and std::bit_cast<float> interprets it. An ordinary numeric conversion would turn 25 into the integer 25, which has a different meaning from the encoding \(I\). The historical code accesses the float through long*. Fixed-width integers and bit_cast make the representation conversion explicit in this implementation. Object-representation conversion · C++ object access rules

Multiplication order affects floating-point behavior too. The implementation first computes x * y and 0.5f * y, then multiplies them. Since \(y\approx1/\sqrt{x}\), the first intermediate is approximately \(\sqrt{x}\), and their product is approximately one half. This multiplication order keeps the intermediate values within the normal range for the supported inputs.

Computing 0.5f * x first produces the subnormal intermediate \(2^{-127}\) at the smallest normal input, \(x=2^{-126}\). Gradual underflow represents that value exactly. Flushing subnormals to zero changes it to zero and changes the correction. On x86, the verification program saves the floating-point control register, temporarily changes its mode for this comparison, and restores the original setting afterward.

An interface that also accepts zero, negative inputs, infinities, and NaNs needs separate handling according to the intended mathematical semantics. Subnormal inputs also need scaling or a dedicated path. The input checks enforce the domain of these functions.

A fused multiply-add evaluates its product and sum with one rounding, which can change the final bits. This build disables contraction and aggressive floating-point reassociation so the code, browser explorer, and tables follow the same arithmetic steps.

6. Square-root paths on modern hardware

The bit-level seed illustrates a general method: estimate a value from its representation, then refine it using the equation. Modern processors also expose square-root or reciprocal-square-root instructions with numerical contracts that an implementation can use directly.

In PTX ISA 9.1, archived with CUDA 13.1.1, rsqrt.approx.f32 specifies a maximum relative error of \(2^{-22.9}\) for positive finite inputs with default subnormal handling. sqrt.rn.f32 specifies square-root rounding to nearest, ties to even. The approx and rn modifiers identify these different contracts. Reciprocal square root · Square root

The required output guides the choice. Normalization consumes a reciprocal square root directly. A correctly rounded square root requires a library function or instruction with that contract. Approximate fused computations need both an error budget and inspection of the generated machine code. Computing x * rsqrt.approx(x) adds a final multiplication rounding and has its own error path.
