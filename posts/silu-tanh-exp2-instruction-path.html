SiLU 的 tanh 与 exp2 实现：指令依赖与验证方法

SiLU 常出现在 MLP 的逐元素 activation 或 fused epilogue 中。融合消除中间访存以后，activation 的特殊函数和串行依赖可能进入 kernel 的关键路径，此时两种数学等价的公式会产生不同的指令序列。Sigmoid 形式通常包含 ex2 与 reciprocal/divide，tanh 恒等式则用 FMUL/FFMA 完成缩放和仿射变换。两条路径的比较需要同时考察 SASS、数值误差和 kernel duration。

1. 数学等价关系

SiLU 是将输入 \(x\) 与其 sigmoid 门值相乘的逐元素 activation：

\[ \mathrm{silu}(x)=x\sigma(x),\qquad \sigma(x)=\frac{1}{1+e^{-x}} \]

在近似数学路径中，指数可以改写成 base-2 exponential。PTX ISA 12.6.3 定义了 ex2.approx.f32，所以 sigmoid 可以写成：

sigmoid / exp2

\[ \sigma(x)=\frac{1}{1+2^{-x\log_2 e}} \]

tanh identity

\[ \sigma(x)=\frac{1+\tanh(x/2)}{2} \]

两个公式在实数域等价，因而定义同一个函数。编译到 GPU 后，exp2 形式沿 ex2、加一和 reciprocal/divide 形成依赖链；tanh 形式则在 tanh 前后加入普通浮点缩放与乘加。优化比较的对象正是这两条指令路径。

2. 指令路径

由公式可以先得到概念依赖图，再用编译产物确认具体 lowering。编译器可能合并乘加、选择 reciprocal 近似序列、调用 libdevice，或针对 packed dtype 采用另一套实现，因此下表描述依赖结构而非固定的 SASS 指令数。

写法 概念上的 lowering special path 普通 FP 指令 主要代价
\(x/(1+e^{-x})\) FMUL 计算 \(-x\log_2e\),
MUFU.EX2,
FADD 加 1,
RCP 或 divide sequence,
FMUL 乘回 \(x\)		 EX2 + reciprocal/divide scale、add、output multiply 倒数或除法拉长依赖链
\(x(1+\tanh(x/2))/2\) FMUL 计算 \(x/2\),
MUFU.TANH,
FFMA 计算 \(0.5t+0.5\),
FMUL 乘回 \(x\)		 TANH input scale、affine transform、output multiply 避开 reciprocal/divide

下面是用于对照依赖链的伪代码，*_approx 不是 CUDA C++ API 名称：

// sigmoid / exp2 style (pseudocode)
float t = -1.4426950408889634f * x;
float e = ex2_approx(t);
float y = x * rcp_approx(1.0f + e);

// tanh identity style
float h = 0.5f * x;
float s = fmaf(0.5f, tanh_approx(h), 0.5f);
float y = x * s;

3. 性能模型

CUDA Best Practices Guide 12.6.3 的 native arithmetic throughput 表按 compute capability 列出普通 FP32 算术和若干 approximate special-function 操作的吞吐上限。对 SiLU 而言，可检验的性能假设是：tanh 恒等式用普通浮点乘加替代 sigmoid 路径中的 reciprocal/divide，从而缩短串行依赖链。最终收益取决于整条 kernel 的瓶颈，而不是单条特殊函数指令的纸面吞吐。

PTX 文档为 tanh.approx.f32 与 ex2.approx.f32 规定语义、精度和目标架构要求；具体 latency、issue throughput 和调度行为由目标 GPU 与编译结果共同决定。因此，比较应围绕完整依赖链展开：exp2 路径包含后续倒数或除法，tanh 路径包含缩放与乘加。

Dtype 还会改变 lowering。PTX 支持 tanh.approx.f16、tanh.approx.f16x2、tanh.approx.bf16 和 tanh.approx.bf16x2，其中 bf16/bf16x2 具有更高的目标架构要求。Half2 或 bf16x2 kernel 的分析需要确认编译器是否生成了对应的 packed instruction，随后再按实际指令序列计算依赖成本。

4. 编译产物与验证

一项完整的实现比较需要同时覆盖生成代码、编译条件、数值行为和端到端计时：

  • 用 cuobjdump --dump-sass 或 nvdisasm 看 cubin,确认最终是 MUFU.EX2、MUFU.TANH、RCP、FFMA,还是 libdevice 调用。
  • 固定编译选项再比较，尤其是 --use_fast_math、--ftz、--prec-div。这些选项会改变除法、denormal 和 intrinsic lowering。
  • 单独测数值误差。tanh identity 和 exp2 sigmoid 在实数域等价,但近似指令、flush-to-zero 和 rounding 会让结果不再 bitwise 相同。

这组证据可以把公式层面的候选变成架构相关的结论。固定编译选项后，SASS 说明实际依赖链，误差测试给出可接受输入域，kernel duration 则衡量该局部变化是否穿透到整体性能。Tanh 恒等式的价值由这三项结果共同决定。

SiLU Implementations with tanh and exp2: Instruction Dependencies and Validation

SiLU commonly appears as an elementwise activation in an MLP or a fused epilogue. Once fusion removes intermediate memory traffic, special-function work and serial dependencies in the activation can enter the kernel's critical path. Two mathematically equivalent formulas then produce different instruction sequences: the sigmoid form typically contains ex2 and reciprocal/divide, while the tanh identity uses FMUL/FFMA for scaling and the affine transform. Comparing the paths requires SASS inspection, numerical-error measurements, and kernel timing.

1. Mathematical Equivalence

SiLU is the elementwise activation that multiplies \(x\) by its sigmoid gate:

\[ \mathrm{silu}(x)=x\sigma(x),\qquad \sigma(x)=\frac{1}{1+e^{-x}} \]

For an approximate arithmetic path, the exponential can be rewritten in base 2. PTX ISA 12.6.3 defines ex2.approx.f32, giving the following sigmoid form:

sigmoid / exp2

\[ \sigma(x)=\frac{1}{1+2^{-x\log_2 e}} \]

tanh identity

\[ \sigma(x)=\frac{1+\tanh(x/2)}{2} \]

The formulas are equivalent over the real numbers and therefore define the same function. After GPU compilation, the exp2 form creates a dependency chain through ex2, addition, and reciprocal/divide. The tanh form places ordinary floating-point scaling and multiply-add work around tanh. Those instruction paths are the objects of the optimization comparison.

2. Instruction path

The formulas first provide a conceptual dependency graph; generated code then identifies the concrete lowering. A compiler may fuse multiply-adds, choose a reciprocal approximation sequence, call libdevice, or use another implementation for packed dtypes. // sigmoid / exp2 form (pseudocode)

float e = ex2_approx(t);
float y = x * rcp_approx(1.0f + e);

// tanh identity (pseudocode)
float h = 0.5f * x;
float s = fmaf(0.5f, tanh_approx(h), 0.5f);
float y = x * s;

3. Performance Model

The CUDA Best Practices Guide 12.6.3 lists throughput limits for ordinary FP32 arithmetic and several approximate special-function operations by compute capability. For SiLU, the testable performance hypothesis is that the tanh identity replaces reciprocal/divide in the sigmoid path with ordinary floating-point multiply-add work and shortens the serial dependency chain. Any resulting speedup depends on the bottleneck of the complete kernel rather than the paper throughput of one special-function instruction.

The PTX ISA defines semantics, accuracy, and target requirements for tanh.approx.f32 and ex2.approx.f32. The target GPU and generated code determine their latency, issue throughput, and scheduling behavior. The comparison should therefore cover each complete chain: exp2 followed by reciprocal or divide, versus tanh surrounded by scaling and multiply-adds.

Dtype changes the lowering again. PTX defines scalar and packed forms including tanh.approx.f16x2 and tanh.approx.bf16x2, with architecture requirements documented by the ISA. Analysis of a half2 or bf16x2 kernel should confirm that the compiler emitted the expected packed instruction before assigning a cost to the sequence.

4. Generated Code and Validation

A complete implementation comparison covers generated code, compiler conditions, numerical behavior, and end-to-end timing:

  • Inspect SASS with cuobjdump --dump-sass or nvdisasm.
  • Compare with fixed compiler flags, especially --use_fast_math, --ftz, and --prec-div.
  • Measure numerical error separately. Approximate instructions, flush-to-zero behavior, and rounding mean the two formulas do not have to match bit for bit.

Together, these observations turn an algebraic candidate into an architecture-specific result. With compiler flags fixed, SASS identifies the realized dependency chain, error measurements establish the acceptable input domain, and kernel duration shows whether the local change reaches overall performance. Those three results determine the value of the tanh identity on the target GPU.
