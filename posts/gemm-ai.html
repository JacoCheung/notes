GEMM Arithmetic Intensity 的分块模型与适用边界

GEMM 在固定矩阵形状下执行确定数量的 FLOP，但 kernel 为这些计算搬运多少数据，取决于 tile 如何组织复用以及数据跨越哪一级存储边界。Arithmetic intensity 是某段计算量与指定边界流量的比值：HBM、L2 和 shared memory 各自对应不同的分母。单层 blocking 公式可以刻画 tile 内复用；进入多级 cache、CTA 调度和 kernel 融合后，则需要为每个边界单独建立流量模型。

除非另有说明，本文分析 $C=AB$（等价于 GEMM 中 $\beta=0$）且输入、输出元素均占 $b$ 字节；FMA 按 2 FLOPs 计。若需要读取原始 $C$，分母还要增加一次 $MN b$。

建模前提：§一、§二中的单层 blocking 假设每个输出 tile 独立取得 A、B 数据，不计算相邻输出 tile 的 cache 命中。§三改用分层 Roofline：各层 AI 由该层实际或建模流量定义，不把 L2 容量直接等同于可实现的跨 CTA 复用。

一、方阵基线（$N \times N$）

$C = A \cdot B$，三者都是 $N \times N$。总 FLOPs $= 2N^3$（每个 $C$ 元素 $N$ 次乘加）。

1. 理论下界（完美复用）

每个输入 / 输出元素只从主存进出一次，总访存 $3N^2$ 元素：

$$\text{AI}_{\text{ideal}} \;=\; \frac{2N^3}{3N^2 \cdot b} \;=\; \frac{2N}{3b}\ \text{FLOP/byte}$$

该下界随 $N$ 线性增长。它只说明在完美复用假设下，大矩阵具有较高的计算/访存比；是否越过目标 GPU 的 Roofline balance point，还需要使用同一 dtype 的峰值算力、对应存储层带宽和实测流量。

2. 完全无复用（naive 三重循环）

$C$ 在寄存器 acc 里累加，K 走完后一次写回。整个 GEMM：

  • FLOPs：$2 N^3$
  • 读 $A$：$N^3$（每个 $A[i,k]$ 跨 $j$ 重复加载 $N$ 次）
  • 读 $B$：$N^3$（每个 $B[k,j]$ 跨 $i$ 重复加载 $N$ 次）
  • 写 $C$：$N^2$（每个 $(i,j)$ 累加完写回一次）
$$\text{AI}_{\text{no-reuse}} \;=\; \frac{2 N^3}{(2 N^3 + N^2)\cdot b} \;\xrightarrow{N\to\infty}\; \frac{1}{b}\ \text{FLOP/byte}$$

写 $C$ 的 $N^2$ 项被 $2 N^3$ 压住，渐近值与 $N$ 无关。FP32 下为 $0.25$ FLOP/byte；Roofline 模型会把这种实现归到带宽受限区域，但不能据此给出某一 GPU 的实测峰值占比。

朴素三重循环伪代码：

# Naive GEMM: C = A · B, 三者均为 N×N
for i in 0..N:
    for j in 0..N:
        acc = 0
        for k in 0..N:
            acc += A[i, k] * B[k, j]      # 每次迭代 2 loads + 2 FLOPs
        C[i, j] = acc                       # C 全程留在寄存器

内层每次 FMA 都从 DRAM 拉 A[i,k] 和 B[k,j]，没有任何跨迭代复用，故 $\text{AI} = 1/b$。

3. 分块（块大小 $T \times T$，cache 零延迟）

一个 $T \times T$ 的 $C$ 块沿 $k$ 方向扫过 $N/T$ 次：

  • FLOPs: $(N/T) \cdot 2T^3 = 2NT^2$
  • 主存访问：$A$ tiles $(N/T)\cdot T^2 = NT$，$B$ tiles $NT$，$C$ 写回 $T^2$（K-loop 累加完一次）
$$\text{AI}_{\text{blocked}} \;=\; \frac{2NT^2}{(2NT + T^2)\cdot b} \;\xrightarrow{N\to\infty}\; \frac{T}{b}\ \text{FLOP/byte}$$

当 $N \gg T/2$ 时写 $C$ 可忽略，全图总访存 $\approx 2N^3/T$，正是 Hong–Kung 下界 $\Omega(N^3/\sqrt{M})$ 的具象形式。

分块 GEMM 伪代码（方形 tile，$T \times T$）：

# Blocked GEMM, 假设 3·T² 元素能同时放进 cache
for i0 in 0..N step T:              # 遍历 C 的行块
    for j0 in 0..N step T:          # 遍历 C 的列块
        C_tile = 0                       # T×T 累加器（寄存器 / shared mem）
        for k0 in 0..N step T:      # 沿 K 方向扫块
            # —— 一次性把两个输入 tile 搬进 fast storage ——
            A_tile = A[i0:i0+T, k0:k0+T]
            B_tile = B[k0:k0+T, j0:j0+T]
            # —— tile 内做稠密小 GEMM（在 cache 里，零 DRAM 访问）——
            for i in 0..T:
                for j in 0..T:
                    for k in 0..T:
                        C_tile[i, j] += A_tile[i, k] * B_tile[k, j]
        C[i0:i0+T, j0:j0+T] = C_tile     # 一次写回

每对 A_tile、B_tile 从 DRAM 加载一次后，会在 tile 内复用 $T$ 次，因此 AI 从 $1/b$ 增长到 $T/b$。

4. cache 容量约束

三个 tile 同时在 cache：$3T^2 b \le M$，故

$$T_{\max} \;=\; \sqrt{\frac{M}{3b}}, \qquad \text{AI}_{\max} \;=\; \sqrt{\frac{M}{3b^{3}}}$$

要 AI 翻倍，cache 必须变 4 倍。

二、任意形状 tile generalized

一般 GEMM：$C\,(M{\times}N)= A\,(M{\times}K)\cdot B\,(K{\times}N)$，tile 尺寸 $M_t \times N_t$（$C$ 块）、$M_t \times K_t$（$A$ 块）、$K_t \times N_t$（$B$ 块）。

1. 单个输出 tile 的流量公式

算一个 $M_t \times N_t$ 的 $C$ tile：

项量（元素）
FLOPs$2\, M_t N_t K$
读 $A$$(K/K_t)\cdot M_t K_t = M_t K$
读 $B$$(K/K_t)\cdot K_t N_t = K N_t$
写 $C$$M_t N_t$（K-loop 累加完一次写回）
$$\text{AI} \;=\; \frac{2 M_t N_t K}{\big((M_t + N_t)\,K + M_t N_t\big)\cdot b}$$

分母里 $(M_t + N_t) K$ 来自 $A$、$B$ 在 K 方向的反复加载（随 $K$ 线性增长），$M_t N_t$ 是 C tile 在累加结束后的一次写回（与 $K$ 无关）。当 $K \gg \tfrac{M_t N_t}{M_t + N_t}$ 时，写 C 可忽略，渐近退化为：

$$\boxed{\;\text{AI} \;\xrightarrow{K \to \infty}\; \frac{2 M_t N_t K}{(M_t + N_t)\, K \cdot b} \;=\; \frac{2}{b} \cdot \frac{M_t N_t}{M_t + N_t} \;=\; \frac{H(M_t, N_t)}{b}\;}$$

其中 $H(M_t, N_t) \;=\; \dfrac{2 M_t N_t}{M_t + N_t}$ 是调和平均。后续关于 tile 形状的比较使用这个渐近形式；Split-K 会把一个 C tile 的 reduction 分给多个 CTA，并引入 partial sum 的写入与规约，因此第五节分析工作分解时仍需回到完整流量。

2. 较短的 tile 边限制复用

调和平均更接近较小的输入。这里的直观解释是：$A$ 的每个元素在 tile 内最多复用 $N_t$ 次，$B$ 的每个元素最多复用 $M_t$ 次。

$M_t \times N_t$$H(M_t, N_t)$解释
$128 \times 128$128方阵基准
$256 \times 64$$102$元素个数 $\times 1$，AI 降到 80%
$512 \times 32$$60$元素个数 $\times 1$，AI 只剩 47%
$1024 \times 16$$31.5$接近 $2 N_t$
$M_t \to \infty,\; N_t$ 固定$2 N_t$极限等于短边两倍
$1 \times N_t$（GEMV）$\approx 2$常数，算力发挥不出
在这个单层模型中，GEMV、skinny GEMM 与 LLM decode 中一侧较短的 $Q\cdot K^\top$ 都受到短边复用上限约束，因此 arithmetic intensity 较低。

3. $K_t$ 在单层渐近式中消去

  • $K_t$ 只是 $K$ 循环的切片，不改变 $A$、$B$ 的复用倍数（仍是 $N_t$、$M_t$）。
  • $K_t$ 仍会改变 A/B stage 的容量、循环次数、同步频率和编译器生成的指令序列。
  • Tensor Core 指令的合法 shape、尾块处理和多 stage 缓冲会进一步限制可选值，具体约束应以目标 ISA 与 kernel 实现为准。
  • 放开“tile 间无复用”假设后，应从观测到的各层流量重新计算 AI，而不是把 $K_t$ 直接代入一个通用 cache 公式。

4. cache 预算下的最优形状

固定 $K_t$，约束 $M_t N_t + K_t (M_t + N_t) \le M/b$，最大化 $H(M_t, N_t)$：

$$\arg\max_{M_t,\,N_t} H(M_t, N_t)\ \Longrightarrow\ M_t=N_t=T,\quad T\le -K_t+\sqrt{K_t^2+M/b}$$

在这一容量约束下，$M_t$ 与 $N_t$ 越接近，调和平均越大。方形 tile 因而给出单层流量模型中的上界基线。

5. 两种退化极端：行条 / 列条 tile

当 $M_t$ 或 $N_t$ 退化到 1 时，$H(1, N) \to 2$、$H(M, 1) \to 2$，AI 都趋近 $2/b$。Berkeley slide 中 naive 情形的 $q \approx 2$ 可以用这种行条或列条 tile 解释：实现保留一维复用，另一输入则随输出位置反复加载。

$M_t = 1,\ N_t = N$（行条）：A 的第 $i$ 行加载一次、被 $N$ 次复用：

# 行条 tile: 一次扫完 C 的一整行, A 行在 cache 里被复用 N 次
for i in 0..M:
    # 把 A[i, :] (K 个元素) 搬进 fast storage, 整个 j 循环都用它
    for j in 0..N:                     # 扫 C 的整行
        acc = 0                             # C[i, j] 在寄存器
        for k in 0..K:
            acc += A[i, k] * B[k, j]        # A[i,k] 从 cache, B[k,j] 从 DRAM
        C[i, j] = acc

访存：读 A 用 $M K$（每行一次），读 B 用 $M N K$（跨 $i$ 无复用），FLOPs $2 M N K$：

$$\text{AI}_{\text{row-strip}} \;=\; \frac{2 M N K}{(M K + M N K)\, b} \;\xrightarrow{N \to \infty}\; \frac{2}{b}$$

$M_t = M,\ N_t = 1$（列条）：对称情形，B 的第 $j$ 列被 $M$ 次复用：

# 列条 tile: 一次扫完 C 的一整列, B 列在 cache 里被复用 M 次
for j in 0..N:
    # 把 B[:, j] (K 个元素) 搬进 fast storage, 整个 i 循环都用它
    for i in 0..M:                     # 扫 C 的整列
        acc = 0
        for k in 0..K:
            acc += A[i, k] * B[k, j]        # B[k,j] 从 cache, A[i,k] 从 DRAM
        C[i, j] = acc

访存对称：读 B 用 $N K$，读 A 用 $M N K$，FLOPs $2 M N K$：

$$\text{AI}_{\text{col-strip}} \;=\; \frac{2 M N K}{(N K + M N K)\, b} \;\xrightarrow{M \to \infty}\; \frac{2}{b}$$

当 $M_t$ 与 $N_t$ 都大于 1 时，tile 能同时复用 $A$ 和 $B$。方形特例回到第一节的分块 GEMM，其渐近 AI 可达到 $T/b$。

三、分层 Roofline 与跨 tile 复用

单层公式描述的是一个理想化的 tile 流量。真实 GPU 还会受到 L2 命中、CTA 执行顺序、并发 kernel 和 cache 替换策略影响。相邻输出 tile 具有复用 A 或 B panel 的机会，但 CUDA 不保证这些 tile 以能够命中 L2 的顺序执行，也不保证某个 panel 在下一次访问前仍驻留。

因此，多级分析应先为每个边界定义流量：

$$\mathrm{AI}_{\mathrm{HBM}}=\frac{2MNK}{Q_{\mathrm{HBM}}},\qquad \mathrm{AI}_{\mathrm{L2}}=\frac{2MNK}{Q_{\mathrm{L2}}},\qquad \mathrm{AI}_{\mathrm{SMEM}}=\frac{2MNK}{Q_{\mathrm{SMEM}}}.$$

$Q_x$ 可以来自明确的流量模型，也可以来自 profiler 计数器；两种来源不能混写成同一个“实际字节数”。给定各层带宽上限 $BW_x$ 与计算峰值 $P$，分层 Roofline 上界写成：

$$P_{\mathrm{bound}}=\min\!\left(P,\;BW_{\mathrm{HBM}}\,\mathrm{AI}_{\mathrm{HBM}},\;BW_{\mathrm{L2}}\,\mathrm{AI}_{\mathrm{L2}},\;BW_{\mathrm{SMEM}}\,\mathrm{AI}_{\mathrm{SMEM}}\right).$$

$K_t$ 会改变每个 stage 的 A/B 占用、stage 数、循环开销和可选调度，但不能仅凭 L2 容量推出跨 CTA 的实际复用率。尤其是 $M_oN_o$ 个输出并不会作为一个巨型 accumulator 自动驻留 L2；各 CTA 通常在寄存器中保存自己的输出 tile。要判断 $K_t$ 是否改善 HBM 流量，需要固定 kernel 与问题形状，比较生成代码、L2/HBM 计数器和执行时间。

四、流量最优与实现约束

调和平均给出了固定元素预算下的流量方向，kernel 配置还必须满足 MMA 指令 shape、寄存器分配、shared-memory layout、边界尺寸和并发度约束。方形 tile 是用于比较的流量上界，而具体实现可能选择更长或更窄的形状来匹配矩阵尺寸与硬件资源。

$M_t \times N_t$$H(M_t,N_t)$FP16 渐近 AI说明
$128 \times 128$$128$$64$ FLOP/byte方形基准
$256 \times 64$$102.4$$51.2$ FLOP/byte元素数相同，短边降低复用
$64 \times 64$$64$$32$ FLOP/byte减小 tile 也会降低单层 AI
$1 \times 128$$\approx1.98$$\approx0.99$ FLOP/byte接近 GEMV 边界

表中没有列工作集字节数，因为 accumulator 往往使用比输入更宽的数据类型；用同一个 $b$ 同时计算 A/B stage 和 accumulator 会低估寄存器或 shared-memory 占用。

五、Arithmetic Intensity 与 GEMM 工作分解

Arithmetic intensity 描述每字节对应多少计算，不描述工作如何分配给 CTA。当输出 tile 数不足、尾部不均衡或单个 tile 的 $K$ 很长时，库可以在几种分解之间选择：

分解工作分配额外成本
Data Parallel一个 CTA 负责一个输出 tile 的完整 $K$输出 tile 太少时并行度不足
Split-K多个 CTA 负责同一输出 tile 的不同 $K$ 区间部分和需要 atomic 或 workspace 规约，流量随 split count 增加
Stream-K按计算迭代而不是完整输出 tile 分配工作跨 tile 边界的部分和仍需协调；收益依赖问题形状与实现
Persistent scheduler常驻 CTA 依次领取多个 tile增加调度状态和同步开销
Raster / swizzle改变输出 tile 的访问顺序以增加 panel 的时间局部性cache 命中收益不是 CUDA 保证，需 profile 验证

Stream-K 论文给出 work-centric 分解，固定版本的 CUTLASS 则同时保留多种 scheduler。它们面向不同的并行度与负载均衡条件，选择时需要固定 dtype、layout、epilogue、GPU 与问题集合，再比较生成配置和 benchmark 结果。

$K_t$ 的合法值首先受目标 MMA 指令和尾块策略限制，随后受每个 stage 的 A/B 容量、stage 数、寄存器占用与 occupancy 约束。源码中的 tile shape 只能证明某个 kernel 能被实例化，不能证明它是目标 workload 的性能最优点。

六、串联 GEMM 的中间结果流量

前面的模型只处理一个 GEMM。对串联计算 \(P=AB\)、\(D=PC\)，新的问题是中间矩阵 \(P\) 是否需要写回 HBM。设 \(A\in\mathbb{R}^{M\times K}\)、\(B\in\mathbb{R}^{K\times N}\)、 \(C\in\mathbb{R}^{N\times L}\)，两次乘法共执行：

\[\mathrm{FLOPs}_{\mathrm{total}}=2MNK+2MNL=2MN(K+L).\]

先假设四个外部矩阵都以每元素 \(b\) 字节存储，中间矩阵以每元素 \(b_p\) 字节存储。若 \(P\) 完全留在 on-chip，理想 HBM 流量模型为：

\[\mathrm{AI}_{\mathrm{fused}} =\frac{2MN(K+L)}{(MK+KN+NL+ML)b}.\]

若两个 GEMM 分成独立 kernel，\(P\) 至少经历一次写出和一次读回：

\[\mathrm{AI}_{\mathrm{materialized}} =\frac{2MN(K+L)} {(MK+KN+NL+ML)b+2MN b_p}.\]

两者之比只是这个理想流量模型中的 AI 比值：

\[\frac{\mathrm{AI}_{\mathrm{fused}}} {\mathrm{AI}_{\mathrm{materialized}}} =1+\frac{2MN b_p}{(MK+KN+NL+ML)b}.\]

它不是 kernel speedup。融合还会改变寄存器和 shared memory 占用、occupancy、同步、epilogue 以及可选 scheduler；只要其中一项成为瓶颈，运行时间就不会按 AI 比值缩短。

中间维决定保存策略

GEMM1 的输出列维 \(N\) 同时是 GEMM2 的 reduction 维。实现通常在以下策略之间取舍：

策略中间结果主要约束
完整物化写入 HBM，再由第二个 kernel 读取多出 \(2MN b_p\) 字节，但两个 GEMM 可独立调度
on-chip 完整保存一个 CTA 保存 \(M_t\times N\) 的中间 tile寄存器和 shared memory 容量；保存精度由实现决定
沿 \(N\) 分块依次生成 \(M_t\times N_t\) 子块并消费可能重复读取其他 operand，并需要跨子块保持输出状态

容量估算必须区分存储类型。若中间 tile 以 \(b_p\) 字节保存，第二个 GEMM 的 accumulator 以 \(b_{acc}\) 字节保存，仅这两部分就需要：

\[M_tN_t b_p+M_tL_t b_{acc}\quad\text{bytes}.\]

这还没有计入 A、B、C 的 stage buffer 和运行时保留的寄存器，因此不能从架构的整块 register-file 或 shared-memory 容量直接推出一个通用的 \(N\) 上限。

Attention 只能借用流量模型

Attention 包含 softmax，不能代数化为 \((QK^\top)V\)。不过，上述模型仍能隔离“score 或 probability 矩阵是否物化”这一项。令序列长度为 \(S\)、head dimension 为 \(d\)，把 \(M=N=S\)、\(K=L=d\) 代入，并暂取 \(b_p=b\)，得到：

\[\frac{\mathrm{AI}_{\mathrm{fused}}} {\mathrm{AI}_{\mathrm{materialized}}} =1+\frac{S}{2d}.\]

该式只比较两次矩阵乘法和中间矩阵往返流量，不包含 softmax 的读写、在线归一化、mask、数值稳定处理与实际 tile 重载。FlashAttention 的完整 I/O 分析应使用其算法定义，而不能把这个比值当作端到端加速比。

七、Linear 训练中的三个 GEMM 形状

Linear 层能说明为什么“FLOPs 相同”并不等于“kernel 性能相同”。令 \(R=B\cdot S\) 为展平后的 token 数，\(I=d_{in}\)，\(O=d_{out}\)，前向为 \(Y=XW^\top\)。忽略 bias 后，前向和两项反向分别是：

阶段矩阵乘法GEMM \((M,N,K)\)reduction 维
fwd\(X[R,I]W^\top[I,O]\to Y[R,O]\)\((R,O,I)\)\(I\)
dgrad\(dY[R,O]W[O,I]\to dX[R,I]\)\((R,I,O)\)\(O\)
wgrad\(dY^\top[O,R]X[R,I]\to dW[O,I]\)\((O,I,R)\)\(R\)

三者均为 \(2RIO\) FLOPs。在“每个 operand 只从 HBM 读取或写入一次、storage dtype 相同”的下界模型中，也都涉及 \(RI+RO+IO\) 个元素。然而它们交换了输出维与 reduction 维，实际库可选的 tile、layout、split-K、epilogue 和 workspace 因而不同。

仅凭这张 shape 表不能推出固定的 fwd > dgrad > wgrad 排序，也不能断言某一项一定使用 Split-K、Stream-K 或特定 accumulator dtype。cuBLASLt 和 CUTLASS 的算法选择还依赖 GPU、数据类型、矩阵 layout、对齐、epilogue、workspace 和库版本；可靠结论来自固定环境下的算法枚举与 profile。PyTorch 与列主序 BLAS 之间的表示转换另见《PyTorch Linear 与 cuBLAS 的矩阵表示转换》。

八、模型的使用条件

  • 单层 blocking 中，方形 tile 的渐近 AI 为 \(T/b\)；任意形状由 \(H(M_t,N_t)/b\) 给出，较短边限制复用。
  • \(K_t\) 在单层渐近式中消去，但仍影响 stage 容量、指令合法性、同步频率、寄存器占用与 occupancy。
  • HBM、L2 和 shared memory 的 AI 必须分别用各自边界上的流量计算；cache 容量不等于可实现的跨 CTA 命中。
  • Split-K、Stream-K、persistent scheduler 与 raster order 是工作分解方案，没有仅由 AI 决定的通用优先级。
  • 融合 B2B GEMM 可以消除中间矩阵的 HBM 往返，但理想 AI 比值不等于实测 speedup。

GEMM Arithmetic Intensity: Blocking Models and Their Limits

A fixed GEMM shape performs a fixed number of FLOPs, while its data traffic depends on tile reuse and on the memory boundary being measured. Arithmetic intensity is the ratio of that work to traffic across a specified boundary, so HBM, L2, and shared memory each produce a different denominator. A single-level blocking model captures reuse within a tile; multi-level caches, CTA scheduling, and kernel fusion require separate traffic models for their respective boundaries.

Unless stated otherwise, the model is \(C=AB\), equivalent to \(\beta=0\) in GEMM. Inputs and outputs occupy \(b\) bytes per element, and one FMA counts as 2 FLOPs. A nonzero \(\beta\) adds an \(MN b\) read of the original \(C\).

Model boundary: Sections 1 and 2 treat each output tile as acquiring its own A and B data and do not credit cache hits between output tiles. Section 3 switches to a hierarchical Roofline model in which each intensity is defined by modeled or measured traffic at that memory boundary.

1. Square-matrix baseline

For \(N\times N\) matrices, \(C=AB\) performs \(2N^3\) FLOPs because each output element requires \(N\) multiply-adds.

1. Ideal lower bound with perfect reuse

If every input and output element crosses HBM exactly once, the ideal lower-bound traffic is \(3N^2b\):

\[\mathrm{AI}_{\mathrm{ideal}}=\frac{2N^3}{3N^2b}=\frac{2N}{3b}.\]

This value grows linearly with \(N\). Determining whether it lies above a particular GPU's Roofline balance point still requires peak compute and bandwidth for the same dtype and memory boundary.

2. No reuse in the naive triple loop

At the opposite extreme, every inner-loop iteration reloads one A and one B element while the C accumulator stays in a register until completion. Across the full GEMM, this gives:

  • FLOPs: \(2N^3\)
  • Read A: \(N^3\) elements, because each \(A[i,k]\) is reloaded across \(j\)
  • Read B: \(N^3\) elements, because each \(B[k,j]\) is reloaded across \(i\)
  • Write C: \(N^2\) elements after each dot product completes
\[\mathrm{AI}_{\mathrm{no\ reuse}} =\frac{2N^3}{(2N^3+N^2)b} \xrightarrow{N\to\infty}\frac{1}{b}.\]

The asymptote is independent of matrix size. It places the implementation in the bandwidth-limited region of a Roofline model, but it does not predict a measured percentage of GPU peak.

Pseudocode for the naive triple loop:

# Naive GEMM: C = A * B; all matrices are N by N
for i in 0..N:
    for j in 0..N:
        acc = 0
        for k in 0..N:
            acc += A[i, k] * B[k, j]      # 2 loads and 2 FLOPs
        C[i, j] = acc                     # C stays in a register

Under the stated model, the inner FMA obtains both operands from HBM on every iteration, which produces the \(1/b\) asymptote.

3. Blocking with a \(T\times T\) output tile

A \(T\times T\) output tile advances through \(N/T\) blocks along K. It performs \((N/T)2T^3=2NT^2\) FLOPs, reads \(NT\) elements from each input, and writes \(T^2\) output elements once:

\[\mathrm{AI}_{\mathrm{blocked}} =\frac{2NT^2}{(2NT+T^2)b} \xrightarrow{N\to\infty}\frac{T}{b}.\]

Pseudocode for square-tiled GEMM:

# Blocked GEMM; three T by T tiles fit in fast storage
for i0 in 0..N step T:
    for j0 in 0..N step T:
        C_tile = 0
        for k0 in 0..N step T:
            A_tile = A[i0:i0+T, k0:k0+T]
            B_tile = B[k0:k0+T, j0:j0+T]
            for i in 0..T:
                for j in 0..T:
                    for k in 0..T:
                        C_tile[i, j] += A_tile[i, k] * B_tile[k, j]
        C[i0:i0+T, j0:j0+T] = C_tile

Each loaded A or B element participates in \(T\) output updates inside the tile. This local reuse raises the asymptotic intensity from \(1/b\) to \(T/b\).

4. Cache-capacity bound

If three same-precision tiles must fit in a fast store of capacity \(M\) bytes, \(3T^2b\le M\), giving:

\[T_{\max}=\sqrt{\frac{M}{3b}},\qquad \mathrm{AI}_{\max}=\sqrt{\frac{M}{3b^3}}.\]

Within this capacity model, doubling the AI bound requires four times as much storage. The formula does not claim that a GPU exposes one cache in which all three tiles remain resident without conflict or eviction.

2. Rectangular output tiles

For \(C[M,N]=A[M,K]B[K,N]\), let the output tile be \(M_t\times N_t\), with A and B stages of \(M_t\times K_t\) and \(K_t\times N_t\).

1. Traffic for one output tile

Computing one output tile across the full reduction dimension gives:

TermElements
FLOPs\(2M_tN_tK\)
Read A\((K/K_t)M_tK_t=M_tK\)
Read B\((K/K_t)K_tN_t=KN_t\)
Write C\(M_tN_t\), once after the K loop
\[\mathrm{AI} =\frac{2M_tN_tK}{\big((M_t+N_t)K+M_tN_t\big)b}.\]

The \((M_t+N_t)K\) term accounts for the A and B stages loaded across K, whereas \(M_tN_t\) is the single output write. When \(K\gg M_tN_t/(M_t+N_t)\), the output term becomes asymptotically small:

\[\boxed{\mathrm{AI}\xrightarrow{K\to\infty} \frac{2M_tN_t}{(M_t+N_t)b} =\frac{H(M_t,N_t)}{b}},\qquad H(M_t,N_t)=\frac{2M_tN_t}{M_t+N_t}.\]

The tile-shape comparisons below use this asymptotic form. Split-K changes the model because multiple CTAs write and reduce partial results for one output tile, so its traffic must be evaluated with the complete expression.

2. The shorter tile edge limits reuse

The harmonic mean lies closer to its smaller input. In the tile, each A element can be reused across at most \(N_t\) output columns, while each B element can be reused across at most \(M_t\) output rows.

\(M_t\times N_t\)\(H(M_t,N_t)\)Interpretation
\(128\times128\)128square baseline
\(256\times64\)102the same element count, 80% of the square baseline
\(512\times32\)60the same element count, 47% of the square baseline
\(1024\times16\)31.5close to twice the shorter edge
\(M_t\to\infty\), fixed \(N_t\)\(2N_t\)the limit is twice the shorter edge
\(1\times N_t\)approaches 2the GEMV boundary
In this single-level model, GEMV, skinny GEMM, and a decode-time \(QK^\top\) product with one short dimension all have limited operand reuse and correspondingly low arithmetic intensity.

3. Cancellation of \(K_t\) in the single-level asymptote

  • \(K_t\) partitions the full K loop without changing the reuse count: A elements are still reused \(N_t\) times and B elements \(M_t\) times.
  • It still changes A/B stage capacity, loop count, synchronization frequency, and the generated instruction sequence.
  • Legal Tensor Core shapes, a final partial \(K_t\) stage when K is not evenly divisible, and multistage buffering further constrain the allowed values.
  • Once cross-tile cache reuse is admitted, intensity must be recomputed from traffic at each memory boundary rather than by inserting \(K_t\) into a universal cache formula.

4. Shape optimum under a cache budget

For a fixed \(K_t\) and a byte budget \(M\), maximizing \(H(M_t,N_t)\) under \(M_tN_t+K_t(M_t+N_t)\le M/b\) favors a square tile:

\[\arg\max_{M_t,N_t}H(M_t,N_t) \Longrightarrow M_t=N_t=T,\qquad T\le -K_t+\sqrt{K_t^2+M/b}.\]

Within this capacity constraint, bringing \(M_t\) and \(N_t\) closer together raises their harmonic mean. The square tile therefore supplies the upper-bound baseline for the single-level traffic model.

5. Degenerate row-strip and column-strip tiles

When either \(M_t\) or \(N_t\) becomes 1, \(H(1,N)\to2\) and \(H(M,1)\to2\). Each strip retains reuse for one operand while repeatedly loading the other.

For \(M_t=1\) and \(N_t=N\), a row strip loads row \(i\) of A once and reuses it across N output columns:

# Row strip: keep A[i, :] in fast storage while sweeping one row of C
for i in 0..M:
    for j in 0..N:
        acc = 0
        for k in 0..K:
            acc += A[i, k] * B[k, j]      # A from fast storage; B from HBM
        C[i, j] = acc

The full multiplication reads \(MK\) A elements and \(MNK\) B elements:

\[\mathrm{AI}_{\mathrm{row\ strip}} =\frac{2MNK}{(MK+MNK)b} \xrightarrow{N\to\infty}\frac{2}{b}.\]

For \(M_t=M\) and \(N_t=1\), the symmetric column strip keeps one column of B:

# Column strip: keep B[:, j] in fast storage while sweeping one column of C
for j in 0..N:
    for i in 0..M:
        acc = 0
        for k in 0..K:
            acc += A[i, k] * B[k, j]      # B from fast storage; A from HBM
        C[i, j] = acc

This form reads \(NK\) B elements and \(MNK\) A elements:

\[\mathrm{AI}_{\mathrm{column\ strip}} =\frac{2MNK}{(NK+MNK)b} \xrightarrow{M\to\infty}\frac{2}{b}.\]

When both \(M_t\) and \(N_t\) exceed 1, a tile can reuse both operands. The square special case then returns to the \(T/b\) asymptote derived in Section 1.

3. Hierarchical Roofline and cross-tile reuse

The single-level expression describes idealized traffic for one tile. Actual L2 reuse also depends on CTA execution order, concurrent kernels, cache indexing, and replacement. CUDA does not guarantee that adjacent output tiles run in an order that preserves a particular A or B panel in L2.

A hierarchical analysis therefore defines traffic separately at each boundary:

\[\mathrm{AI}_{\mathrm{HBM}}=\frac{2MNK}{Q_{\mathrm{HBM}}},\qquad \mathrm{AI}_{\mathrm{L2}}=\frac{2MNK}{Q_{\mathrm{L2}}},\qquad \mathrm{AI}_{\mathrm{SMEM}}=\frac{2MNK}{Q_{\mathrm{SMEM}}}.\]

Each \(Q_x\) may come from an explicit traffic model or from profiler counters, but those sources should not be blended into one “actual byte count.” With peak compute \(P\) and bandwidth bounds \(BW_x\), the hierarchical Roofline bound is:

\[P_{\mathrm{bound}}=\min\!\left( P,\ BW_{\mathrm{HBM}}\mathrm{AI}_{\mathrm{HBM}}, \ BW_{\mathrm{L2}}\mathrm{AI}_{\mathrm{L2}}, \ BW_{\mathrm{SMEM}}\mathrm{AI}_{\mathrm{SMEM}} \right).\]

4. Traffic Optima and Implementation Constraints

The harmonic mean supplies a traffic optimum for a fixed element budget, while a kernel must also satisfy MMA instruction shapes, register allocation, shared-memory layouts, boundary dimensions, and concurrency targets. 5. Arithmetic Intensity and GEMM Work Decomposition

Arithmetic intensity describes work per byte; it does not say how CTAs should divide that work. Libraries may choose among several decompositions when there are too few output tiles, an imbalanced tail, or a long reduction:

DecompositionWork assignmentAdditional cost
Data Parallelone CTA owns the full K range of one output tileinsufficient parallelism when output-tile count is small
Split-Kmultiple CTAs own different K ranges of one output tilepartial sums require atomics or a workspace reduction
Stream-Kwork is partitioned by compute iterations rather than complete output tilespartial sums at tile boundaries still require coordination
Persistent schedulerresident CTAs acquire multiple tiles over their lifetimescheduling state and synchronization
Raster or swizzlechanges output-tile order to improve panel localitycache-hit improvement is not guaranteed by CUDA

The Stream-K paper defines a work-centric decomposition, while the pinned CUTLASS revision exposes several schedulers. They address different parallelism and load-balancing conditions, so the selection should be evaluated for a fixed GPU, dtype, layout, epilogue, workspace, and problem set.

6. Intermediate traffic in back-to-back GEMMs

For \(P=AB\) followed by \(D=PC\), the intermediate matrix introduces a new traffic decision. Let \(A\in\mathbb{R}^{M\times K}\), \(B\in\mathbb{R}^{K\times N}\), and \(C\in\mathbb{R}^{N\times L}\). The two multiplications execute:

\[\mathrm{FLOPs}_{\mathrm{total}}=2MN(K+L).\]

Suppose the external matrices use \(b\) bytes per element and the intermediate uses \(b_p\). Keeping \(P\) on-chip gives:

\[\mathrm{AI}_{\mathrm{fused}} =\frac{2MN(K+L)}{(MK+KN+NL+ML)b}.\]

Materializing \(P\) adds one write and one read:

\[\mathrm{AI}_{\mathrm{materialized}} =\frac{2MN(K+L)} {(MK+KN+NL+ML)b+2MN b_p}.\]
\[\frac{\mathrm{AI}_{\mathrm{fused}}} {\mathrm{AI}_{\mathrm{materialized}}} =1+\frac{2MN b_p}{(MK+KN+NL+ML)b}.\]

The ratio is an ideal traffic-model result, not a speedup. Fusion also changes register and shared-memory use, occupancy, synchronization, epilogues, and scheduler choices.

The shared dimension determines how the intermediate is held

GEMM1's N dimension is GEMM2's reduction dimension. Implementations usually choose among three storage strategies:

StrategyData movementPrimary constraint
Full materializationwrite P to HBM and read it in the second kerneladds \(2MNb_p\) bytes, but leaves both GEMMs independently schedulable
Keep the full on-chip tileone CTA retains an \(M_t\times N\) intermediate tileregister and shared-memory capacity; storage precision is implementation-dependent
Tile along Nproduce and consume \(M_t\times N_t\) slices in sequencemay reload other operands and must preserve output state across slices

If the intermediate occupies \(b_p\) bytes per element and GEMM2 accumulates in \(b_{acc}\) bytes, the intermediate tile and output accumulators alone require:

\[M_tN_t b_p+M_tL_t b_{acc}\quad\text{bytes}.\]

A universal N limit cannot be inferred from the architecture's total register-file or shared-memory capacity because input stages, compiler allocation, occupancy targets, and per-block limits also consume those resources.

Attention uses the same traffic question, not the same algebra

Softmax prevents attention from being reduced algebraically to \((QK^\top)V\). The B2B model can still isolate the cost of materializing the score or probability matrix. Setting sequence length to \(S\), head dimension to \(d\), \(M=N=S\), \(K=L=d\), and temporarily \(b_p=b\) gives:

\[\frac{\mathrm{AI}_{\mathrm{fused}}} {\mathrm{AI}_{\mathrm{materialized}}} =1+\frac{S}{2d}.\]

This omits softmax traffic, online normalization, masks, numerical-stability work, and actual tile reloads. FlashAttention's end-to-end behavior must be evaluated with its full I/O model; the expression above is not an attention speedup formula.

7. The three GEMM shapes in Linear training

Let \(R=B\cdot S\) be the flattened token count, \(I=d_{in}\), and \(O=d_{out}\). With \(Y=XW^\top\) and bias omitted, forward and the two backward products are:

PhaseMatrix productGEMM \((M,N,K)\)Reduction
fwd\(X[R,I]W^\top[I,O]\to Y[R,O]\)\((R,O,I)\)\(I\)
dgrad\(dY[R,O]W[O,I]\to dX[R,I]\)\((R,I,O)\)\(O\)
wgrad\(dY^\top[O,R]X[R,I]\to dW[O,I]\)\((O,I,R)\)\(R\)

Each phase performs \(2RIO\) FLOPs. Under the same ideal assumptions about storage dtype and one HBM transfer per operand, each also touches \(RI+RO+IO\) elements. The phases exchange output and reduction dimensions, however, so a library may choose different tiles, layouts, split-K factors, epilogues, and workspaces.

The shape table alone does not imply a fixed fwd > dgrad > wgrad ranking, nor does it prove that one phase must use Stream-K, Split-K, or a particular accumulator type. cuBLASLt and CUTLASS algorithm selection also depends on GPU, dtype, layout, alignment, epilogue, workspace, and library revision. See PyTorch Linear and cuBLAS Matrix Representation for the row-major PyTorch to column-major BLAS mapping.

8. Conditions for Applying the Model

  • Under single-level blocking, a square tile approaches \(T/b\); a rectangular tile approaches \(H(M_t,N_t)/b\), with the shorter edge limiting reuse.
  • \(K_t\) cancels from the single-level asymptote but still affects stage capacity, legal instructions, synchronization, register use, and occupancy.
  • HBM, L2, and shared-memory intensities require traffic measured or modeled at their respective boundaries. Cache capacity alone does not establish cross-CTA hits.
  • Split-K, Stream-K, persistent scheduling, and raster order are work decompositions with no universal priority derived from AI alone.
  • Fusing back-to-back GEMMs can remove an intermediate HBM round trip, but the ideal AI ratio is not measured speedup.
