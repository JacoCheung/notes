PyTorch Linear 与 cuBLAS GEMM 的布局对应

torch.nn.Linear 在模型代码中接收 row-major Tensor，底层 GEMM 接口却可能按另一套布局约定描述同一块内存。分析 profiler 中的 TN、NT 或 NN 时，需要先把 PyTorch 的矩阵公式转换到 cuBLAS 的 column-major 视图。这个转换同时决定操作数顺序、transpose mode 和求和规约维度。

同一缓冲区的两种矩阵视图

为隔离布局问题，下面只讨论二维、实数、contiguous row-major Tensor，并省略 bias。记 \(X\in\mathbb{R}^{m\times k}\)、\(W\in\mathbb{R}^{n\times k}\)、\(Y\in\mathbb{R}^{m\times n}\)。对任意 row-major 矩阵 \(Z\)，用 \(\widehat{Z}\) 表示 cuBLAS 对同一缓冲区的 column-major 解释。若 \(Z\) 的 shape 是 \(a\times b\)，那么：

\[ \widehat{Z}=Z^{\mathsf T}\in\mathbb{R}^{b\times a}. \]

因此，row-major 公式 \(C=AB\) 对应的 column-major 输出是 \(\widehat{C}=C^{\mathsf T}=B^{\mathsf T}A^{\mathsf T}\)。这里的转置只改变矩阵视图，不复制或重排缓冲区。Linear 的三组公式都可以沿用这条等式推导。

Linear 前向与反向的 GEMM

表中的两个字母依次表示 cuBLAS 的 transa 与 transb。字母 N 保持 column-major 矩阵不变，T 对它转置。

目标 PyTorch row-major 公式 同一输出缓冲区的 cuBLAS column-major 公式 cuBLAS 操作数 transpose mode reduction axis
前向 \(Y=XW^{\mathsf T}\) \(\widehat{Y}=WX^{\mathsf T}=\operatorname{op}_{T}(\widehat{W})\operatorname{op}_{N}(\widehat{X})\) A=w, B=x TN \(k\), input dimension
weight gradient \(\mathrm{d}W=\mathrm{d}Y^{\mathsf T}X\) \(\widehat{\mathrm{d}W}=X^{\mathsf T}\mathrm{d}Y=\operatorname{op}_{N}(\widehat{X})\operatorname{op}_{T}(\widehat{\mathrm{d}Y})\) A=x, B=dy NT \(m\), flattened batch dimension
input gradient \(\mathrm{d}X=\mathrm{d}Y W\) \(\widehat{\mathrm{d}X}=W^{\mathsf T}\mathrm{d}Y^{\mathsf T}=\operatorname{op}_{N}(\widehat{W})\operatorname{op}_{N}(\widehat{\mathrm{d}Y})\) A=w, B=dy NN \(n\), output dimension

transpose mode 描述交换操作数之后，cuBLAS 如何解释 A 与 B。以 wgrad 为例，PyTorch 计算 \(\mathrm{d}W=\mathrm{d}Y^{\mathsf T}X\)，同一输出缓冲区的 column-major 视图则保存 \(\widehat{\mathrm{d}W}=X^{\mathsf T}\mathrm{d}Y\)。调用顺序由此变为 A=x、B=dy，mode 为 NT；乘积沿 flattened batch 维 \(m\) 求和。

GEMM 的规约维度是两个输入共有、但没有保留在输出 shape 中的维度。矩阵乘法沿这个维度执行乘加，因而可以直接比较输入与输出 shape 来确定 reduction axis。

Linear 沿用前文的 \(m\)、\(k\)、\(n\)。Attention 中，\(S_Q\) 与 \(S_K\) 分别表示 query 和 key/value 序列长度，\(d\) 是 query/key head dimension，\(d_v\) 是 value head dimension；batch、head 和 attention scale 等不改变下表规约轴的维度与因子均予以省略。

PyTorch Linear and cuBLAS GEMM Layout Mapping

torch.nn.Linear receives row-major tensors in model code, while the underlying GEMM interface may describe the same memory through a different layout convention. Interpreting profiler labels such as TN, NT, and NN therefore begins by translating the PyTorch equations into cuBLAS column-major views. That translation determines the operand order, transpose mode, and reduction dimension together.

Two matrix views of one buffer

To isolate the layout issue, assume two-dimensional, real-valued, contiguous row-major tensors and omit the bias. Let \(X\in\mathbb{R}^{m\times k}\), \(W\in\mathbb{R}^{n\times k}\), and \(Y\in\mathbb{R}^{m\times n}\). For a row-major matrix \(Z\), let \(\widehat{Z}\) denote the column-major matrix that cuBLAS sees in the same buffer. If \(Z\) has shape \(a\times b\), then:

\[ \widehat{Z}=Z^{\mathsf T}\in\mathbb{R}^{b\times a}. \]

A row-major product \(C=AB\) consequently becomes \(\widehat{C}=C^{\mathsf T}=B^{\mathsf T}A^{\mathsf T}\) in the column-major view. This transpose changes only the matrix interpretation; it does not copy or rearrange the buffer. The same identity derives all three Linear equations below.

GEMMs in Linear forward and backward

The two mode letters denote cuBLAS transa and transb, in that order. Letter N leaves a column-major matrix unchanged, while T transposes it.

Target PyTorch row-major equation cuBLAS column-major equation for the same output buffer cuBLAS operands Transpose mode Reduction axis
forward \(Y=XW^{\mathsf T}\) \(\widehat{Y}=WX^{\mathsf T}=\operatorname{op}_{T}(\widehat{W})\operatorname{op}_{N}(\widehat{X})\) A=w, B=x TN \(k\), input dimension
weight gradient \(\mathrm{d}W=\mathrm{d}Y^{\mathsf T}X\) \(\widehat{\mathrm{d}W}=X^{\mathsf T}\mathrm{d}Y=\operatorname{op}_{N}(\widehat{X})\operatorname{op}_{T}(\widehat{\mathrm{d}Y})\) A=x, B=dy NT \(m\), flattened batch dimension
input gradient \(\mathrm{d}X=\mathrm{d}Y W\) \(\widehat{\mathrm{d}X}=W^{\mathsf T}\mathrm{d}Y^{\mathsf T}=\operatorname{op}_{N}(\widehat{W})\operatorname{op}_{N}(\widehat{\mathrm{d}Y})\) A=w, B=dy NN \(n\), output dimension

The transpose mode describes how cuBLAS interprets A and B after the operands have been swapped. For wgrad, PyTorch computes \(\mathrm{d}W=\mathrm{d}Y^{\mathsf T}X\), while the column-major view of the same output buffer stores \(\widehat{\mathrm{d}W}=X^{\mathsf T}\mathrm{d}Y\). The call consequently uses A=x, B=dy, and mode NT, with reduction over the flattened batch dimension \(m\).

The GEMM reduction dimension is the dimension shared by both inputs but absent from the output shape.Multiplication and accumulation take place along this dimension, so comparing the operand shapes with the result identifies the reduction axis directly.

Linear retains the \(m\), \(k\), and \(n\) notation introduced above. For attention, \(S_Q\) and \(S_K\) denote the query and key/value sequence lengths, \(d\) is the query/key head dimension, and \(d_v\) is the value head dimension. Batch, head, and attention-scale terms are omitted because they do not change the reduction axes below.

Module Target GEMM and shapes Output shape Reduction axis
Linear forward \(X_{m\times k}W^{\mathsf T}_{k\times n}\) \(Y_{m\times n}\) \(k\), input_dim
Linear wgrad \(\mathrm{d}Y^{\mathsf T}_{n\times m}X_{m\times k}\) \(\mathrm{d}W_{n\times k}\) \(m\), flattened batch
Linear dgrad \(\mathrm{d}Y_{m\times n}W_{n\times k}\) \(\mathrm{d}X_{m\times k}\) \(n\), output_dim
Attention \(\mathrm{d}P\) \(\mathrm{d}O_{S_Q\times d_v}V^{\mathsf T}_{d_v\times S_K}\) \(\mathrm{d}P_{S_Q\times S_K}\) \(d_v\), value head dimension
Attention \(\mathrm{d}Q\) \(\mathrm{d}S_{S_Q\times S_K}K_{S_K\times d}\) \(\mathrm{d}Q_{S_Q\times d}\) \(S_K\), seq_K
Attention \(\mathrm{d}K\) \(\mathrm{d}S^{\mathsf T}_{S_K\times S_Q}Q_{S_Q\times d}\) \(\mathrm{d}K_{S_K\times d}\) \(S_Q\), seq_Q
Attention \(\mathrm{d}V\) \(P^{\mathsf T}_{S_K\times S_Q}\mathrm{d}O_{S_Q\times d_v}\) \(\mathrm{d}V_{S_K\times d_v}\) \(S_Q\), seq_Q

PyTorch gives Linear wgrad the output shape [output_dim, input_dim]. The cuBLAS column-major view of the same buffer is \(\widehat{\mathrm{d}W}\in\mathbb{R}^{k\times n}\), or [input_dim, output_dim]; the transposed view leaves the reduction dimension \(m\) unchanged.

This table is an algebraic mapping under explicit layout assumptions. It does not establish which GEMM backend or kernel a particular PyTorch run selects. ATen may choose cuBLASLt or another implementation according to dtype, shape, stride, and platform; non-contiguous inputs may also require a copy or different leading dimensions. cuBLASLt can describe row-major matrices directly, so its calls do not require this operand swap.
