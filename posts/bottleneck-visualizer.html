短板效应可视化

流水线的吞吐上限由处理能力最低的阶段决定。木桶模型把这一约束画成水位：提高长板，水位不变；补齐短板，瓶颈随之转移。调整下方的阶段能力，可以观察优化收益如何受到其他阶段的限制。

交互工具

每块木板代表一个阶段，数值是相对于同一个吞吐基准的处理能力。红色标出当前短板，水位表示模型中的整体吞吐上限。

Bottleneck Visualization

A pipeline’s throughput ceiling is set by its least capable stage. The barrel model turns that constraint into a water level: raising a taller stave leaves the level unchanged; raising the shortest one moves the bottleneck elsewhere. Adjusting stage capacities reveals where further improvements stop helping.

Interactive tool

Each stave is a stage whose capacity is expressed against one shared throughput reference. Red marks the current bottlenecks; the water level is the model’s overall throughput ceiling.

模型与指标

设各阶段处理能力为 c₁ … cₙ，它们已经按共同基准归一化。对能够重叠执行、每项工作依次经过各阶段的理想流水线，有：

吞吐上限 = min(c₁, …, cₙ)
相对最大阶段的差距 = 1 − min(cᵢ) / max(cᵢ)

默认配置中，Data Loading 为 42%，Checkpoint I/O 为 55%。只把 Data Loading 从 42% 提升至 70%，整体上限也只能升到 55%：新短板变成了 Checkpoint I/O。提高了 13 个百分点，相对原上限约提升 31%。

若两个阶段同为 42%，它们是共同瓶颈。只提高其中一个，水位仍停在 42%。面板中的“gap to max”只是最小值与最大值的相对差距，不是一次优化必然能追回的性能损失。

操作与实验

  • 拖动滑块，观察水位和瓶颈名称；多个短板会同时标红。
  • 使用 add stage 添加阶段，使用行末按钮删除阶段。clear all 清空模型，reset 恢复示例。
  • 使用 export 导出当前木桶图。预览中的图片为 SVG，可下载后插入文档。

适用边界

处理能力不等于利用率。GPU 利用率、CPU 利用率和带宽利用率的分母不同，不能直接取最小值来预测训练吞吐。阶段名称只是示例，不表示工具已经测量了对应资源。

这个模型忽略了启动与排空、共享资源竞争、同步开销和阶段之间的依赖变化。对于完全串行、无法重叠的阶段，每项工作的总耗时是各阶段耗时之和；此时应按耗时占比分析优化收益，不能直接套用木桶水位。

若要分析单个计算负载受到算力和带宽的共同约束，可使用本系列的 Roofline 性能模型可视化。

Model and metrics

Let c₁ … cₙ be stage capacities normalized to a shared throughput reference. For an ideal pipeline with overlapping stages and every item passing through every stage:

Throughput ceiling = min(c₁, …, cₙ)
Gap relative to the strongest stage = 1 − min(cᵢ) / max(cᵢ)

The example starts with Data Loading at 42% and Checkpoint I/O at 55%. Raising only Data Loading to 70% lifts the overall ceiling to 55%, where Checkpoint I/O becomes the bottleneck. That is a gain of 13 percentage points, or about 31% relative to the original ceiling.

If two stages share the minimum of 42%, improving just one leaves the ceiling unchanged. “Gap to max” compares the smallest and largest capacities; it is not a prediction of recoverable performance.

Controls and experiments

  • Move a slider to update the water level and bottleneck names. Tied bottlenecks are all highlighted.
  • Use add stage to add a stage and the row’s remove button to delete it. clear all empties the model; reset restores the example.
  • Use export to preview and download the current barrel diagram as SVG.

Model limits

Capacity is not utilization. GPU utilization, CPU utilization, and bandwidth utilization use different denominators. Their minimum does not predict training throughput. Stage names are illustrative; the tool does not measure these resources.

The model omits pipeline startup and draining, resource contention, synchronization overhead, and changing dependencies. For sequential stages that cannot overlap, per-item latency is the sum of stage times; optimization must account for those time fractions instead.

For a workload constrained by both compute throughput and memory bandwidth, see Roofline Performance Visualization in this series.
