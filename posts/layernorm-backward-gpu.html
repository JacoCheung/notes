LayerNorm 反向传播：数学推导、CUDA 规约与 Triton 融合实现

Transformer block 通常把每个 token 的 hidden features 作为一组执行 LayerNorm。反向传播需要同时生成输入梯度 dX，以及共享 affine 参数的 dγ 和 dβ。前者在单个 token 的 feature 维内规约，后两者则跨 token 规约；这两个互相垂直的方向决定了 GPU kernel 的组织方式。本文从闭式梯度出发，对照 PyTorch native CUDA 的分离实现与 generative-recommenders 的 Triton 融合实现，说明公式中的规约如何落到 block、临时缓冲区和 kernel launch 上。

0. 形状与记号

torch.nn.LayerNorm(normalized_shape) 对输入末尾若干维做归一化。PyTorch native 先把输入视为二维矩阵。若原始形状为 $[s_0,\ldots,s_{k-1},n_0,\ldots,n_{p-1}]$，且 normalized_shape 为 $[n_0,\ldots,n_{p-1}]$，则：

\[ R = \prod_{i=0}^{k-1}s_i, \qquad H = \prod_{i=0}^{p-1}n_i, \qquad X \in \mathbb{R}^{R\times H}. \]

在典型 LLM 中，输入形状是 $[B,S,H]$，LayerNorm 只归一化 hidden dimension，此时 $R=B\times S$。每个 token 对应矩阵中的一行。

统一记号PyTorch nativegenerative-recommenders Triton含义
$R$MN独立归一化的行数
$H$ND每行的归一化宽度
$X_{rj}$X[i * N + j]X[row, col]第 $r$ 行、第 $j$ 个 feature

PyTorch 的 _check_layer_norm_inputs() 建立了这组二维映射。后面的推导统一使用 $R,H$；进入两份实现时，表中的名称对应到各自源码。

1. 前向定义

对第 $r$ 行，LayerNorm 的前向为：

\[ \mu_r = \frac{1}{H}\sum_{j=0}^{H-1}X_{rj}, \]

\[ v_r = \frac{1}{H}\sum_{j=0}^{H-1}(X_{rj}-\mu_r)^2, \qquad q_r = \frac{1}{\sqrt{v_r+\epsilon}}, \]

\[ \widehat{X}_{rj}=(X_{rj}-\mu_r)q_r, \qquad Y_{rj}=\gamma_j\widehat{X}_{rj}+\beta_j. \]

$q_r$ 就是源码中的 rstd。PyTorch 使用总体方差，也就是除以 $H$，与 PyTorch 2.12 torch.nn.LayerNorm 文档里的 unbiased=False 一致。forward 会保存每一行的 mean 和 rstd，backward 直接读取，不再计算一次方差。CUDA wrapper 分配和返回这两个 Tensor 的位置见 layer_norm_cuda()。

2. 输入梯度推导

先固定一行并省略下标 $r$。记上游梯度为 $g_j=\partial L/\partial y_j$，经过 affine weight 后的梯度为：

\[ h_j = g_j\gamma_j. \]

再记 $z_j=x_j-\mu$、$q=(v+\epsilon)^{-1/2}$、$\widehat{x}_j=z_jq$。均值和逆标准差的微分分别为：

\[ \mathrm{d}\mu=\frac{1}{H}\sum_j \mathrm{d}x_j, \]

\[ \mathrm{d}v =\frac{2}{H}\sum_j z_j\,\mathrm{d}x_j, \qquad \mathrm{d}q =-\frac{q^3}{H}\sum_j z_j\,\mathrm{d}x_j. \]

这里用到了 $\sum_j z_j=0$。归一化结果的微分是：

\[ \mathrm{d}\widehat{x}_j =q(\mathrm{d}x_j-\mathrm{d}\mu)+z_j\,\mathrm{d}q. \]

把它代入 $\mathrm{d}L=\sum_j h_j\mathrm{d}\widehat{x}_j$，收集每个 $\mathrm{d}x_j$ 的系数：

\[ \boxed{ \frac{\partial L}{\partial x_j} =q\left[ h_j-\frac{1}{H}\sum_k h_k -\widehat{x}_j\frac{1}{H}\sum_k h_k\widehat{x}_k \right] } \]

GPU 代码通常不会显式写两个 mean，而是保存两个行规约结果：

\[ S_1=\sum_k h_k, \qquad S_2=\sum_k h_k\widehat{x}_k. \]

于是同一公式可以写成：

\[ \boxed{ \frac{\partial L}{\partial x_j} =\frac{q}{H}\left(Hh_j-S_1-\widehat{x}_jS_2\right) } \]

# X, dY: [R, H]；gamma: [H]
xhat = (X - mean[:, None]) * rstd[:, None]
h = dY * gamma[None, :]

s1 = h.sum(dim=1, keepdim=True)
s2 = (h * xhat).sum(dim=1, keepdim=True)
dX = (rstd[:, None] / H) * (H * h - s1 - xhat * s2)

eps 通过 forward 保存的 rstd 进入 backward 公式。反向计算需要该 rstd 与对应的 mean，二者共同恢复归一化时使用的行统计量。

3. 参数梯度与规约轴

记完整矩阵上的上游梯度为 $G_{rj}=\partial L/\partial Y_{rj}$。$\gamma$ 和 $\beta$ 在所有行之间共享，因此参数梯度沿 $R$ 规约：

\[ \boxed{ \frac{\partial L}{\partial \gamma_j} =\sum_{r=0}^{R-1}G_{rj}\widehat{X}_{rj} }, \qquad \boxed{ \frac{\partial L}{\partial \beta_j} =\sum_{r=0}^{R-1}G_{rj} }. \]

LayerNorm backward 的两个 reduction axis

dX 的每一行互不依赖，适合一个 CUDA block 负责一行。dγ 和 dβ 要跨行求和；当 $R$ 很大时，一个 block 顺序扫完所有行会缺少并行度，因此常见实现先产生 partial sum，再做第二级规约。

4. PyTorch native CUDA 实现

以下说明以 PyTorch main commit f772fda 为基准。layer_norm_backward_cuda() 根据 grad_input_mask 分配 dX、dgamma 和 dbeta，再进入 LayerNormBackwardKernelImpl()。如果某个梯度没有被请求，对应 Tensor 保持 undefined，kernel 路径也会跳过。

dX：一个 block 处理一行

CUDA 路径为 $R$ 行启动 $R$ 个 block。每个线程以步进方式读取该行的 $X$、dY 和 $\gamma$，先累加：

\[ \texttt{stats\_x1}=\sum_j G_{rj}\gamma_j=S_{1,r}, \]

\[ \texttt{stats\_x2} =\sum_jG_{rj}\gamma_j(X_{rj}-\mu_r)q_r =S_{2,r}. \]

随后 block reduction 把两个和广播给整块线程。源码中的 fH=N、term1=rstd/N，最终逐元素执行：

dx = (rstd / H) * (H * dy * gamma
                   - stats_x1
                   - xhat * stats_x2)

这正是上一节的闭式公式。对应代码集中在 layer_norm_grad_input_kernel_vectorized()。源码先遍历一遍数据求 $S_1,S_2$，规约完成后再遍历一遍写 dX，第二遍会重新执行 $X$、dY 和 $\gamma$ 的 load。它们实际命中哪一级缓存不能由源码单独确定，需要用目标 GPU 上的 profiler 观测。

当 $H$ 能被 4 整除、数据类型受支持且几个 buffer 满足对齐条件时，dispatcher 选择四元素向量化 load/store；否则回到标量版本。分支条件在 LayerNormBackwardKernelImplInternal() 中。

dγ 与 dβ：沿行维规约

参数梯度的访存方向不同。相邻线程负责相邻 feature，因此读取 $X$ 和 dY 时仍然保持 coalesced；每个线程或线程组沿 $R$ 累加自己的列。GammaBetaBackwardCUDAKernelTemplate 同时计算：

dgamma[j] += dY[r, j] * (X[r, j] - mean[r]) * rstd[r]
dbeta[j]  += dY[r, j]

普通 CUDA 路径根据 $R$ 选择不同的二维 thread block。$R<64$ 时，一个 y-thread 可以完成一列；$R$ 增大后，多个 y-thread 分担同一列，再经 shared memory 转置和 warp shuffle 得到最终结果。调度阈值见 LaunchGammaBetaBackwardCUDAKernel()。

还有一个专门处理 $R\gg H$ 且 $H$ 很小的分支。它沿行维启动多个 block，先写出形状为 $[\text{num partials},H]$ 的临时结果，再调用 sum(0) 完成第二级规约。多一次 kernel 和一次临时 buffer 读写，换来更多并行 block。源码把这个分支限制在 $R>64\mathrm{K}$ 且列方向不足以占满一半 SM 的情形。

常见 kernel 数量

请求的梯度普通 CUDA 路径$R\gg H$ 特殊路径

仅 dγ/dβ1 个列规约 kernelpartial kernel + final sum(0)
三者都需要通常 2 个 kerneldX kernel + 两阶段参数规约

这里按源码中的逻辑 launch 计数。编译器、CUDA Graph 或底层 reduction 实现可能让 profiler 中的活动名称有所不同，但不会改变两个 reduction axis。

5. Triton fused 实现

generative-recommenders 的实现先由 _weighted_layer_norm_fwd() 计算 forward：一个 Triton program 完成 mean、variance、normalization 和 affine。其 IS_SWISH 分支定义为 X * sigmoid(LayerNorm(X) * W + B)，因此融合边界还包含原始输入 $X$；它与通常写作 SiLU(Y) 的算子不同。对应的 learnable backward 入口是 _weighted_layer_norm_bwd_dx()。

在 _weighted_layer_norm_bwd_dx() 中，IS_SWISH=False 对应标准 LayerNorm 路径。一个 program 处理若干个 $[\texttt{BLOCK\_N},\texttt{BLOCK\_D}]$ tile，并复用同一批输入生成 dX 与参数梯度 partial sum：

xhat = (x - mean) * rstd
wdy = weight * dy

c1 = mean(xhat * wdy, axis=feature)
c2 = mean(wdy, axis=feature)
dx = (wdy - xhat * c1 - c2) * rstd

partial_dw += sum(dy * xhat, axis=row)
partial_db += sum(dy, axis=row)

dx 直接写回最终输出，参数梯度只写 partial sum。launcher 根据 SM 数和行数计算 tile_num，并分配两个 FP32 临时矩阵：

\[ \texttt{\_dweight},\texttt{\_dbias} \in\mathbb{R}^{\texttt{tile\_num}\times H}. \]

具体分配和 launch 在 _triton_weighted_layer_norm_bwd_impl()。第二个 kernel _layer_norm_bwd_dwdb() 沿 tile_num 规约 partial buffer，输出最终 dweight 与 dbias。

这里的 fused backward 由两个阶段组成。第一阶段融合 dX 与参数梯度 partial sum；第二阶段规约不同 program 写出的 partial buffer。多个 program 共享同一个 dweight[j] 输出位置，这份实现用 FP32 partial buffer 隔离写入，再以确定的第二级规约合并结果，避免在第一阶段使用 atomic add。

从固定 Triton 源码的 program 语义看，同一次 tile load 得到的 $X$、dY、mean 和 rstd 同时参与 dX 与参数梯度 partial sum；临时 partial buffer 随后还要写回并由第二个 kernel 读取。实际 DRAM 流量、寄存器占用和 spill 取决于 Triton 编译结果，不能仅由源码断言。该版本的 autotune 配置会按 GPU 世代选择候选 BLOCK_N 和 warp 数。

该实现要求每行能放进 fused feature block。compute_BLOCK_D() 把上限设为每行 64 KiB，并将 feature width 向上取到 2 的幂。超出上限会直接报错。

两种实现把成本放在不同位置。PyTorch native 拆开行规约与列规约，可以分别选择 launch shape；Triton 路径复用主数据读取，同时承担更复杂的 tile、FP32 partial buffer 和收尾规约。$R$ 较小时，第二阶段的固定成本可能占据较大比例；$H$ 较大时，融合 kernel 的寄存器需求也可能压低 occupancy。因此，路径选择需要结合实际的 $R,H$、dtype 和目标 GPU 测量。

7. 精度与正确性验证

LayerNorm backward 的误差主要来自 reduction 顺序。PyTorch native 用 acc_type<T, true> 选择累加类型；CUDA 上的 FP16 和 BF16 输入通常用 FP32 保存 mean、rstd 和规约中间值。Triton 实现也把 $X$、dY、weight 以及 partial dweight/dbias 转成 FP32，写最终输出时再转回目标 dtype。

验证自定义 kernel 时，最好把三个梯度分开检查：

# 参考路径使用 FP64，kernel 路径使用目标 dtype
x_ref = x.double().requires_grad_(True)
w_ref = weight.double().requires_grad_(True)
b_ref = bias.double().requires_grad_(True)

y_ref = torch.nn.functional.layer_norm(
    x_ref, (H,), w_ref, b_ref, eps
)
(y_ref * dy.double()).sum().backward()

# 分别比较 dx、dweight、dbias；不要只比较最终 loss
torch.testing.assert_close(dx, x_ref.grad.to(dx.dtype), rtol=..., atol=...)
torch.testing.assert_close(dw, w_ref.grad.to(dw.dtype), rtol=..., atol=...)
torch.testing.assert_close(db, b_ref.grad.to(db.dtype), rtol=..., atol=...)

测试矩阵应覆盖向量化、分块和调度边界，包括 $H$ 为 2 的幂与非 2 的幂、$H$ 无法被 4 整除、$H$ 接近 fused size 上限、较小的 $R$、$R\gg H$、非 contiguous 输入，以及只请求部分梯度的情况。输入分布还应包含常量行和大幅平移后的行，例如 $X+c$。常量行检查 $\epsilon$ 与零方差路径，平移测试则容易暴露 mean 处理或低精度消减中的问题。

还可以检查一个结构性质。对每一行，LayerNorm 的 shift invariance 给出：

\[ \sum_j \frac{\partial L}{\partial X_{rj}}\approx 0. \]

这个等式适合作为结构性快速检查；完整验证仍以 reference comparison 为准。由于浮点 reduction 顺序不同，PyTorch native、Triton 与 FP64 reference 应按误差容限比较，而不是要求逐 bit 相同。

LayerNorm Backpropagation: Derivation, CUDA Reductions, and Triton Fusion

Transformer blocks commonly apply LayerNorm to the hidden features of each token. Backpropagation must produce the input gradient dX together with dγ and dβ for the shared affine parameters. The first computation reduces within each token's feature dimension, while the other two reduce across tokens. These orthogonal axes determine how a GPU implementation organizes blocks, temporary storage, and kernel launches. Starting from the closed-form gradients, this article traces that structure through PyTorch native CUDA and the fused Triton implementation in generative-recommenders.

0. Shapes and notation

torch.nn.LayerNorm(normalized_shape) normalizes the trailing dimensions of its input. PyTorch native first views the input as a two-dimensional matrix. If the original shape is $[s_0,\ldots,s_{k-1},n_0,\ldots,n_{p-1}]$ and normalized_shape is $[n_0,\ldots,n_{p-1}]$, then:

\[ R = \prod_{i=0}^{k-1}s_i, \qquad H = \prod_{i=0}^{p-1}n_i, \qquad X \in \mathbb{R}^{R\times H}. \]

A typical LLM input has shape $[B,S,H]$, and LayerNorm normalizes only the hidden dimension. In that case, $R=B\times S$, and each token is one row of the matrix.

Common notationPyTorch nativegenerative-recommenders TritonMeaning
$R$MNNumber of independently normalized rows
$H$NDNormalized width of each row
$X_{rj}$X[i * N + j]X[row, col]Feature $j$ in row $r$

PyTorch's _check_layer_norm_inputs() establishes this two-dimensional mapping. The derivation uses $R,H$ throughout; the table maps those symbols to the names used by each implementation.

1. Forward definition

For row $r$, LayerNorm forward is:

\[ \mu_r = \frac{1}{H}\sum_{j=0}^{H-1}X_{rj}, \]

\[ v_r = \frac{1}{H}\sum_{j=0}^{H-1}(X_{rj}-\mu_r)^2, \qquad q_r = \frac{1}{\sqrt{v_r+\epsilon}}, \]

\[ \widehat{X}_{rj}=(X_{rj}-\mu_r)q_r, \qquad Y_{rj}=\gamma_j\widehat{X}_{rj}+\beta_j. \]

$q_r$ is named rstd in the source. PyTorch uses the population variance, dividing by $H$, which matches unbiased=False in the PyTorch 2.12 torch.nn.LayerNorm documentation. Forward saves one mean and rstd per row, and backward reads them instead of recomputing the variance. The CUDA wrapper allocates and returns these tensors in layer_norm_cuda().

2. Input-gradient derivation

Fix one row and omit the row index. Let the upstream gradient be $g_j=\partial L/\partial y_j$. After the affine weight:

\[ h_j = g_j\gamma_j. \]

Define $z_j=x_j-\mu$, $q=(v+\epsilon)^{-1/2}$, and $\widehat{x}_j=z_jq$. The differentials of the mean and reciprocal standard deviation are:

\[ \mathrm{d}\mu=\frac{1}{H}\sum_j \mathrm{d}x_j, \]

\[ \mathrm{d}v =\frac{2}{H}\sum_j z_j\,\mathrm{d}x_j, \qquad \mathrm{d}q =-\frac{q^3}{H}\sum_j z_j\,\mathrm{d}x_j. \]

This step uses $\sum_j z_j=0$. The differential of the normalized value is:

\[ \mathrm{d}\widehat{x}_j =q(\mathrm{d}x_j-\mathrm{d}\mu)+z_j\,\mathrm{d}q. \]

Substitute it into $\mathrm{d}L=\sum_j h_j\mathrm{d}\widehat{x}_j$ and collect the coefficient of each $\mathrm{d}x_j$:

\[ \boxed{ \frac{\partial L}{\partial x_j} =q\left[ h_j-\frac{1}{H}\sum_k h_k -\widehat{x}_j\frac{1}{H}\sum_k h_k\widehat{x}_k \right] } \]

GPU code normally stores two row-reduction results rather than writing the two means explicitly:

\[ S_1=\sum_k h_k, \qquad S_2=\sum_k h_k\widehat{x}_k. \]

The same expression then becomes:

\[ \boxed{ \frac{\partial L}{\partial x_j} =\frac{q}{H}\left(Hh_j-S_1-\widehat{x}_jS_2\right) } \]

# X, dY: [R, H]; gamma: [H]
xhat = (X - mean[:, None]) * rstd[:, None]
h = dY * gamma[None, :]

s1 = h.sum(dim=1, keepdim=True)
s2 = (h * xhat).sum(dim=1, keepdim=True)
dX = (rstd[:, None] / H) * (H * h - s1 - xhat * s2)

eps enters backward through the rstd saved by forward. Backward uses that value together with the corresponding mean to recover the row statistics used during normalization.

3. Parameter gradients and reduction axes

Let the upstream gradient over the full matrix be $G_{rj}=\partial L/\partial Y_{rj}$. Because $\gamma$ and $\beta$ are shared across rows, their gradients reduce over $R$:

\[ \boxed{ \frac{\partial L}{\partial \gamma_j} =\sum_{r=0}^{R-1}G_{rj}\widehat{X}_{rj} }, \qquad \boxed{ \frac{\partial L}{\partial \beta_j} =\sum_{r=0}^{R-1}G_{rj} }. \]

The two reduction axes in LayerNorm backward

Rows of dX are independent, so one CUDA block can handle one row. dγ and dβ must sum across rows. When $R$ is large, having one block scan every row serially does not expose enough parallelism, so implementations often produce partial sums before a second reduction stage.

4. PyTorch native CUDA implementation

This section uses PyTorch main commit f772fda as its source snapshot. layer_norm_backward_cuda() allocates dX, dgamma, and dbeta according to grad_input_mask, then enters LayerNormBackwardKernelImpl(). If a gradient was not requested, its tensor stays undefined and the corresponding kernel path is skipped.

dX: one block per row

The CUDA path launches $R$ blocks for $R$ rows. Threads step through the row and read $X$, dY, and $\gamma$, accumulating:

\[ \texttt{stats\_x1}=\sum_j G_{rj}\gamma_j=S_{1,r}, \]

\[ \texttt{stats\_x2} =\sum_jG_{rj}\gamma_j(X_{rj}-\mu_r)q_r =S_{2,r}. \]

A block reduction broadcasts both sums to the threads in the block. In the source, fH=N and term1=rstd/N; each element then evaluates:

dx = (rstd / H) * (H * dy * gamma
                   - stats_x1
                   - xhat * stats_x2)

This is the closed form derived above. The relevant code is in layer_norm_grad_input_kernel_vectorized(). It first traverses the data to compute $S_1,S_2$, then traverses it again after the reduction to write dX. The second pass issues another set of loads for $X$, dY, and $\gamma$. Source code alone cannot determine which cache level serves those loads; that requires profiling on the target GPU.

When $H$ is divisible by four, the data type is supported, and the relevant buffers satisfy alignment requirements, the dispatcher selects four-element vectorized loads and stores. Otherwise, it uses the scalar implementation. The conditions appear in LayerNormBackwardKernelImplInternal().

dγ and dβ: reduction across rows

Parameter gradients use the other memory direction. Neighboring threads own neighboring features, preserving coalesced reads of $X$ and dY, while each thread or thread group accumulates its column over $R$. GammaBetaBackwardCUDAKernelTemplate computes both:

dgamma[j] += dY[r, j] * (X[r, j] - mean[r]) * rstd[r]
dbeta[j]  += dY[r, j]

The ordinary CUDA path selects different two-dimensional thread blocks according to $R$. For $R<64$, one y-thread can finish a column. As $R$ grows, several y-threads share a column, then combine their results through a shared-memory transpose and warp shuffle. The dispatch thresholds are in LaunchGammaBetaBackwardCUDAKernel().

A separate branch handles $R\gg H$ with small $H$. It launches several blocks along the row dimension, writes a temporary result of shape $[\text{num partials},H]$, then calls sum(0) for the second reduction stage. The extra kernel and buffer traffic buy more parallel blocks. In this source snapshot, the branch requires $R>64\mathrm{K}$ and too few columns to occupy half the SMs.

Typical kernel counts

5. Triton fused implementation

The generative-recommenders implementation begins with _weighted_layer_norm_fwd(). One Triton program computes the mean, variance, normalization, and affine transform. Its IS_SWISH branch defines X * sigmoid(LayerNorm(X) * W + B), so the fusion boundary also includes the original input $X$; this operation differs from the usual SiLU(Y). The matching learnable backward entry is _weighted_layer_norm_bwd_dx().

In _weighted_layer_norm_bwd_dx(), IS_SWISH=False selects the standard LayerNorm path. One program processes several $[\texttt{BLOCK\_N},\texttt{BLOCK\_D}]$ tiles and reuses the loaded values for dX and parameter-gradient partial sums:

xhat = (x - mean) * rstd
wdy = weight * dy

c1 = mean(xhat * wdy, axis=feature)
c2 = mean(wdy, axis=feature)
dx = (wdy - xhat * c1 - c2) * rstd

partial_dw += sum(dy * xhat, axis=row)
partial_db += sum(dy, axis=row)

dx is written directly to its final output, while parameter gradients are written only as partial sums. The launcher derives tile_num from the SM count and row count, then allocates two FP32 temporary matrices:

\[ \texttt{\_dweight},\texttt{\_dbias} \in\mathbb{R}^{\texttt{tile\_num}\times H}. \]

The allocation and launch are in _triton_weighted_layer_norm_bwd_impl(). A second kernel, _layer_norm_bwd_dwdb(), reduces across tile_num to produce final dweight and dbias.

This fused backward has two stages. The first combines dX with parameter-gradient partial sums, and the second reduces the partial buffers produced by different programs. Because several programs contribute to the same dweight[j], the implementation isolates their writes in FP32 buffers and combines them with a deterministic second reduction instead of using atomic adds in the first stage.

At the level of the pinned Triton program, the values loaded for $X$, dY, mean, and rstd contribute to both dX and the parameter-gradient partial sums. The temporary partial buffers are then written and read by the second kernel. Actual DRAM traffic, register use, and spilling depend on the compiled Triton code and cannot be established from source alone. This version's autotuning configurations choose candidate BLOCK_N values and warp counts according to the GPU generation.

The implementation requires each row to fit in one fused feature block. compute_BLOCK_D() limits a row to 64 KiB and rounds the feature width up to a power of two. Wider rows raise an error.

Intermediate storageNo parameter partial buffer on the ordinary pathTwo FP32 buffers of shape $[\texttt{tile\_num},H]$

The two implementations place costs in different parts of the operation. PyTorch native separates row and column reductions, allowing each to use its own launch shape. The Triton path reuses the main-data loads while adding more involved tiling, FP32 partial buffers, and a final reduction. For small $R$, that second stage can occupy a large fraction of runtime; for large $H$, register demand in the fused kernel may reduce occupancy. Choosing between them therefore requires measurements at the actual $R,H$, dtype, and target GPU.

7. Precision and correctness validation

Reduction order is the main source of numerical differences in LayerNorm backward. PyTorch native uses acc_type<T, true> to choose the accumulator type. For FP16 and BF16 inputs on CUDA, mean, rstd, and reduction intermediates are normally FP32. The Triton implementation also converts $X$, dY, weight, and partial dweight/dbias values to FP32, then casts final outputs back to the target dtype.

Check the three gradients separately when validating a custom kernel:

# Run the reference in FP64 and the kernel in its target dtype.
x_ref = x.double().requires_grad_(True)
w_ref = weight.double().requires_grad_(True)
b_ref = bias.double().requires_grad_(True)

y_ref = torch.nn.functional.layer_norm(
    x_ref, (H,), w_ref, b_ref, eps
)
(y_ref * dy.double()).sum().backward()

# Compare dx, dweight, and dbias separately; final loss alone is insufficient.
torch.testing.assert_close(dx, x_ref.grad.to(dx.dtype), rtol=..., atol=...)
torch.testing.assert_close(dw, w_ref.grad.to(dw.dtype), rtol=..., atol=...)
torch.testing.assert_close(db, b_ref.grad.to(db.dtype), rtol=..., atol=...)

The test matrix should cross vectorization, tiling, and dispatch boundaries: powers of two and other values of $H$, widths not divisible by four, values near the fused size limit, small $R$, $R\gg H$, non-contiguous inputs, and requests for only a subset of the gradients. Include constant rows and rows shifted by a large constant, such as $X+c$. Constant rows exercise the $\epsilon$ and zero-variance path, while shift tests expose mistakes in mean handling or low-precision cancellation.

One structural property is useful for diagnosis. LayerNorm's shift invariance gives, for each row:

\[ \sum_j \frac{\partial L}{\partial X_{rj}}\approx 0. \]

This identity provides a structural quick check; complete validation still uses a reference comparison. Different floating-point reduction orders call for tolerance-based checks between PyTorch native, Triton, and the FP64 reference rather than bitwise equality.
