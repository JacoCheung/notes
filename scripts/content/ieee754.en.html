IEEE 754 floating-point numbers

Floating-point numbers represent both very small and very large values with a finite number of bits. The exponent sets the scale, while the fraction field determines the spacing within that scale, so range and precision are separate properties. With eight bits of binary precision, 258 is exactly representable, while 257 requires rounding.

1. Sign, exponent, and fraction fields

An IEEE 754 binary floating-point format consists of a sign bit \(s\), a biased exponent field \(E\), and a fraction field \(M\). Let the exponent have \(e\) bits and the fraction have \(m\) bits, with an exponent bias of \(b=2^{e-1}-1\). A normal number has the value:

\[x=(-1)^s\left(1+\frac{M}{2^m}\right)2^{E-b}.\]

The fraction field stores the \(m\) bits after the binary point. For normal numbers, the encoding supplies an implicit leading 1, giving a precision of \(p=m+1\) bits. In 32-bit single precision, \(e=8\), \(m=23\), and \(b=127\). [[ieee|Single-precision field layout]]

{{bit-example}}

The bit pattern for 1.5 is 0x3fc00000. Its sign bit is 0, its exponent field is 127, and its fraction field is 0x400000. Thus \(M/2^{23}=0.5\), and the decoded value is \(1.5\times2^0\).

Positive and negative zero both have zero exponent and fraction fields, with different sign bits; they compare equal numerically. NaNs use an all-ones exponent and a nonzero fraction, allowing multiple bit patterns.

2. Representable range and format comparison

2.1 Limits of normal numbers

The general range formulas in this section apply to encodings that reserve an all-ones exponent for special values. The smallest positive normal number has \(E=1\) and \(M=0\), so:

\[x_{\min,\mathrm{normal}}=2^{1-b}=2^{\,2-2^{e-1}}.\]

When the all-ones exponent is reserved, the largest finite exponent field is \(E_{\max}-1\). Setting every fraction bit to 1 gives a significand of \(2-2^{-m}\), hence:

\[x_{\max}=(2-2^{-m})2^{E_{\max}-1-b}=(2-2^{-m})2^b.\]

For example, 16-bit half precision has a 10-bit fraction field and a bias of 15. Its smallest positive normal number is \(2^{-14}\), and its largest finite value is \((2-2^{-10})2^{15}=65504\).

2.2 Subnormal numbers and gradual underflow

When \(E=0\), the encoding uses an implicit leading 0 and retains the exponent scale \(2^{1-b}\):

\[x_{\mathrm{subnormal}}=(-1)^s\frac{M}{2^m}2^{1-b}.\]

The smallest positive subnormal has \(M=1\) and a value of \(2^{1-b-m}\). The largest subnormal has \(M=2^m-1\); it is one interval of the same size below the smallest normal number:

\[2^{1-b}-(1-2^{-m})2^{1-b}=2^{1-b-m}.\]

The same spacing continues across the boundary between subnormal values and the lowest normal interval. In single precision, that spacing is \(2^{-149}\), and the smallest normal number is \(2^{-126}\). As subnormal values approach zero, they retain fewer significant binary digits. 4. Adjacent spacing and the integer precision boundary

Within a normal interval \([2^k,2^{k+1})\), adjacent values are spaced \(2^{k-m}\) apart. The spacing above 1 is therefore \(2^{-m}\), while the spacing above 0.5 is \(2^{-m-1}\). Each power-of-two boundary doubles the spacing as the exponent increases.

At \(2^{m+1}=2^p\), the spacing reaches 2. These formats have enough exponent range to include that point, so every integer from zero through \(2^p\) is exactly representable, and \(2^p+1\) is the first positive integer that is not.

\[n_{\mathrm{first\ missing}}=2^{m+1}+1.\]

bfloat16 has 7 fraction bits plus an implicit leading bit, giving 8 bits of precision. Both 256 and 258 are exactly representable, with 257 halfway between them. Round-to-nearest, ties-to-even maps 257 to 256 and 259 to 260. Adding one to the bfloat16 value 256 and rounding the result back to that format also gives 256.

5. NaN and infinity

NaN (Not a Number) represents cases with no valid numerical result. Under IEEE 754 default exception handling, 0.0 / 0.0 produces NaN, while a positive, nonzero finite number divided by positive zero produces positive infinity. The accompanying C++ program checks the following cases in the default floating-point environment. [[exceptions|IEEE arithmetic and special values]]

{{special-table}}

Ordinary arithmetic propagates NaN. Comparisons return Boolean values: NaN == NaN is false, NaN != NaN is true, and ordered comparisons involving NaN are false. C++ provides std::isnan to identify NaNs and std::isinf to identify infinities. Floating-point remainders use std::fmod; the integer % operator has separate semantics.
